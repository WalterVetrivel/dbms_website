SAVEPOINT and ROLLBACK TO

Undo part of a transaction and keep the rest.

SQL 
SQL> SAVEPOINT SP1;
Savepoint created.
SQL> DELETE FROM CUSTOMERS WHERE ID = 1;
1 row deleted.
SQL> SAVEPOINT SP2;
Savepoint created.
SQL> DELETE FROM CUSTOMERS WHERE ID = 2;
1 row deleted.
SQL> SAVEPOINT SP3;
Savepoint created.
SQL> DELETE FROM CUSTOMERS WHERE ID = 3;
1 row deleted.
SQL 
SQL> ROLLBACK TO SP2;
Rollback complete.
SQL> SELECT * FROM CUSTOMERS;

Locking read: SELECT ... FOR UPDATE

Lock a row while you check and change it.

SQL 
START TRANSACTION;
SELECT status FROM seats WHERE seat_no = '12A' FOR UPDATE;   -- locks the row
-- if status is 'free':
UPDATE seats SET status = 'booked', user_id = 42 WHERE seat_no = '12A';
COMMIT;                                                       -- releases the lock

From 3.12 SQL Facilities for Concurrency and Recovery: Locking reads: FOR UPDATE and FOR SHARE

GRANT and REVOKE

Give and take back privileges on a table.

SQL 
-- read-only access to one table
GRANT SELECT ON Employee_Info TO user1;

-- several privileges at once, and the right to pass them on
GRANT SELECT, INSERT, UPDATE ON college.marks TO 'hod'@'localhost' WITH GRANT OPTION;

-- privilege on chosen columns only
GRANT UPDATE (PhoneNumber, Address) ON Employee_Info TO 'clerk'@'localhost';

-- every privilege on every table of a database
GRANT ALL PRIVILEGES ON college.* TO 'admin'@'localhost';
SQL 
REVOKE SELECT ON Employee_Info FROM user1;
REVOKE GRANT OPTION ON college.marks FROM 'hod'@'localhost';   -- keeps the privileges, removes the right to pass them on
REVOKE ALL PRIVILEGES, GRANT OPTION FROM 'admin'@'localhost';

Lost update

T2 overwrites T1's write, so the withdrawal is lost.

Lost update: T1 withdraws ₹50, T2 deposits ₹100
T1T2A in database
read(A) → 10001000
read(A) → 10001000
A := A − 50
write(A)		950
A := A + 100
write(A)		1100

The correct final balance is 1000 − 50 + 100 = ₹1050. The database shows ₹1100, so T1's withdrawal is lost. This is also called a write-write conflict.
