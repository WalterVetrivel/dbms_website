Create views and indexes for database tables

Save a long query under a name with a view, so it can be used like a table. Then add indexes on the columns people search by, and use EXPLAIN to see MySQL use them.

Aim

Aim
  • To create a view to simplify data retrieval from the games store database.
  • To create indexes on frequently searched columns to improve query performance.

Read these topics first

You need the sample data from Exercise 4, or the starter script. The second view reuses the last query of Exercise 5.

Steps

  1. Create two views: developers with the games they made, and games with their sales. Test each with SELECT * FROM ViewName;.
  2. Create indexes on Games.Genre, Developers.DeveloperName and Publishers.PublisherName.
  3. List the indexes of each table with SHOW INDEXES.
  4. Run SELECT queries that use an indexed column in WHERE.
Syntax 
CREATE VIEW ViewName AS
SELECT ...;

CREATE INDEX IndexName ON TableName (Column);
SHOW INDEXES FROM TableName;

Create the views

MySQL 
CREATE VIEW DeveloperGames AS
SELECT DeveloperName, Title
FROM Developers INNER JOIN Games
ON Developers.DeveloperID = Games.DeveloperID;

CREATE VIEW GameSales AS
SELECT Title, Sales
FROM Games INNER JOIN
  (SELECT GameID, COUNT(*) AS Sales FROM PurchaseHistory GROUP BY GameID) AS GameSales
ON Games.GameID = GameSales.GameID;

Not every view can be updated

GameSales uses GROUP BY and COUNT, so a value like Sales cannot be changed through it. UPDATE GameSales SET Sales = 10; fails with “The target table GameSales of the UPDATE is not updatable”. A view on one table with plain columns (no GROUP BY, DISTINCT or aggregates) can be updated, and the change goes to the base table.

Create the indexes

An index is like the index at the back of a book. MySQL can jump straight to the rows with a given value instead of reading every row. MySQL's indexes are B+ trees (see B+ Tree Index Files).

MySQL 
CREATE INDEX Games_IDX_1 ON Games (Genre);
CREATE INDEX Developers_IDX_1 ON Developers (DeveloperName);
CREATE INDEX Publishers_IDX_1 ON Publishers (PublisherName);

MySQL manual: CREATE INDEX, SHOW INDEX

CREATE INDEX Games_IDX_1
The index's name, unique within the table.
ON Games (Genre)
The table and column to index. Users often browse by genre, so searches on Genre become faster.

Is the index used? EXPLAIN

Put EXPLAIN in front of a SELECT to see the plan MySQL will follow, without running the query.

MySQL 
EXPLAIN SELECT GameID, Title, Genre FROM Games WHERE Genre = 'RPG';
EXPLAIN SELECT GameID, Title FROM Games WHERE Title = 'God of War';

MySQL manual: EXPLAIN

Changes from the record

  • The record says text columns need a size in CREATE INDEX. That is true only for TEXT and BLOB columns, not VARCHAR. For example, CREATE INDEX Games_IDX_2 ON Games (Description(50)); indexes the first 50 characters of the description.
  • EXPLAIN is added to show that the index is really used.

Viva questions

What is a view? Does it store data?

A view is a virtual table defined by a stored SELECT query. It does not store rows; the query runs each time the view is used. See Views.

Give two uses of views.

They make long queries simple to reuse, and they improve security: a user can be given access to a view showing some columns, without access to the whole table.

What is an index? Why not index every column?

An index is a separate sorted structure (a B+ tree in MySQL) that finds rows by a column's value quickly. Every index takes space and must be updated on each INSERT, UPDATE and DELETE, so too many indexes slow down writes.

Which indexes does MySQL create on its own?

One for the primary key, one for each UNIQUE constraint and one for each foreign key column (if no suitable index exists).

What is the difference between a clustered and a non-clustered index?

In a clustered index the table's rows are stored in the index order. In MySQL's InnoDB the primary key is the clustered index. A secondary index such as Games_IDX_1 is non-clustered: it stores the key and the primary key, and MySQL then fetches the row. See Indexing and Hashing.

What does EXPLAIN show?

The plan MySQL will use for a query: the access type (for example ref or ALL), which index it uses and about how many rows it will read.
