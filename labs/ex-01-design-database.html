Aim

Aim

To create a database for an online game store with the required tables.

Read these topics first

You need MySQL 8.4 and a way to run SQL: the MySQL command line client or MySQL Workbench. The set-up steps are on the Labs page.

Steps

  1. Identify the tables and attributes. Users can buy games in the store, so we need:
    • a Users table: user ID, username, email, password, date of birth and location;
    • a Games table: game ID, title, release date, developer ID, publisher ID, genre, description, price and rating;
    • Developers and Publishers tables: ID, name and location;
    • a Cart table: the games each user has added to the cart. It needs only the user ID and the game ID.
  2. Write a CREATE TABLE command for each table. Choose a suitable MySQL data type for each attribute.
  3. Check each table with DESC. It lists the columns and their types.
Syntax 
CREATE TABLE TableName (
  Attribute1 datatype,
  Attribute2 datatype,
  ...
);

DESC TableName;

Create the database

The record starts with CREATE TABLE. On a fresh MySQL server there is no current database yet, so CREATE TABLE fails with “No database selected”. Make a database for the store first and switch to it.

MySQL 
CREATE DATABASE games_store;
USE games_store;

MySQL manual: CREATE DATABASE, USE

CREATE DATABASE games_store
Makes a new, empty database named games_store. A database is a container for tables.
USE games_store
Makes it the current database. Every table you create next goes inside it. Run USE again each time you open a new connection.
Starting again

To throw everything away and start over, run DROP DATABASE games_store; and then the two commands above. DROP DATABASE deletes every table in it, so use it only on practice data.

Create the tables

Each CREATE TABLE gives the table a name and lists its columns. Each column has a name and a data type, separated by a space. Columns are separated by commas, and there is no comma after the last one.

MySQL 
CREATE TABLE Users (
  UserID      int,
  Username    varchar(191),
  Email       varchar(191),
  Password    varchar(255),
  DateOfBirth date,
  Location    varchar(191)
);

CREATE TABLE Games (
  GameID      int,
  Title       varchar(191),
  ReleaseDate date,
  DeveloperID int,
  PublisherID int,
  Genre       varchar(191),
  Description text,
  BasePrice   decimal(10, 2),
  Rating      decimal(10, 2)
);

CREATE TABLE Publishers (
  PublisherID       int,
  PublisherName     varchar(191),
  PublisherLocation varchar(191)
);

CREATE TABLE Developers (
  DeveloperID       int,
  DeveloperName     varchar(191),
  DeveloperLocation varchar(191)
);

CREATE TABLE Cart (
  UserID int,
  GameID int
);

MySQL manual: CREATE TABLE

Clause by clause

CREATE TABLE Users ( ... );
Makes a new table named Users. The column list goes inside round brackets, and the statement ends with a semicolon.
UserID int
A whole number that identifies each user. Exercise 2 makes it the primary key.
Username varchar(191), Email varchar(191)
Text of up to 191 characters. VARCHAR stores only the characters you type, so short names do not waste space.
Password varchar(255)
Longer text. A real application stores a hash of the password, which can be long, never the password itself.
DateOfBirth date, ReleaseDate date
A calendar date written as 'YYYY-MM-DD', for example '2004-03-14'.
DeveloperID int, PublisherID int
The ID of the developer and publisher of the game. They will point to the Developers and Publishers tables. Exercise 3 turns them into foreign keys.
Description text
Long text with no fixed limit that you have to choose (up to 65,535 bytes).
BasePrice decimal(10, 2), Rating decimal(10, 2)
Exact numbers with up to 10 digits, 2 of them after the decimal point, for example 2999.00 or 9.50. Money must be exact, so use DECIMAL, not FLOAT.
Cart (UserID int, GameID int)
One row for each game in a user's cart. A user with three games in the cart has three rows. This table links users and games, which have a many-to-many relationship.

MySQL answers each CREATE TABLE with Query OK, 0 rows affected. The tables exist, but they are empty.

Lower case names on Windows

MySQL on Windows stores table names in lower case, so SHOW TABLES lists cart, developers and so on. You can still type Users or users. On Linux the names keep their case and must be typed exactly.

Why these data types?

The MySQL data types used in this exercise
TypeStoresUsed for
intWhole numbers from about −2.1 billion to 2.1 billionIDs
varchar(n)Text of up to n charactersNames, email, title, genre
textLong textGame description
dateA date, YYYY-MM-DDDate of birth, release date
decimal(p, s)An exact number with p digits, s of them after the pointPrice, rating
Why 191?

MySQL stores text in the utf8mb4 character set, which uses up to 4 bytes for each character. Older versions could index only 767 bytes of a column, and 191 × 4 = 764 fits. The record uses 191 so that Username and Email can have a UNIQUE index. MySQL 8.4 allows 3072 bytes, so varchar(255) also works today.

Viva questions

What is the difference between CHAR and VARCHAR?

CHAR(n) always uses n characters and pads short values with spaces. VARCHAR(n) stores only the characters given, up to n, plus a small length field. VARCHAR saves space for values of different lengths, such as names.

Why is DECIMAL used for the price instead of FLOAT?

DECIMAL stores exact values. FLOAT stores an approximate binary value, so 0.1 + 0.2 may not equal exactly 0.3. Money must be exact.

Is CREATE TABLE a DDL or a DML command?

DDL (Data Definition Language). It defines the structure of the database. DML commands such as INSERT and SELECT work on the rows. See DDL.

What does DESC show?

The structure of a table: each column's name, data type, whether it can be NULL, whether it is part of a key, its default value and extra details.

Why is there a separate Cart table instead of a cart column in Users?

A user can have many games in the cart, and a game can be in many carts. This many-to-many relationship needs its own table with one row for each user–game pair. A single column would have to hold a list, which breaks first normal form.

What is a schema?

The schema is the design of the database: its tables, columns, data types and constraints. It changes rarely. The rows stored at a moment are called the instance.
