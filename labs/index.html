Exercises 1 to 8 use MySQL. Each one builds on the tables and data of the one before, so do them in order. Exercise 9 is a C program and Exercise 10 uses MongoDB. Both stand alone.

    Every query was run

    All the SQL on these pages was run, and the outputs are copied from the real results. It was written to work on MySQL 8.4 LTS, the version used in the lab. The C programs were compiled and run, and the MongoDB commands were run in mongosh.

    Set up MySQL

    You need two programs: MySQL Community Server, which stores the data, and MySQL Workbench, a window where you type and run SQL. Both are free.

    1. Download MySQL Server. Go to dev.mysql.com/downloads/mysql and choose version 8.4 LTS. On Windows, download the MSI installer. You do not need an Oracle account: click “No thanks, just start my download”.
    2. Install it. Run the MSI and keep the default choices. At the end, it opens MySQL Configurator.
    3. Set the root password. The Configurator asks for a password for the root user. Pick one you will remember, because every exercise needs it.
    4. Run MySQL as a Windows service. Keep the default, so the server starts by itself when the computer starts. Then click Execute to finish.
    5. Install Workbench. Download it from dev.mysql.com/downloads/workbench and install it.
    6. Open Workbench and click the Local instance box. Type the root password. A query tab opens.
    7. Run SQL. Type or paste a statement and press Ctrl + Enter to run the statement under the cursor. Ctrl + Shift + Enter runs everything in the tab. The results appear in the grid below.

    The command line client

    You can also use the MySQL command line client instead of Workbench. Open it from the Start menu, or type this in a command prompt:

    Command prompt 
    mysql -u root -p

    -u root is the user name and -p makes it ask for the password. If Windows says that mysql is not recognized, add C:\Program Files\MySQL\MySQL Server 8.4\bin to your PATH, or use the MySQL 8.4 Command Line Client from the Start menu. Type exit to leave.

    Linux and macOS

    On Ubuntu, sudo apt install mysql-server installs the server. On macOS, use the DMG installer from the same download page. Workbench has builds for both.

    The game store database

    The store sells games to users. A developer makes each game and a publisher sells it. Users put games in a cart and then buy them. Each purchase is a transaction that can hold several games.

    E-R diagram

    Tables

    The two many-to-many relationships become their own tables: in cart becomes Cart, and includes becomes PurchaseHistory. Underlined columns form the primary key. FK marks a foreign key.

    Users

    • UserID
    • Username unique
    • Email unique
    • Password
    • DateOfBirth
    • Location

    Games

    • GameID
    • Title
    • ReleaseDate
    • DeveloperID FK to Developers
    • PublisherID FK to Publishers
    • Genre
    • Description
    • BasePrice check > 0
    • Rating

    Developers

    • DeveloperID
    • DeveloperName
    • DeveloperLocation

    Publishers

    • PublisherID
    • PublisherName
    • PublisherLocation

    Cart

    • UserID FK to Users
    • GameID FK to Games

    Transactions

    • TransactionID auto-increment
    • TransactionDate
    • UserID FK to Users

    PurchaseHistory

    • TransactionID FK to Transactions
    • GameID FK to Games
    • SalePrice

    Exercise 6 adds a CurrentPrice column to Games and an Offers table for price cuts. Exercise 7 adds views and indexes.

    Starter script

    Missed a lab, or broke your tables? The starter script builds the whole database as it is at the end of Exercise 3, with all the keys and foreign keys. It also loads the sample data from Exercise 4. Use it to start any of Exercises 4 to 8.

    Download games_store.sql

    1. In Workbench: choose File, then Open SQL Script, and pick the file. Press the lightning button to run it all.
    2. In the command line client: type SOURCE C:/Users/you/Downloads/games_store.sql with your own path. Use forward slashes, even on Windows.
    It starts from scratch

    The script deletes any games_store database first, so your own changes are lost. For Exercise 8, run the Exercise 6 set-up after the script, because Exercise 8 needs the CurrentPrice column.
