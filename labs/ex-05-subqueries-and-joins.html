Aim

Aim

To query the database using sub-queries and joins.

Read these topics first

You need the sample data from Exercise 4, or the starter script.

Steps

  1. Use sub-queries to get:
    • the titles of the games with the lowest and the highest rating;
    • the titles of the games published by Nintendo;
    • (hard) the title of the game with the most sales.
  2. Use joins to get:
    • each game title with its publisher's name (INNER JOIN);
    • all publishers with their games, even publishers with no games (LEFT JOIN);
    • the title and number of sales of each game that has sold at least once (join a table with a sub-query).
Syntax 
SELECT * FROM Table1 WHERE Column = (SELECT ... FROM Table2 WHERE Condition);

SELECT Col1, Col2 FROM Table1
INNER JOIN Table2 ON Table1.Key = Table2.Key;     -- or LEFT JOIN, RIGHT JOIN

Sub-query: lowest and highest rating

In Exercise 4, MIN and MAX gave the ratings but not the titles. A sub-query solves this in one statement.

MySQL 
SELECT Title, Rating FROM Games
WHERE Rating = (SELECT MIN(Rating) FROM Games);

SELECT Title, Rating FROM Games
WHERE Rating = (SELECT MAX(Rating) FROM Games);

Sub-query across two tables

The publisher's name is in Publishers, but Games stores only the PublisherID. The inner query turns the name into an ID.

MySQL 
SELECT Title FROM Games
WHERE PublisherID = (SELECT PublisherID FROM Publishers
                     WHERE PublisherName = 'Nintendo');

= needs exactly one value

If the inner query returns more than one row, = fails with “Subquery returns more than 1 row”. For example, three publishers are in the USA. When the inner query may return many rows, use IN:

MySQL 
SELECT Title FROM Games
WHERE PublisherID IN (SELECT PublisherID FROM Publishers
                      WHERE PublisherLocation = 'USA');

The best-selling game

This is the record's “hard” query. Build it from the inside out, one step at a time.

Step 1: sales of each game

Each row of PurchaseHistory is one copy sold, so counting the rows of each game gives its sales.

MySQL 
SELECT GameID, COUNT(*) AS Sales FROM PurchaseHistory
GROUP BY GameID;

Step 2: the highest sales figure

MySQL 
SELECT MAX(Sales) FROM
  (SELECT COUNT(*) AS Sales FROM PurchaseHistory GROUP BY GameID) AS SalesCount;

The step 1 query is used in FROM, like a table. This is called a derived table, and it must have a name (AS SalesCount).

Step 3: put it together

MySQL 
SELECT Title FROM Games WHERE GameID IN
  (SELECT GameID FROM PurchaseHistory
   GROUP BY GameID
   HAVING COUNT(*) =
     (SELECT MAX(Sales) FROM
       (SELECT COUNT(*) AS Sales FROM PurchaseHistory GROUP BY GameID) AS SalesCount));
The best-selling game

(SELECT MAX(Sales) FROM (...) AS SalesCount)
The innermost part: 4, the highest sales figure (step 2).
SELECT GameID FROM PurchaseHistory GROUP BY GameID HAVING COUNT(*) = 4
The middle part: the ID of every game that sold 4 copies (104).
SELECT Title FROM Games WHERE GameID IN (...)
The outer part: turns the ID into a title.

A shorter way, once you know ORDER BY and LIMIT: SELECT GameID, COUNT(*) AS Sales FROM PurchaseHistory GROUP BY GameID ORDER BY Sales DESC LIMIT 1;. It shows only one game even when two games tie, so the sub-query version is safer.

INNER JOIN

MySQL 
SELECT Title, PublisherName FROM Games
INNER JOIN Publishers ON Games.PublisherID = Publishers.PublisherID
ORDER BY Games.GameID;

MySQL manual: JOIN clause

FROM Games INNER JOIN Publishers
Combine rows of the two tables.
ON Games.PublisherID = Publishers.PublisherID
The join condition: pair each game with the publisher whose ID matches. It is almost always foreign key = primary key. The table name before the dot says which table's column you mean, because both tables have a PublisherID column.
INNER
Keep only rows that found a partner. A game with no publisher, or a publisher with no games, does not appear.
ORDER BY Games.GameID
Not in the record. Without it, the row order depends on how MySQL runs the join.

RIGHT JOIN does the reverse and keeps every row of the right table. Games RIGHT JOIN Publishers gives the same result as the query above. MySQL has no FULL OUTER JOIN; the Joins page shows how to get one with UNION.

To find only the publishers with no games, add WHERE Games.GameID IS NULL.

Joining a sub-query

Join Games with the step 1 query from above, to show titles next to sales.

MySQL 
SELECT Title, Sales FROM Games
INNER JOIN (SELECT GameID, COUNT(*) AS Sales FROM PurchaseHistory
            GROUP BY GameID) AS GameSales
ON Games.GameID = GameSales.GameID
ORDER BY Games.GameID;

A derived table with two columns, GameID and Sales, named GameSales.

Matches each game with its sales row. Games that never sold have no row in GameSales, so INNER JOIN leaves them out. Use LEFT JOIN to list them with NULL sales.

Changes from the record

  • The hard query uses WHERE GameID IN instead of =. With =, the query fails with “Subquery returns more than 1 row” whenever two games tie for the most sales.
  • The join queries have ORDER BY, so your output appears in the same order as the tables here.

Viva questions

What is a sub-query?

A query written inside another query, in brackets. The inner query's result is used by the outer query, for example in WHERE or FROM. See Sub Queries.

What is the difference between INNER JOIN and LEFT JOIN?

INNER JOIN keeps only rows with a match in both tables. LEFT JOIN keeps every row of the left table and fills NULL where the right table has no match. See Joins.

What is a correlated sub-query?

A sub-query that uses a column of the outer query, so it runs once for each outer row. Example: SELECT Title FROM Games g WHERE NOT EXISTS (SELECT * FROM PurchaseHistory p WHERE p.GameID = g.GameID); lists games that never sold.

When should you use IN instead of = with a sub-query?

When the inner query can return more than one row. = needs exactly one value.

What is a derived table?

A sub-query in the FROM clause. It acts like a temporary table for that one statement and must have an alias.

What is a Cartesian product, and when does it happen?

Every row of one table paired with every row of the other. It happens when a join has no join condition. 12 games × 7 publishers would give 84 rows.
