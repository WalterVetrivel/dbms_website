Aim

Aim

To perform basic CRUD operations on a simple document (NoSQL) database using MongoDB.

Read these topics first

This exercise does not use MySQL or the games_store database. It builds a small, separate games collection in MongoDB.

Words you will meet
  • A document is one record, written as field: value pairs inside braces. It is like a row.
  • A collection is a group of documents. It is like a table, but it has no fixed columns.
  • CRUD stands for Create, Read, Update and Delete.
  • mongosh is the MongoDB Shell, where you type commands.

Steps

  1. Set up MongoDB. Install MongoDB Community Server and mongosh, or use a free cloud cluster on MongoDB Atlas.
  2. Connect to the server with mongosh.
  3. Create a database with use. MongoDB creates it when you first store data in it.
  4. Create a collection with db.createCollection().
  5. Create: insert documents with insertOne().
  6. Read: fetch documents with find() and findOne().
  7. Update: change a field with updateOne() and $set.
  8. Delete: remove a document with deleteOne().

Install and connect

  1. Install the server. Download MongoDB Community Server from mongodb.com/try/download/community. On Windows, the installer can run it as a service, so it starts by itself.
  2. Install mongosh. The shell is a separate download: mongodb.com/try/download/shell. (MongoDB Compass, the free GUI, also has mongosh built in at the bottom of its window.)
  3. Connect. Open a command prompt and type mongosh. With no address, it connects to the server on your own computer, at mongodb://localhost:27017.
Command prompt 
mongosh
mongosh "mongodb://localhost:27017"
mongosh "mongodb+srv://cluster0.example.mongodb.net/" --username student

The first two lines do the same thing. The third connects to a cloud cluster on Atlas. Atlas shows your own cluster address on its Connect page, and mongosh asks for the password.

mongo or mongosh?

The record types mongo. That was the old shell, and MongoDB 6.0 removed it. Current versions only have mongosh. The commands in this exercise are the same in both.

Database and collection

mongosh 
use gamestore
db.createCollection('games')
SQL equivalent 
CREATE DATABASE gamestore;
USE gamestore;
CREATE TABLE games (...);
Output 
switched to db gamestore
{ ok: 1 }

MongoDB manual: Databases and collections, db.createCollection()

use gamestore
Switches to the database named gamestore. If it does not exist, MongoDB creates it as soon as you store something in it. There is no CREATE DATABASE command.
db
In mongosh, db always means the current database.
db.createCollection('games')
Creates an empty collection named games. { ok: 1 } means it worked. Unlike CREATE TABLE, it names no columns, because each document can have its own fields.

This step is optional. If you insert into a collection that does not exist, MongoDB creates it for you.

Create: insertOne

Insert two games. Each one is a document with five fields.

mongosh 
db.games.insertOne({
  gameID: 101,
  title: 'Control',
  developer: 'Remedy Entertainment',
  genre: 'Action Adventure',
  price: 80
})

db.games.insertOne({
  gameID: 102,
  title: 'Alan Wake 2',
  developer: 'Remedy Entertainment',
  genre: 'Survival Horror',
  price: 80
})
SQL equivalent 
CREATE TABLE games (
  gameID INT PRIMARY KEY,
  title VARCHAR(100),
  developer VARCHAR(100),
  genre VARCHAR(50),
  price INT
);

INSERT INTO games
VALUES (101, 'Control', 'Remedy Entertainment',
        'Action Adventure', 80);

INSERT INTO games
VALUES (102, 'Alan Wake 2', 'Remedy Entertainment',
        'Survival Horror', 80);
Output (once for each insert) 
{
  acknowledged: true,
  insertedId: ObjectId('6ac87604a3af7dae7a3069b3')
}

MongoDB manual: db.collection.insertOne(), Documents

db.games
The games collection in the current database.
insertOne({ ... })
Adds one document. The document is written in braces, as field: value pairs separated by commas. Text goes in quotes. Numbers do not.
acknowledged: true
The server received and saved the insert.
insertedId: ObjectId('...')
Every document needs a unique _id field, like a primary key. We did not give one, so MongoDB made an ObjectId for us. Your ID will be different, because it is built from the time and a random value.

Notice that gameID is just a normal field. MongoDB does not stop you from inserting a second document with gameID 101. To make it unique, you would add a unique index: db.games.createIndex({ gameID: 1 }, { unique: true }).

MongoDB manual: db.collection.find(), db.collection.findOne()

find()
Returns every document in the collection. With a filter, such as find({ genre: 'Survival Horror' }), it returns only the matching ones. mongosh shows the first 20 and asks you to type it for more.
findOne({ gameID: 102 })
The braces hold the filter, like a WHERE clause. { gameID: 102 } means gameID = 102. findOne returns the first match as one document, not a list. If nothing matches, it returns null.

Update: updateOne

Control goes on sale. Change its price to 40 and check it.

mongosh 
db.games.updateOne(
  { gameID: 101 },
  { $set: { price: 40 } }
)

db.games.findOne({ gameID: 101 })
SQL equivalent 
UPDATE games SET price = 40 WHERE gameID = 101;

SELECT * FROM games WHERE gameID = 101;
Output 
{
  acknowledged: true,
  insertedId: null,
  matchedCount: 1,
  modifiedCount: 1,
  upsertedCount: 0
}
{
  _id: ObjectId('6ac87604a3af7dae7a3069b3'),
  gameID: 101,
  title: 'Control',
  developer: 'Remedy Entertainment',
  genre: 'Action Adventure',
  price: 40
}

MongoDB manual: db.collection.updateOne(), $set

{ gameID: 101 }
The first argument is the filter: which document to change. It works like WHERE.
{ $set: { price: 40 } }
The second argument says what to change. $set sets the price field to 40 and leaves every other field as it was. It works like SET in SQL. If the field does not exist yet, $set adds it.
matchedCount: 1, modifiedCount: 1
One document matched the filter, and one was changed. If the price was already 40, modifiedCount would be 0.
updateOne
Changes only the first matching document, even if more match. Use updateMany to change them all.

Delete: deleteOne

Remove Alan Wake 2, then list the collection again.

mongosh 
db.games.deleteOne({ gameID: 102 })

db.games.find()
SQL equivalent 
DELETE FROM games WHERE gameID = 102 LIMIT 1;

SELECT * FROM games;
Output 
{ acknowledged: true, deletedCount: 1 }
[
  {
    _id: ObjectId('6ac87604a3af7dae7a3069b3'),
    gameID: 101,
    title: 'Control',
    developer: 'Remedy Entertainment',
    genre: 'Action Adventure',
    price: 40
  }
]

MongoDB manual: db.collection.deleteOne()

deleteOne({ gameID: 102 })
Deletes the first document that matches the filter. deletedCount: 1 confirms one was removed. If nothing matched, deletedCount is 0 and there is no error.
find()
Only Control is left, with its new price of 40.
Careful with an empty filter

db.games.deleteMany({}) deletes every document, just like DELETE FROM games; with no WHERE. Always check the filter first with find().

More to try

These go beyond the record, but they show what makes a document database different. Run them after the steps above.

Insert many, with different fields

mongosh 
db.games.insertMany([
  { gameID: 103, title: 'Resident Evil 4',
    developer: 'Capcom', genre: 'Survival Horror',
    price: 2999, platforms: ['PC', 'PS5'] },
  { gameID: 104, title: 'God of War',
    developer: 'Santa Monica Studio',
    genre: 'Action Adventure', price: 3299 }
])
SQL equivalent 
INSERT INTO games VALUES
  (103, 'Resident Evil 4', 'Capcom',
   'Survival Horror', 2999),
  (104, 'God of War', 'Santa Monica Studio',
   'Action Adventure', 3299);
Output 
{
  acknowledged: true,
  insertedIds: {
    '0': ObjectId('6ac87604a3af7dae7a3069b5'),
    '1': ObjectId('6ac87604a3af7dae7a3069b6')
  }
}

Resident Evil 4 has a platforms field that holds a list. The other games do not have it. A collection allows this. In SQL, every row has the same columns, so the list would need a column for each game or a second table.

Filter, choose fields and sort

mongosh 
db.games.find(
  { price: { $gt: 100 } },
  { _id: 0, title: 1, price: 1 }
)

db.games.find({}, { _id: 0, title: 1, price: 1 })
        .sort({ price: -1 })
SQL equivalent 
SELECT title, price FROM games
WHERE price > 100;

SELECT title, price FROM games
ORDER BY price DESC;
Output 
[
  { title: 'Resident Evil 4', price: 2999 },
  { title: 'God of War', price: 3299 }
]
[
  { title: 'God of War', price: 3299 },
  { title: 'Resident Evil 4', price: 2999 },
  { title: 'Control', price: 40 }
]
{ price: { $gt: 100 } }
A filter with a query operator. $gt means greater than. Others are $lt, $gte, $lte, $ne and $in.
{ _id: 0, title: 1, price: 1 }
The second argument is the projection: which fields to show. 1 means show and 0 means hide. It works like the column list after SELECT. _id is shown unless you hide it.
.sort({ price: -1 })
Sorts by price. 1 means ascending and -1 means descending, like ORDER BY price DESC.

Count and update many

mongosh 
db.games.countDocuments({ genre: 'Action Adventure' })

db.games.updateMany(
  { developer: 'Remedy Entertainment' },
  { $inc: { price: 10 } }
)
SQL equivalent 
SELECT COUNT(*) FROM games
WHERE genre = 'Action Adventure';

UPDATE games SET price = price + 10
WHERE developer = 'Remedy Entertainment';
Output 
2
{
  acknowledged: true,
  insertedId: null,
  matchedCount: 1,
  modifiedCount: 1,
  upsertedCount: 0
}

$inc adds to a number, so Control's price goes from 40 to 50. The SQL column needs price = price + 10 to do the same.

Changes from the record

  • mongosh instead of mongo. The old mongo shell is not part of current MongoDB versions.
  • Straight quotes. Some of the record's steps use curly quotes, as in db.createCollection(“CollectionName”). mongosh rejects these with a SyntaxError. Type ' or " yourself instead of copying from a word processor.
  • No semicolon after use. The record's step 3 writes use DatabaseName;. It works, but use is a shell command, not JavaScript, so the semicolon is not needed.
  • The last output. The record shows [] (an empty list) after deleting game 102. In fact Control (game 101) is still there, as the output above shows. You would only get [] after deleting both games.

Viva questions

What is NoSQL? Name its four main types.

NoSQL means “not only SQL”: databases that do not store data in fixed tables. The four main types are document stores (MongoDB), key-value stores (Redis), column-based systems (Cassandra) and graph databases (Neo4j). See NoSQL Databases: Introduction.

What is a document and a collection?

A document is one record made of field-value pairs, stored in a JSON-like format called BSON. A collection is a group of documents, like a table. See Document Based Systems.

What is the _id field?

Every document's unique identifier, like a primary key. If you do not give one, MongoDB creates an ObjectId automatically.

What does “schema-less” or “flexible schema” mean?

Documents in one collection do not need the same fields. In this exercise, only Resident Evil 4 has a platforms field. A table in SQL forces every row to have the same columns.

What is the difference between find and findOne?

find returns all matching documents (as a cursor that mongosh prints as a list). findOne returns only the first match as a single document, or null if nothing matches.

What does $set do? What happens without it?

$set changes only the fields you name and keeps the rest. updateOne refuses an update without an operator such as $set. (replaceOne is the method that replaces a whole document.)

When would you choose MongoDB over MySQL?

When records have varied or changing fields, when data is naturally nested (a game with its list of platforms), or when the data must be spread over many servers. MySQL is the better choice when you need joins, strict constraints and multi-table transactions, as in the store's purchases.
