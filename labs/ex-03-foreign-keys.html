Aim

Aim

To add foreign keys and enforce referential integrity in the database.

Read these topics first

Finish Exercise 2 first. A foreign key can only point to a column that is a primary key (or UNIQUE), so the keys from Exercise 2 must be in place.

Steps

  1. Identify the foreign keys. A foreign key column may only hold values that exist in the column it refers to. For example, a game may only name a developer that is in the Developers table.
  2. Decide what happens on delete. When a referenced row is deleted, either delete the rows that refer to it (CASCADE) or set their foreign key to NULL (SET NULL).
  3. Add the foreign keys with ALTER TABLE.
  4. Test them. Insert a value with no match (it should fail). Then insert correct values, delete the referenced row and see what happens.
Syntax 
ALTER TABLE TableName ADD CONSTRAINT ConstraintName
  FOREIGN KEY (Column) REFERENCES ParentTable (Column)
  ON DELETE CASCADE;          -- or ON DELETE SET NULL

Plan the foreign keys

The table that holds the foreign key is the child. The table it points to is the parent.

Be careful with CASCADE

One DELETE on a parent can silently remove many child rows. Use it only when the child rows really have no meaning without the parent.

Add the foreign keys

MySQL 
ALTER TABLE Games ADD CONSTRAINT Games_FK_1 FOREIGN KEY (DeveloperID)
  REFERENCES Developers (DeveloperID) ON DELETE SET NULL;
ALTER TABLE Games ADD CONSTRAINT Games_FK_2 FOREIGN KEY (PublisherID)
  REFERENCES Publishers (PublisherID) ON DELETE SET NULL;
ALTER TABLE Cart ADD CONSTRAINT Cart_FK_1 FOREIGN KEY (UserID)
  REFERENCES Users (UserID) ON DELETE CASCADE;
ALTER TABLE Cart ADD CONSTRAINT Cart_FK_2 FOREIGN KEY (GameID)
  REFERENCES Games (GameID) ON DELETE CASCADE;
ALTER TABLE Transactions ADD CONSTRAINT Transactions_FK FOREIGN KEY (UserID)
  REFERENCES Users (UserID) ON DELETE SET NULL;
ALTER TABLE PurchaseHistory ADD CONSTRAINT Purchase_FK_1 FOREIGN KEY (TransactionID)
  REFERENCES Transactions (TransactionID) ON DELETE CASCADE;
ALTER TABLE PurchaseHistory ADD CONSTRAINT Purchase_FK_2 FOREIGN KEY (GameID)
  REFERENCES Games (GameID) ON DELETE CASCADE;

Clause by clause

ALTER TABLE Games ADD CONSTRAINT Games_FK_1
Adds a rule named Games_FK_1 to the child table, Games. The name appears in error messages, and you need it to remove the rule later with ALTER TABLE Games DROP FOREIGN KEY Games_FK_1;.
FOREIGN KEY (DeveloperID)
The column in Games that must match a parent row.
REFERENCES Developers (DeveloperID)
The parent table and column. The parent column must be a primary key or UNIQUE, and both columns must have the same data type (here both are int).
ON DELETE SET NULL
When a developer is deleted, MySQL sets DeveloperID to NULL in that developer's games. The child column must allow NULL for this to work.
ON DELETE CASCADE
When the parent row is deleted, MySQL deletes the child rows too.

With no ON DELETE clause, the rule is RESTRICT: MySQL refuses to delete a parent row that still has children. You can also add ON UPDATE CASCADE so that changing a parent's ID updates the children.

To see the keys, run SHOW CREATE TABLE Games;. Its output ends with these lines:

Part of the SHOW CREATE TABLE Games output 
  CONSTRAINT `Games_FK_1` FOREIGN KEY (`DeveloperID`) REFERENCES `developers` (`DeveloperID`) ON DELETE SET NULL,
  CONSTRAINT `Games_FK_2` FOREIGN KEY (`PublisherID`) REFERENCES `publishers` (`PublisherID`) ON DELETE SET NULL,
  CONSTRAINT `Games_CHK` CHECK ((`BasePrice` > 0))

Test: a value with no match

Developer 501 was deleted in Exercise 2, so this INSERT names a developer that does not exist.

MySQL: this gives an error 
INSERT INTO Games VALUES (102, 'Pokemon Black', '2010-09-18', 501, 700, 'RPG',
  'Best game in the Pokemon franchise', 50, 10);
Output 
ERROR 1452 (23000): Cannot add or update a child row: a foreign key constraint fails
(`games_store`.`games`, CONSTRAINT `Games_FK_1` FOREIGN KEY (`DeveloperID`)
REFERENCES `developers` (`DeveloperID`) ON DELETE SET NULL)

This is referential integrity at work: a child row cannot point to a parent that is not there. Now add the developer first, and the same INSERT succeeds.

MySQL 
INSERT INTO Developers VALUES (501, 'Game Freak', 'Japan');
INSERT INTO Games VALUES (102, 'Pokemon Black', '2010-09-18', 501, 700, 'RPG',
  'Best game in the Pokemon franchise', 50, 10);

Deleting the user also deleted the cart row, because Cart_FK_1 uses ON DELETE CASCADE.

Changes from the record

  • The developer is named “Game Freak” (two words, its real name) and Pokemon Black has its real release date, 2010-09-18.
  • The CASCADE test is added, because the record's step 4 asks for the ON DELETE rules to be tested but shows only SET NULL.

Common errors

ErrorCauseFix
ERROR 1452 (23000): Cannot add or update a child row: a foreign key constraint failsThe value has no match in the parent. When it appears on ALTER TABLE, a row already in the child table has no match.Insert the parent row first, or correct or delete the bad child rows, then try again.

Viva questions

What is referential integrity?

The rule that every foreign key value must either match a primary key value in the parent table or be NULL. A child row can never point to a row that does not exist. See Constraints.

What is the difference between ON DELETE CASCADE and ON DELETE SET NULL?

CASCADE deletes the child rows along with the parent. SET NULL keeps the child rows but sets their foreign key to NULL.

What happens on delete if no ON DELETE rule is given?

MySQL uses RESTRICT (also called NO ACTION): it refuses to delete a parent row that still has child rows and gives error 1451.

Can a foreign key column hold NULL? Can it repeat?

Yes to both, unless the column is also NOT NULL or part of a primary key. Many games can have the same publisher, and Pokemon Black now has a NULL developer.

Why might a real shop not use CASCADE from Games to PurchaseHistory?

Deleting a game would erase its sales records, which a business needs for accounts and taxes. A real shop would mark the game as “not for sale” instead of deleting it, or use RESTRICT.

Which table is the parent and which is the child in Games_FK_1?

Developers is the parent (it is referenced). Games is the child (it holds the foreign key).
