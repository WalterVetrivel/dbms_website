Aim

Aim
  • To create additional tables with constraints for the online game store database.
  • To add constraints to the existing tables.
  • To use DML commands to insert, update and delete rows in the created tables.

Read these topics first

Finish Exercise 1 first. Start each session with USE games_store;.

Steps

  1. Create two new tables with primary keys. A Transactions table with a unique ID for each purchase, its date and the ID of the user who made it. A PurchaseHistory table with the transaction ID, game ID and the price paid. In PurchaseHistory the pair (transaction ID, game ID) must be unique, because one transaction can hold many games and one game can be sold in many transactions.
  2. Add primary keys to the tables from Exercise 1 with ALTER TABLE.
  3. Add other constraints. Username and Email must be UNIQUE and NOT NULL. Password must be NOT NULL. The price of a game must be greater than 0 (CHECK).
  4. Insert rows into Users, Games, Developers and Publishers. Check them with SELECT.
  5. Update rows: change a user's location and a game's price.
  6. Delete a row from Developers, using its ID. Check with SELECT.

Tables with a primary key

MySQL 
CREATE TABLE Transactions (
  TransactionID   int PRIMARY KEY AUTO_INCREMENT,
  TransactionDate date,
  UserID          int
);

CREATE TABLE PurchaseHistory (
  TransactionID int,
  GameID        int,
  SalePrice     decimal(10, 2),
  PRIMARY KEY (TransactionID, GameID)
);

MySQL manual: CREATE TABLE

TransactionID int PRIMARY KEY
A column-level primary key. Each transaction ID must be unique and cannot be NULL.
AUTO_INCREMENT
MySQL fills in the next number (1, 2, 3 ...) when an INSERT leaves the column out. Exercise 8 uses this to number each checkout.
PRIMARY KEY (TransactionID, GameID)
A table-level, composite primary key. Neither column is unique alone, but each pair is. A composite key must be written after the columns, like this.

Add primary keys with ALTER TABLE

The tables from Exercise 1 have no keys yet. ALTER TABLE changes a table that already exists.

MySQL 
ALTER TABLE Users ADD CONSTRAINT Users_PK PRIMARY KEY (UserID);
ALTER TABLE Games ADD CONSTRAINT Games_PK PRIMARY KEY (GameID);
ALTER TABLE Developers ADD CONSTRAINT Devs_PK PRIMARY KEY (DeveloperID);
ALTER TABLE Publishers ADD CONSTRAINT Pubs_PK PRIMARY KEY (PublisherID);
ALTER TABLE Cart ADD CONSTRAINT Cart_PK PRIMARY KEY (UserID, GameID);

MySQL manual: ALTER TABLE

ALTER TABLE Users
Changes the Users table. Its rows stay as they are.
ADD CONSTRAINT Users_PK
Adds a rule and gives it a name. A name makes error messages clear and lets you drop the rule later. MySQL always calls a primary key PRIMARY, so it ignores the name you give it here.
PRIMARY KEY (UserID)
UserID must be unique and not NULL. MySQL also builds an index on it, so finding a user by ID is fast.
PRIMARY KEY (UserID, GameID)
The same game can be in many carts and a cart can hold many games, but the same user–game pair cannot appear twice.
Add keys before adding data

If a table already has duplicate IDs or NULLs, ADD PRIMARY KEY fails. Remove the bad rows first, or add keys while the tables are still empty, as we do here.

UNIQUE, NOT NULL and CHECK

MySQL 
ALTER TABLE Users ADD CONSTRAINT Users_UNQ_1 UNIQUE (Username);
ALTER TABLE Users ADD CONSTRAINT Users_UNQ_2 UNIQUE (Email);
ALTER TABLE Users MODIFY COLUMN Username varchar(191) NOT NULL;
ALTER TABLE Users MODIFY COLUMN Email varchar(191) NOT NULL;
ALTER TABLE Users MODIFY COLUMN Password varchar(255) NOT NULL;
ALTER TABLE Games ADD CONSTRAINT Games_CHK CHECK (BasePrice > 0);

MySQL manual: ALTER TABLE, CHECK constraints

UNIQUE (Username)
No two users may have the same username. Unlike a primary key, a UNIQUE column may hold NULL, and a table can have many UNIQUE columns.
MODIFY COLUMN Username varchar(191) NOT NULL
Redefines the column with the NOT NULL rule. MODIFY needs the full column definition, so the data type must be written again. If you leave it out, the statement fails.
CHECK (BasePrice > 0)
Every row must have a price greater than 0. MySQL tests the rows already in the table now, and every new or changed row later. CHECK is enforced from MySQL 8.0.16 onwards; older versions read it and ignored it.

Insert rows

MySQL 
INSERT INTO Users VALUES (1, 'test', 'test@test.com', '123456', '2000-01-01', 'India');
INSERT INTO Developers VALUES (500, 'Nintendo', 'Japan');
INSERT INTO Publishers VALUES (700, 'Nintendo', 'Japan');
INSERT INTO Games VALUES (101, 'Super Mario Bros', '1985-09-13', 500, 700, 'Platformer',
  'Play as Mario and rescue Princess Peach from Bowser', 50, 10);

MySQL manual: INSERT, SELECT

INSERT INTO Users VALUES (...)
Adds one row. With no column list, you must give a value for every column, in the order the columns were created (the order DESC shows).
'test', '2000-01-01'
Text and dates go inside straight single quotes. Numbers such as 1, 500 and 50 do not need quotes.
50, 10
The base price and rating. MySQL stores them as 50.00 and 10.00 because the columns are decimal(10, 2).

To fill only some columns, name them. The others get NULL (or their default value):

Syntax with a column list 
INSERT INTO Developers (DeveloperID, DeveloperName) VALUES (510, 'Valve');

Update rows

MySQL 
UPDATE Users SET Location = 'Australia' WHERE Username = 'test';
UPDATE Games SET BasePrice = 40 WHERE GameID = 101;

MySQL manual: UPDATE

UPDATE Users
The table to change.
SET Location = 'Australia'
The new value. To change several columns, separate them with commas: SET Location = 'Australia', Email = 'new@test.com'.
WHERE Username = 'test'
Only rows that match are changed. MySQL replies Rows matched: 1 Changed: 1. Without WHERE, every row in the table is changed.

Delete rows

Add an extra developer, then delete it by its ID.

MySQL 
INSERT INTO Developers VALUES (501, 'Test', 'USA');
SELECT * FROM Developers;
Developers before the DELETE
DeveloperIDDeveloperNameDeveloperLocation
500NintendoJapan
501TestUSA
MySQL 
DELETE FROM Developers WHERE DeveloperID = 501;
SELECT * FROM Developers;

MySQL manual: DELETE

DELETE FROM Developers
Removes whole rows from the table. The table itself stays.
WHERE DeveloperID = 501
Only the row with ID 501 is removed. Using the primary key in WHERE is the safest way to pick exactly one row.
Developers after the DELETE
DeveloperIDDeveloperNameDeveloperLocation
500NintendoJapan
Never forget WHERE

DELETE FROM Developers; with no WHERE removes every row. MySQL Workbench blocks UPDATE and DELETE without a key in WHERE (its “safe updates” setting) to protect you from this.

Test the constraints

A constraint is only useful if it stops bad data. Try these statements. Each one should fail, and the table stays unchanged.

MySQL: each of these gives an error 
INSERT INTO Users VALUES (1, 'arjun', 'arjun@example.com', 'pass', '2004-03-14', 'India');

ERROR 1062 (23000): Duplicate entry '1' for key 'users.PRIMARY': user ID 1 already exists.

MySQL 
INSERT INTO Users VALUES (2, 'test', 'other@example.com', 'pass', '2004-03-14', 'India');

ERROR 1062 (23000): Duplicate entry 'test' for key 'users.Users_UNQ_1': the username is taken.

MySQL 
INSERT INTO Users (UserID, Username, Password) VALUES (3, 'meera', 'pass');

ERROR 1364 (HY000): Field 'Email' doesn't have a default value: Email is NOT NULL and was left out.

MySQL 
UPDATE Games SET BasePrice = 0 WHERE GameID = 101;

ERROR 3819 (HY000): Check constraint 'Games_CHK' is violated.: the price must be greater than 0.

Changes from the record

  • The record's step 3.2 asks for a check on Price, but the column is named BasePrice. The solution uses BasePrice.
  • The release date of Super Mario Bros is changed from 1980-01-01 to its real date, 1985-09-13.
  • The record writes UNIQUE(UserName). Column names in MySQL are not case-sensitive, so it works, but this page uses the exact name Username.

Viva questions

What is the difference between a primary key and a unique key?

Both stop duplicate values. A primary key cannot be NULL and a table has only one. A UNIQUE column can hold NULL and a table can have many. See Keys.

What is a composite key? Give an example from this exercise.

A key made of two or more columns. PurchaseHistory uses (TransactionID, GameID) and Cart uses (UserID, GameID).

Which commands in this exercise are DDL and which are DML?

DDL: CREATE TABLE and ALTER TABLE, because they change the structure. DML: INSERT, UPDATE, DELETE and SELECT, because they work on the rows.

What happens if you run DELETE without a WHERE clause?

Every row in the table is deleted. The empty table stays.

What is the difference between DELETE, TRUNCATE and DROP?

DELETE (DML) removes chosen rows and can be rolled back inside a transaction. TRUNCATE (DDL) removes all rows quickly and keeps the table. DROP (DDL) removes the table itself.

What does AUTO_INCREMENT do?

It gives a new row the next number in sequence when the column is left out of the INSERT. It is used for ID columns.

Why must MODIFY COLUMN repeat the data type?

MODIFY replaces the whole column definition. The type is part of that definition, so it must be given again along with NOT NULL.
