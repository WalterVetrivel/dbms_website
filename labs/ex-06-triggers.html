Write SQL triggers for insert, update and delete operations

A trigger is SQL that MySQL runs by itself when a row is inserted, updated or deleted. Here, three triggers keep each game's current price in step with the discount offers on it.

Aim

Aim

To write triggers to update or log information in the database when a row is inserted, before a row is deleted and when a row is updated.

Read these topics first

You need the Games table with data from Exercise 4, or the starter script.

Steps

  1. Initial set-up. Add a CurrentPrice column to Games and copy the base price into it. Create an Offers table with the GameID as the primary key and the percentage off.
  2. Create three triggers:
    • when an offer is inserted, set the game's current price using the percentage off;
    • when an offer is updated, change the current price to match;
    • when an offer is deleted, set the current price back to the base price.
  3. Test the triggers with INSERT, UPDATE and DELETE on Offers, and SELECT on Games to see the effect.
Syntax 
DELIMITER $$
CREATE TRIGGER TriggerName
AFTER INSERT ON TableName          -- BEFORE or AFTER; INSERT, UPDATE or DELETE
FOR EACH ROW
BEGIN
  Statement1;
  Statement2;
END;
$$
DELIMITER ;

Initial set-up

MySQL 
ALTER TABLE Games ADD COLUMN CurrentPrice decimal(10, 2) AFTER BasePrice;
UPDATE Games SET CurrentPrice = BasePrice;

CREATE TABLE Offers (
  GameID        int PRIMARY KEY,
  PercentageOff int NOT NULL,
  FOREIGN KEY (GameID) REFERENCES Games (GameID),
  CHECK (PercentageOff > 0)
);

MySQL manual: ALTER TABLE, UPDATE, CREATE TABLE

ADD COLUMN CurrentPrice decimal(10, 2) AFTER BasePrice
Adds the price a customer pays today. AFTER places it next to BasePrice in DESC and SELECT *. Existing rows get NULL in the new column.
UPDATE Games SET CurrentPrice = BasePrice
No WHERE, on purpose: every game starts with no discount.
GameID int PRIMARY KEY
A game can have at most one offer at a time.
FOREIGN KEY (GameID) REFERENCES Games (GameID)
An offer must be for a real game.
CHECK (PercentageOff > 0)
A 0% or negative discount makes no sense, so it is refused.

Why DELIMITER?

A trigger body holds statements that end with ;. But the MySQL client sends your text to the server as soon as it sees a ;, which would cut the trigger in half. DELIMITER $$ tells the client to wait for $$ instead. After the triggers, DELIMITER ; switches back.

  • DELIMITER is a command of the client (the command line or Workbench), not an SQL statement the server runs.
  • Do not run any other query between DELIMITER $$ and DELIMITER ;, unless you end it with $$.
  • Any rare symbol works, for example //.

MySQL manual: Defining stored programs (DELIMITER)

Create the triggers

MySQL 
DELIMITER $$

CREATE TRIGGER TRG_Add_Offer
AFTER INSERT ON Offers
FOR EACH ROW
BEGIN
  UPDATE Games
  SET CurrentPrice = BasePrice - (BasePrice * NEW.PercentageOff / 100)
  WHERE GameID = NEW.GameID;
END;
$$

CREATE TRIGGER TRG_Update_Offer
AFTER UPDATE ON Offers
FOR EACH ROW
BEGIN
  UPDATE Games
  SET CurrentPrice = BasePrice - (BasePrice * NEW.PercentageOff / 100)
  WHERE GameID = NEW.GameID;
END;
$$

CREATE TRIGGER TRG_Delete_Offer
AFTER DELETE ON Offers
FOR EACH ROW
BEGIN
  UPDATE Games SET CurrentPrice = BasePrice WHERE GameID = OLD.GameID;
END;
$$

DELIMITER ;

MySQL manual: CREATE TRIGGER, Trigger syntax and examples

Clause by clause

CREATE TRIGGER TRG_Add_Offer
The trigger's name. It must be unique in the database.
AFTER INSERT ON Offers
The event and timing: run after a row has been inserted into Offers. AFTER is right here, because the offer row should exist before the price changes. A BEFORE trigger runs first and is used to check or change the new row itself.
FOR EACH ROW
Run once for every row affected. An INSERT of three offers fires the trigger three times.
BEGIN ... END;
The body. It can hold several statements, each ending with ;.
NEW.PercentageOff, NEW.GameID
NEW is the row being inserted, or the row's new values in an UPDATE.
BasePrice - (BasePrice * NEW.PercentageOff / 100)
The discounted price. For 10% off Rs. 40: 40 − (40 × 10 / 100) = 36.
OLD.GameID
OLD is the row as it was before an UPDATE or DELETE. A DELETE trigger has only OLD, because there is no new row. An INSERT trigger has only NEW.

Changes from the record

  • The record's step 1 says AFTER Price and SET CurrentPrice = Price, but the column is BasePrice. The record's queries (and this page) use BasePrice.
  • The record names the column PercentOff in the steps and PercentageOff in the queries. This page uses PercentageOff throughout.
  • The record's aim says “before a row is deleted”, but its delete trigger is AFTER DELETE. AFTER is correct here: the price should reset only once the offer is really gone.

Viva questions

What is a trigger?

A named block of SQL stored in the database that runs automatically when an INSERT, UPDATE or DELETE happens on a given table. See Triggers.

What is the difference between a BEFORE and an AFTER trigger?

A BEFORE trigger runs before the row is written. It can check or change the NEW values, for example to round a price. An AFTER trigger runs once the row is written, and is used to update other tables or write a log.

What are NEW and OLD?

NEW holds the row's values after the change (INSERT and UPDATE). OLD holds the values before the change (UPDATE and DELETE).

What does FOR EACH ROW mean?

The trigger body runs once for every row the statement changes. MySQL supports only row-level triggers.

If the base price of a game changes while it has an offer, is CurrentPrice still right?

No. These triggers are on Offers only. A BEFORE UPDATE trigger on Games could recalculate CurrentPrice from the offer whenever BasePrice changes. New games also start with NULL CurrentPrice, which a BEFORE INSERT trigger on Games could fix.

Why is DELIMITER needed?

The body contains semicolons. DELIMITER changes the end-of-statement marker in the client, so the whole CREATE TRIGGER reaches the server as one statement.
