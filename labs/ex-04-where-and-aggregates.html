Read these topics first

You need the tables and keys from Exercises 1 to 3. If you missed them, run the starter script instead. It builds the database and loads all the data on this page.

Steps

  1. Use WHERE clauses to get:
    • the username and location of all users from Australia;
    • a list of action games;
    • games that cost more than Rs. 500;
    • games with “Resident Evil” in the title (use LIKE);
    • the title, rating and price of adventure games with a rating of at least 7 (use AND).
  2. Use aggregate functions and GROUP BY to find:
    • the total number of games;
    • the number of games in each genre;
    • the lowest and highest rating;
    • the average price of action games.
Syntax 
SELECT Columns FROM TableName WHERE Condition;
SELECT COUNT(*) FROM TableName WHERE Condition;
SELECT MIN(Column), MAX(Column), AVG(Column) FROM TableName;
SELECT Column, COUNT(*) FROM TableName GROUP BY Column;

WHERE clauses

WHERE keeps only the rows for which the condition is true. MySQL reads a SELECT in this order: FROM (which table), then WHERE (which rows), then SELECT (which columns).

MySQL manual: SELECT, Comparison operators, LIKE

1. Users from Australia

MySQL 
SELECT Username, Location FROM Users WHERE Location = 'Australia';
Users from Australia

Show only these two columns.
WHERE Location = 'Australia'
Keep rows whose location equals the text 'Australia'. Text comparison in MySQL ignores case by default, so 'australia' also matches.

2. Action games

MySQL 
SELECT Title, Genre FROM Games WHERE Genre LIKE '%Action%';
Games whose genre contains Action

A pattern match. % stands for any number of characters (even none), so the pattern matches any genre that contains “Action”. This finds “Action Adventure” games as well.

With WHERE Genre = 'Action' you get only Devil May Cry 5, because = needs an exact match.

Aggregate functions

An aggregate function takes many rows and returns one value.

MySQL manual: Aggregate functions

Total number of games

MySQL 
SELECT COUNT(*) AS 'No. of Games' FROM Games;
Number of games
No. of Games
12
COUNT(*)
Counts rows. COUNT(DeveloperID) would count only rows where DeveloperID is not NULL, which gives 11.
AS 'No. of Games'
An alias: the heading for the result column. Quotes are needed because the name has spaces and a dot.

Lowest and highest rating

MySQL 
SELECT MIN(Rating) AS Lowest, MAX(Rating) AS Highest FROM Games;
Lowest and highest rating
LowestHighest

One SELECT can hold several aggregates. This gives the ratings but not the game titles. Exercise 5 finds the titles with a sub-query.

Average price of action games

MySQL 
SELECT AVG(BasePrice) AS AveragePrice FROM Games WHERE Genre LIKE '%Action%';
SELECT ROUND(AVG(BasePrice), 2) AS AveragePrice FROM Games WHERE Genre LIKE '%Action%';

AveragePrice
1932.333333
The same average, rounded to 2 decimal places
AveragePrice
1932.33
WHERE Genre LIKE '%Action%'
WHERE runs before the aggregate, so AVG sees only the three action games: (999 + 3299 + 1499) ÷ 3.
ROUND(value, 2)
Rounds to 2 decimal places, which suits a price.

SUM(Column) adds the values. For example, SELECT SUM(SalePrice) FROM PurchaseHistory; gives the store's total sales, 26789.00.

GROUP BY and HAVING

MySQL manual: SELECT (GROUP BY, HAVING and ORDER BY clauses)

Number of games in each genre

MySQL 
SELECT Genre, COUNT(*) AS Games FROM Games
GROUP BY Genre
ORDER BY Genre;
Games in each genre
GenreGames
Action1
Action Adventure2
Adventure1
Platformer1
RPG2
Simulation1
Survival Horror4
GROUP BY Genre
Puts rows with the same genre into one group. COUNT(*) then counts each group, so the result has one row per genre.
SELECT Genre, COUNT(*)
With GROUP BY, the SELECT list may hold only the grouped column and aggregates. Adding Title would fail, because a group has many titles.
ORDER BY Genre
Sorts the result. Without it, MySQL 8 does not promise any order for groups.

Only genres with more than one game

MySQL 
SELECT Genre, COUNT(*) AS Games FROM Games
GROUP BY Genre
HAVING COUNT(*) > 1
ORDER BY Genre;
Genres with more than one game
GenreGames
Action Adventure2
RPG2
Survival Horror4
HAVING COUNT(*) > 1
HAVING filters groups after they are counted. WHERE filters rows before grouping, so WHERE COUNT(*) > 1 is an error.
The order MySQL works in

FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY. This is why WHERE cannot use an aggregate, but HAVING can.

Viva questions

What is the difference between WHERE and HAVING?

WHERE filters rows before grouping and cannot use aggregates. HAVING filters groups after GROUP BY and can use aggregates such as COUNT(*). See GROUP BY and HAVING.

Name the five common aggregate functions.

COUNT, SUM, AVG, MIN and MAX. Each returns one value from many rows. See Aggregate Functions.

What is the difference between COUNT(*) and COUNT(column)?

COUNT(*) counts every row. COUNT(column) counts only rows where that column is not NULL.

What do % and _ mean in LIKE?

% matches any number of characters, including none. _ matches exactly one character. 'R%' finds values starting with R.

Why does WHERE DeveloperID = NULL return nothing?

NULL means “unknown”, and comparing anything with unknown gives unknown, not true. Use IS NULL or IS NOT NULL.

What is an alias?

A new name given with AS, either to a result column (COUNT(*) AS Games) or to a table (FROM Games g).
