B+ Tree Index Files

A B+ tree is the index that most databases use. It finds any record in a few disk reads, and it stays balanced when you insert or delete keys.

Why we need a B+ tree

Think of a college with 50,000 student records stored on disk. You want the record for roll number 4217. Without an index, the DBMS may have to read every block of the file. That is slow, because each disk read takes time.

An index works like the index at the back of a textbook. It tells the DBMS where to look. A simple sorted index (see Ordered Indices, topic 4.5) works well at first. But when many records are inserted and deleted, a sorted index gets out of order and needs to be rebuilt.

A B+ tree solves this problem. It reorganizes itself in small steps on every insert and delete, so it never needs a full rebuild.

Definition

A B+ tree is a balanced tree that is used as an index. All search keys are stored in the leaf nodes, the leaves are linked in key order, and the internal nodes guide the search.

Balanced means that every path from the root to a leaf has the same length. So every search takes the same number of steps.

Structure of a B+ tree

Every node of a B+ tree has the same layout. A node holds up to n pointers (P) and up to n − 1 search keys (K). The keys in a node are kept in sorted order.

Layout of one node
P1K1P2K2…Pn−1Kn−1Pn

There are three kinds of node:

  • Leaf nodes are at the bottom. Each key Ki has a pointer Pi to its record on disk. The last pointer Pn points to the next leaf. The chain of linked leaves is called the sequence set.
  • Internal nodes (non-leaf nodes) only guide the search. Pointer Pi leads to a subtree that holds the keys from Ki−1 up to (but not including) Ki.
  • The root is the top node. It can be a leaf (when the tree is small) or an internal node.

The rules for each node

To stay balanced, every node except the root must be at least half full. The table shows what this means for small values of n.

Note

Some books and question papers say “a tree of order 3”. This means each node has at most 3 pointers (children), so n = 3 and each node holds at most 2 keys.

Searching

To find a key, start at the root and go down one level at a time until you reach a leaf.

  1. In the current node, compare the search key with the keys in the node.
  2. If the search key is less than the first key, follow the first pointer. Otherwise, follow the pointer just after the largest key that is less than or equal to the search key.
  3. Repeat until you reach a leaf.
  4. If the leaf has the key, the search is successful. If not, the key is not in the tree.
Example: search for 17 in the tree above
  1. At the root [19]: 17 < 19, so follow the first pointer.
  2. At [5 | 11]: 17 ≥ 11, so follow the last pointer.
  3. At the leaf [11 | 17]: 17 is found.

The search read 3 nodes, one on each level. A search for 20 also reads 3 nodes and ends at the leaf [19 | 23]. 20 is not there, so the search is unsuccessful.

Range queries

A range query asks for all keys between two values, for example “all keys from 7 to 19”. The B+ tree finds 7 with a normal search. Then it reads along the linked leaves until it passes 19. It does not need to go back up the tree. This is the main reason why the leaves are linked.

Insertion

A new key always goes into a leaf. If the leaf is full, it splits into two nodes. A split can travel up the tree, one level at a time.

  1. Search for the leaf where the new key belongs.
  2. Put the key into the leaf in sorted order.
  3. If the leaf now has more than n − 1 keys, split it. The old leaf keeps the first half of the keys. A new leaf gets the second half. Copy the first key of the new leaf (the middle key) up into the parent.
  4. If the parent now has more than n pointers, split the parent too. This time, move the middle key up. It does not stay at the lower level.
  5. If the root splits, make a new root. The tree grows one level taller.

Example: a leaf split with n = 4

A leaf holds [5 | 7 | 11], which is full (3 keys). Insert 17. The sorted keys are 5, 7, 11 and 17. The old leaf keeps [5 | 7]. The new leaf gets [11 | 17]. The middle key 11 is copied up into the parent.

Common mistake

Students often remove the middle key from the leaf after a leaf split. Do not do this. In a B+ tree, every key must stay in a leaf. Only an internal node split moves the key up.

Note on odd numbers of keys

When a full leaf gets one more key and the total is odd, one side gets the extra key. This page follows the method in the class notes: the new (right) leaf gets the extra key. For example, with n = 3, the keys 2, 3 and 5 split into [2] and [3 | 5], and 3 is copied up. Some textbooks keep the extra key on the left instead. Both trees are correct B+ trees. In the exam, use one method and show every step.

Deletion

To delete a key, find its leaf and remove the key. If the leaf is still at least half full, you are done. If not, the leaf has an underflow, and it must get more keys from a sibling. A sibling is a node next to it with the same parent.

  1. Find the leaf that holds the key and remove the key.
  2. If the leaf still has at least ⌈(n − 1) / 2⌉ keys, stop.
  3. Borrow (redistribute): if a sibling has more keys than it needs, move one key from the sibling into the leaf. Update the guide key in the parent.
  4. Merge (coalesce): if no sibling can lend a key, join the leaf and a sibling into one node. Remove one key and one pointer from the parent.
  5. If the parent now has too few pointers, repeat steps 3 and 4 for the parent. When an internal node borrows, the key from the parent comes down, and a key from the sibling goes up.
  6. If the root is left with only one child, remove the root. The tree becomes one level shorter.
  7. If the deleted key is still used as a guide key in an internal node, replace it with its in-order successor (the smallest key in the subtree to its right).
Example: delete 23, then 19 (n = 4)

Start with the tree from the class notes: insert 2, 3, 5, 7, 11, 17, 19, 23, 29, 31, then 9, 10 and 8.

Delete 23. The leaf [19 | 23] becomes [19], with only 1 key. Its only sibling, [29 | 31], has no key to spare. So merge them into [19 | 29 | 31], and remove 29 from the parent. Now the parent has only 1 pointer. Its left sibling [5 | 9 | 11] has 4 pointers, so it can lend one. The key 19 comes down from the root, the leaf [11 | 17] moves across, and 11 goes up into the root.

Delete 19. The leaf [19 | 29 | 31] becomes [29 | 31]. It still has 2 keys, so no node changes shape. But 19 is still a guide key in the internal node [19]. Replace it with its in-order successor, 29.

Fan-out and height

Definition

The fan-out of a node is the number of pointers (children) it has. In a B+ tree, each internal node except the root has a fan-out between ⌈n / 2⌉ and n.

Real B+ trees have a very large fan-out. One node usually fills one disk block. If a block is 4 KB and one key with its pointer takes about 40 bytes, a node holds about 100 pointers.

Merits and demerits (advantages and disadvantages)

Merits (advantages)

  • The tree is always balanced, so every search reads the same number of nodes.
  • Inserts and deletes change only a few nodes. The index never needs a full rebuild.
  • Every node except the root is at least half full, so little space is wasted.
  • The leaves are linked, so range queries and sorted reads are fast.
  • The tree supports both random access (one key) and sequential access (keys in order).

Demerits (disadvantages)

  • Splits and merges add extra work to inserts and deletes.
  • Some keys are stored twice (in a leaf and in an internal node), and nodes may be only half full. This takes extra space.

A B tree is a similar index that stores each key only once. Topic 4.7 compares the two.

B+ trees in MySQL

In MySQL, the InnoDB storage engine keeps each table and each index as a tree of disk pages. The MySQL manual calls these B-tree indexes. They work like a B+ tree: the keys or rows are in the leaf pages, and the pages on each level are linked. So a query on a range of values is fast.

SQL (MySQL 8.4) 
CREATE TABLE student (
  roll_no INT PRIMARY KEY,
  name    VARCHAR(50),
  marks   INT
);

CREATE INDEX idx_marks ON student (marks);

SELECT name, marks
FROM student
WHERE marks BETWEEN 60 AND 80;

The primary key roll_no gets an index on its own. CREATE INDEX builds a second index on marks. The SELECT can use this index to find 60 and then read along the leaves until it passes 80.

In real life

Railway PNR status

A railway booking system stores crores of bookings. When you check a PNR number, a B+ tree index on the PNR column finds your booking by reading only three or four nodes.

UPI payment history

When you ask your UPI app for “payments from 1 March to 15 March”, the bank's database uses an index on the payment date. It finds 1 March once, then reads along the linked leaves until 15 March. This is a range query.

Key points

  • A B+ tree is a balanced tree index: every leaf is on the same level.
  • A node has up to n pointers and n − 1 keys. Every node except the root is at least half full.
  • All keys and record pointers are in the leaves. The leaves are linked in key order.
  • A search goes from the root to one leaf, so it reads one node on each level.
  • A leaf split copies the middle key up. An internal node split moves the middle key up.
  • A deletion that leaves a node too empty borrows from a sibling, or merges with one if no sibling can lend.
  • The tree grows taller only when the root splits, and shorter only when the root loses its last key.
  • A high fan-out keeps the tree short, so a search needs few disk reads.
