RAID

RAID joins many disks so that they work like one large disk. Done well, it makes storage faster, and it keeps the data safe when a disk fails.

Why we need RAID

A database is stored on disks. A single disk has two problems.

  • It can fail. When a disk fails, all the data on it is lost. A large server has hundreds of disks, so some disk fails every few weeks.
  • It is slow. One disk can read only a limited number of blocks each second.

RAID solves both problems by using many disks together.

Definition

RAID (Redundant Array of Independent Disks) is a way of organizing several disks so that the operating system sees them as one logical disk. RAID improves reliability by storing redundant (extra) information, and it improves performance by reading and writing many disks in parallel.

The letter I first stood for “inexpensive”, because RAID let people build a big disk from many cheap ones. Today most books say “independent”.

Three key ideas

Every RAID level is built from one or more of these three ideas.

1. Striping (for speed)

Striping splits the data across several disks. With block-level striping, block 1 goes to disk 1, block 2 to disk 2, and so on. One row of blocks across the disks is called a stripe. A large file can then be read from all the disks at the same time.

2. Mirroring (for safety)

Mirroring (also called shadowing) writes every block to two disks. If one disk fails, the copy on the other disk is used. Mirroring is simple and safe, but it doubles the number of disks.

3. Parity (safety at a lower cost)

A parity block is computed from the data blocks in a stripe with the XOR (exclusive OR, ⊕) operation. XOR compares bits: two equal bits give 0, and two different bits give 1. If one data block is lost, XOR of all the other blocks in the stripe gives it back.

Example: rebuilding a block from parity

A stripe has three data blocks (each shown as 4 bits) and one parity block.

Now the disk with A2 fails. Compute A1 ⊕ A3 ⊕ P = 0110 ⊕ 1001 ⊕ 1100 = 0011. This is A2, so no data is lost.

One parity disk protects many data disks. So parity costs less than mirroring. But every write must also update the parity, so writes are slower.

RAID levels 0 to 6

A RAID level is one way of combining striping, mirroring and parity. In the figures, green blocks hold data, and purple blocks hold parity (P) or a second check code (Q).

RAID 0: block striping, no redundancy

Data blocks are striped across all the disks. Nothing extra is stored.

  • Merit (advantage): the fastest level, and all the space holds data.
  • Demerit (disadvantage): no redundancy. If any one disk fails, the data is lost.

RAID 1: mirroring

Every block is written to two disks. Some books call striping plus mirroring RAID 1 + 0 or RAID 10.

  • Merits (advantages): the data survives a disk failure; reads are fast, because either copy can be read; rebuilding is a simple copy.
  • Demerit (disadvantage): only half of the space holds data, so it is costly.

RAID 2: memory-style error-correcting codes

Data is striped at the level of bits. Extra disks store error-correcting codes (ECC), such as Hamming codes, like the codes used in computer memory. For example, 4 data disks need 3 code disks.

  • Merit (advantage): it can find and correct a wrong bit.
  • Demerit (disadvantage): it needs many extra disks and is complex, so it is not used in practice. RAID 3 does the same job with one extra disk.

RAID 3: bit-interleaved parity

Data is striped in very small units (bits or bytes). One disk holds all the parity. A disk controller can already tell which disk has failed, so one parity bit is enough to rebuild the lost bit.

  • Merits (advantages): only one extra disk; good speed for large reads and writes, because all disks work together.
  • Demerit (disadvantage): every request uses every disk, so the array can serve only one small request at a time.

RAID 4: block-interleaved parity

Like RAID 3, but the data is striped in blocks. One disk holds the parity blocks.

  • Merit (advantage): a small read uses only one disk, so different disks can serve different reads at the same time.
  • Demerit (disadvantage): every write must also update the parity disk. The parity disk becomes a bottleneck (the slowest point).

RAID 5: block-interleaved distributed parity

Like RAID 4, but the parity blocks are spread over all the disks. In each stripe, a different disk holds the parity.

  • Merits (advantages): no single parity disk, so there is no bottleneck; all disks also serve reads; only one disk of space is used for parity.
  • Demerit (disadvantage): a small write needs four disk operations: read the old data, read the old parity, write the new data, and write the new parity.

RAID 6: P + Q redundancy

Like RAID 5, but each stripe has two check blocks. P is the parity. Q uses a different code (such as a Reed-Solomon code). It needs at least 4 disks.

  • Merit (advantage): the data survives two disk failures at the same time.
  • Demerits (disadvantages): two disks of space go to check blocks, and writes are slower than RAID 5.

Choosing a RAID level

Four factors decide which RAID level to use:

  1. The money cost of the extra disks.
  2. Performance in normal use, measured in input and output (I/O) operations each second.
  3. Performance when a disk has failed.
  4. Performance during a rebuild, when the data of the failed disk is being put on a new disk.

RAID 2, 3 and 4 are rarely used today. RAID 5 is better than RAID 4, and RAID 3 offers nothing that RAID 5 does not.

Common mistake

RAID is not a backup. If a user deletes a table by mistake, RAID deletes it on every disk at once. A database still needs backups (see recovery in Unit III).

Merits and demerits (advantages and disadvantages)

Merits (advantages)

  • Reliability: with mirroring or parity, the data survives a disk failure.
  • Performance: striping lets many disks work in parallel.
  • Availability: the system keeps running while a failed disk is replaced and rebuilt.
  • The operating system and the DBMS see one large disk, so nothing else needs to change.

Demerits (disadvantages)

  • Extra disks cost money, and some space holds copies or parity instead of data.
  • Parity levels make small writes slower.
  • It does not protect against user mistakes, viruses or fire, so backups are still needed.

Try it yourself

Pick a RAID level and watch the blocks being written. Then press Fail on a disk and see whether the data survives. Press Replace and rebuild to put the data back on a new disk.

Things to try
  • In RAID 0, fail any disk. Why is all the data lost, and not just a quarter of it?
  • In RAID 5, fail disk 2 and check the XOR shown in the narration by hand.
  • In RAID 6, fail two disks. Then try the same in RAID 5.

In real life

Exam result day

When a university publishes results, lakhs of students check them at the same time. Striping across many disks lets the server answer many reads at once, and parity keeps the site running if a disk fails.

Bank servers

A bank cannot lose a single payment. Its database servers usually keep the transaction log on mirrored disks (RAID 1) and the tables on RAID 5 or RAID 6, and they still take backups every day.

Key points

  • RAID (Redundant Array of Independent Disks) makes many disks work as one logical disk.
  • Striping gives speed, mirroring gives safety, and parity gives safety at a lower cost.
  • Parity is the XOR of the data blocks in a stripe. XOR of the other blocks rebuilds a lost block.
  • RAID 0 has no redundancy. RAID 1 mirrors every block.
  • RAID 2 uses error-correcting codes; RAID 3 and RAID 4 use one parity disk (bit and block striping).
  • RAID 5 spreads parity over all disks, so there is no parity bottleneck.
  • RAID 6 stores P and Q in each stripe and survives two disk failures.
  • Choose a level by cost, normal performance, performance after a failure and rebuild performance.
