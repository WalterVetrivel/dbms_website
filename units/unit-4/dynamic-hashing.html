Dynamic Hashing

Static hashing has a fixed number of buckets, so a growing file overflows. Dynamic hashing lets the number of buckets grow and shrink with the data, one bucket at a time.

Why we need dynamic hashing

Static hashing (topic 4.8) fixes the number of buckets when the file is created. A database usually grows, so there are three poor choices:

  1. Choose buckets for the current size. As the file grows, buckets overflow and searches slow down.
  2. Choose buckets for the size expected in some years. Much space is wasted at first.
  3. Reorganize from time to time with a new hash function and more buckets. Every record must move, and the file cannot be used while this happens.
Definition

Dynamic hashing is hashing in which the number of buckets changes as the database grows or shrinks. Buckets are added or removed one at a time, when needed. The most common form is extendible hashing.

Extendible hashing: the structure

The hash function gives a value written as a string of bits, for example h(17) = 10001. Extendible hashing does not use all the bits at once. It uses only as many bits as it needs now, and more bits later as the file grows.

Directory (bucket address table)
A table of pointers to buckets. To find a key, the DBMS takes the last d bits of its hash value and follows that entry of the directory. The directory has 2d entries.
Global depth (d)
The number of bits the directory uses. It belongs to the whole directory.
Local depth (d′)
The number of bits that all the keys in one bucket share. Each bucket has its own local depth, and it is never more than the global depth.

If a bucket's local depth is less than the global depth, several directory entries point to the same bucket. For example, with d = 3, a bucket of local depth 2 for the bits 00 is pointed to by both 000 and 100. The number of entries that point to a bucket is 2d − d′.

Note on bits

The class notes, and this page, use the last bits of the hash value. Silberschatz uses the first bits of a 32-bit hash value. The method is the same; only the end of the bit string differs.

Search, insertion and deletion

Search

Compute h(K), take its last d bits, follow that directory entry to a bucket and look for K there. A search reads the directory entry and one bucket.

Insertion

  1. Find the bucket for the key, as in a search. If it has room, put the key there. Done.
  2. If the bucket is full and its local depth is less than the global depth, split the bucket. Make a new bucket and increase the local depth of both by 1. Move each key to the bucket that matches its next bit. Point half of the directory entries that pointed to the old bucket at the new one.
  3. If the bucket is full and its local depth equals the global depth, first double the directory. Add 1 to the global depth, and give each new entry the same pointer as its partner entry. Then split the bucket as in step 2.
  4. Try to insert the key again. (Rarely, all the keys go to one side and a further split is needed.)

Deletion

Find the key and remove it. If its bucket becomes empty, merge it with its split image (the bucket that differs only in the last bit of its local depth). The directory entries now point to the remaining bucket, and its local depth goes down by 1. If no bucket uses all d bits any more, the directory can be halved.

Common mistake

Not every split doubles the directory. The directory doubles only when the full bucket's local depth equals the global depth. Otherwise only the bucket splits.

Static hashing compared with dynamic hashing

Static hashing compared with dynamic (extendible) hashing
Static hashingDynamic hashing
The number of buckets is fixed when the file is created.The number of buckets grows and shrinks with the data.
The hash function never changes.The function uses more or fewer bits of the hash value.
A growing file causes bucket overflow and long chains.A full bucket splits, so overflow is rare.
Growing means reorganizing the whole file.Growing changes only one bucket (and sometimes doubles the directory).
Simple; no directory.Needs a directory (bucket address table), one extra step on each lookup.
Wastes space if built large for the future.Uses space in step with the data.

Merits and demerits (advantages and disadvantages)

Merits (advantages)

  • Performance does not fall as the file grows.
  • Little wasted space: buckets are added only when needed.
  • No full reorganization: a split moves only the keys of one bucket.

Demerits (disadvantages)

  • Each lookup goes through the directory first, which is one more step.
  • Doubling the directory is costly when the directory is large.
  • If many keys share the same last bits, the directory can grow very large for a few buckets.
  • Like all hashing, it is poor for range queries.

In real life

A growing shop

A new online shop starts with a few hundred customers. On sale days, thousands join every hour. Dynamic hashing adds buckets as customers join, without stopping the site to rebuild its files.

A growing hostel

A hostel puts students in rooms by the last digit of the roll number. When one room is full, it opens a new room and splits that group by the last two digits. Only that one group moves.

Key points

  • Dynamic hashing changes the number of buckets as the data grows or shrinks; extendible hashing is the common form.
  • The directory (bucket address table) uses the last d bits of the hash value; d is the global depth.
  • Each bucket has a local depth d′; 2d − d′ directory entries point to it.
  • A full bucket with d′ < d splits; the directory does not change size.
  • A full bucket with d′ = d first doubles the directory (d increases by 1), then splits.
  • When a bucket becomes empty, it merges with its split image, and the directory may halve.
  • Dynamic hashing avoids overflow chains and full reorganization, at the cost of one directory lookup.
