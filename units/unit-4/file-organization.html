File Organization

A table is stored on disk as a file of records. The way those records are arranged decides how fast the DBMS can find, add and delete them.

Files, records and blocks

Think of a STUDENT table with 5,000 rows. On disk, the DBMS keeps it in a file.

  • A file is a sequence of records. Each row of the table is one record.
  • A record is a sequence of fields (the columns, such as RollNo and Name).
  • The disk reads and writes data in fixed-size units called blocks (for example 4 KB or 8 KB). One block holds many records.

Reading one block from disk is slow compared with work in memory. So the goal of every file organization is to read as few blocks as possible.

Definition

A file organization is the method of arranging the records of a file on disk, so that the DBMS can store and find them.

The four main file organizations are heap, sequential, hashing and multitable clustering. How each record is laid out inside a block (fixed-length and variable-length records) is covered in topic 4.3.

Operations on files

Programs work with a file through a small set of operations. They are of two kinds: retrieval operations find and read records, and update operations insert, delete and modify them. Most operations use a selection condition, such as RollNo = 112 or Dept = 'CSE', to choose the records.

The DBMS keeps a current record pointer for each open file. Record-at-a-time operations work on one record and move this pointer.

Record-at-a-time operations
OperationWhat it does
OpenPrepares the file for reading or writing and sets the pointer to the start of the file.
ResetMoves the pointer back to the first record.
Find (locate)Finds the first record that meets the condition and makes it the current record.
FindNextFinds the next record that meets the condition.
Read (get)Copies the current record into memory.
InsertAdds a new record to the file.
DeleteRemoves the current record, or marks it as deleted.
ModifyChanges some field values of the current record.
CloseFinishes using the file and frees its buffers.

Set-at-a-time operations work on many records at once:

  • FindAll: finds all the records that meet the condition.
  • Find n: finds the next n records that meet the condition.
  • FindOrdered: returns all the records in a given order.
  • Reorganize: rebuilds the file, for example to sort it or to remove deleted records.
Example

To raise the marks of RollNo 112: Open the STUDENT file, Find the record with RollNo = 112, Read it, Modify the Marks field, then Close the file. The SQL statement UPDATE student SET marks = marks + 5 WHERE rollno = 112; does all of these steps for you.

The file organization decides how fast each operation is. For example, Find on RollNo is slow in a heap file but fast in a hashing file on RollNo.

Heap file organization

Definition

In a heap file organization, a record can be placed anywhere in the file where there is space. The records are in no order.

A new record usually goes into the last block, or into any block with free space. The DBMS keeps a small list of blocks that have free space, so it does not have to search for room.

A heap file: records are in the order they arrived
BlockRecords (RollNo, Name)
1(126, Harini), (101, Anitha), (148, Nandhini)
2(112, Divya), (137, Karthik), (104, Bharath)
3(130, Imran), free space
  • Merits (advantages): inserting is very fast; no space is wasted on keeping an order; good for loading a lot of data at once.
  • Demerits (disadvantages): to find one record, the DBMS may have to read every block (a linear scan); range queries and sorted output are slow without an index.

Sequential file organization

Definition

In a sequential file organization, the records are stored in sorted order of a search key. A search key is the attribute (or set of attributes) used to look up records, for example RollNo.

Each record has a pointer to the next record in search-key order. Keeping the records in the same order on disk as well makes reading the whole file in order very fast.

A sequential file sorted on RollNo. Each record points to the next one.
BlockRecords in RollNo order
1101 → 104 → 108
2112 → 115 → 119
3123 → 126 → 130

Insertion

Keeping the records in order on disk is hard when there are many inserts. The DBMS uses these rules:

  1. Find the record that comes just before the new record in search-key order.
  2. If that block has free space, put the new record there.
  3. If not, put the new record in an overflow block.
  4. In both cases, update the pointer chain so that the records can still be read in order.
Example: insert RollNo 110

110 belongs after 108, in block 1. Block 1 is full, so 110 goes to an overflow block. The pointer of 108 now points to 110, and the pointer of 110 points to 112. Reading the file in order still gives 101, 104, 108, 110, 112 …

Deletion

To delete a record, remove it from the pointer chain: the record before it now points to the record after it.

After many inserts, the file has many overflow blocks, and reading in order jumps around the disk. Then the file is reorganized: it is rewritten in sorted order. This is done when the system is not busy.

  • Merits (advantages): reading all records in key order is fast; a search on the key can use binary search; range queries (RollNo 110 to 125) are fast.
  • Demerits (disadvantages): inserts and deletes are slow because the order must be kept; overflow blocks build up, so the file needs reorganizing.

Hashing file organization

Definition

In a hashing file organization, a hash function is computed on an attribute of each record. The result says which bucket (block) the record goes into.

For example, with h(RollNo) = RollNo mod 10, the record for RollNo 126 goes into bucket 6. To find RollNo 126 later, the DBMS computes h(126) = 6 and reads only bucket 6.

  • Merit (advantage): a search for one key value needs about one block read.
  • Demerits (disadvantages): range queries are slow, because nearby keys are in different buckets; a bucket can overflow when too many records hash to it.

Topic 4.8 (static hashing) and topic 4.9 (dynamic hashing) explain hashing in detail.

Multitable clustering file organization

Usually each table has its own file. Some queries join two tables again and again, for example a department and its students.

Definition

In a multitable clustering file organization, records of two or more tables are stored in the same file. Related records are kept close together, often in the same block. The attribute that decides which records go together is the cluster key.

DEPARTMENT and STUDENT records stored together, clustered on DeptID
RecordTable

101, Anitha, CSESTUDENT

ECE, Electronics, Block BDEPARTMENT

A query that joins DEPARTMENT and STUDENT on DeptID now finds each department and its students in one block.

  • Merit (advantage): joins on the cluster key are very fast.
  • Demerits (disadvantages): a query on only one table reads blocks that also hold the other table, so it is slower. The file has records of different types and sizes, so it is more complex.

To read only the students quickly, the DBMS can link all STUDENT records with a pointer chain.

File organization in MySQL

MySQL's InnoDB storage engine stores every table sorted on its primary key, inside a B+ tree (see topic 4.6). The manual calls this the clustered index. So an InnoDB table behaves like a sequential file that never needs reorganizing.

SQL (MySQL 8.4) 
CREATE TABLE student (
  roll_no INT PRIMARY KEY,
  name    VARCHAR(50),
  dept    CHAR(4)
);

-- Rows come back in roll_no order, read along the clustered index.
SELECT * FROM student WHERE roll_no BETWEEN 110 AND 125;

In real life

Attendance log

A college records every swipe of a student ID card at the gate. New rows arrive all day and are rarely searched one by one. A heap file suits this: each new row is simply added at the end.

Mark sheets in roll number order

The exam cell prints mark sheets in roll number order once a semester. A file sorted on roll number (sequential organization) lets it read every record in order without sorting.

Key points

  • A file is a sequence of records, and a record is a sequence of fields. Data moves between disk and memory in blocks.
  • A file organization is the way the records of a file are arranged on disk.
  • Operations on files: Open, Reset, Find, FindNext, Read, Insert, Delete, Modify and Close one record at a time, and FindAll, Find n, FindOrdered and Reorganize for many records.
  • Heap: records in any order. Fast inserts, slow searches.
  • Sequential: records sorted on a search key and linked by pointers. Fast ordered reads, slow inserts.
  • A sequential file puts extra records in overflow blocks and is reorganized from time to time.
  • Hashing: a hash function on an attribute gives the bucket of each record. Fast exact lookups, poor range queries.
  • Multitable clustering stores related records of several tables together, which speeds up joins.
