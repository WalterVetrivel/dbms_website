Ordered Indices

An ordered index keeps its search keys in sorted order, like the index of a book. This page covers the main types: primary and secondary, dense and sparse, and multilevel.

What an ordered index is

Definition

An ordered index stores the search-key values in sorted order, and links each value to the records that have it.

On this page, the data file is a STUDENT file with 15 records, kept in RollNo order, with 3 records in each block (B1 to B5).

Primary and secondary indices

Definitions

A primary index, also called a clustering index, is an index whose search key also sets the order of the records in the file. A file can have only one primary index.

A secondary index, also called a non-clustering index, is an index whose search key is in a different order from the file. A file can have many secondary indices.

For our file, an index on RollNo is the primary (clustering) index, because the file is sorted on RollNo. An index on Name or Dept is a secondary (non-clustering) index.

Note on terms

This page follows Silberschatz, where “primary index” and “clustering index” mean the same thing. Elmasri and Navathe split them. In their books, a primary index is on an ordering field that is a key (unique). A clustering index is on an ordering field that is not a key, such as Dept when the file is sorted by Dept. In both books, a secondary index is on a field that does not set the order of the file.

A clustering index on a non-key field groups records with the same value together. For example, if the file were sorted by semester, all first-semester students would be together, then all second-semester students, and so on. The index entry for each semester points to the first record of its group.

Clustering index compared with non-clustering index
Clustering (primary) indexNon-clustering (secondary) index
The file is sorted on the same search key as the index.The file is sorted on a different key.

Records with nearby keys are in the same block, so range queries read few blocks.Records with nearby keys can be in different blocks, so a range query may read one block per record.

Dense and sparse indices

Definitions

In a dense index, there is an index entry for every search-key value in the file.

In a sparse index, there are index entries for only some of the search-key values, usually one entry for each block (the first key in the block).

Searching

  • Dense index: find the entry for the key and follow its pointer straight to the record. If there is no entry, the record does not exist, and no data block is read.
  • Sparse index: find the entry with the largest search key that is less than or equal to the key you want. Follow its pointer to a block, then read the records in that block one by one until you find the key.
Example: find RollNo 126 with the sparse index
  1. The largest entry that is less than or equal to 126 is 123. It points to block B3.
  2. Read block B3: 123 is not it, 126 is found.

Only one data block is read, and the index has only 5 entries instead of 15.

A sparse index works only when the file is sorted on the search key, so only a clustering index can be sparse. A secondary index must be dense, because the records it points to are not in order.

Dense index compared with sparse index
Dense indexSparse index

Exam tip

A good trade-off, used by real systems, is a sparse index with one entry per block. The biggest cost of a search is bringing a block into memory. Once the block is in memory, looking through it takes almost no time.

Multilevel indices

Even a sparse index can be large. Suppose a file has 1,000,000 records and 100 records fit in a block. That is 10,000 data blocks, so a sparse index has 10,000 entries. If 100 entries fit in a block, the index itself fills 100 blocks. A binary search on 100 blocks reads about log2(100) ≈ 7 index blocks for every search.

The solution is to treat the index like any other sorted file and build a sparse index on the index.

Definition

A multilevel index is an index with two or more levels. The original index is the inner index. A sparse outer index is built on the blocks of the inner index. If the outer index is still too large, another level is added.

In the example, the outer index has only 100 entries, so it fits in one block, which can stay in memory. A search reads 1 inner index block and then 1 data block, instead of about 7 index blocks.

Example from the class notes: why an index helps

A data file has 300 blocks. A binary search on the file reads about log2(300) + 1 ≈ 9 blocks. Its primary index fits in only 3 blocks. A binary search on the index reads about log2(3) + 1 ≈ 3 blocks, plus one read of the data block that the index points to.

A multilevel index is a tree. A B+ tree (topic 4.6) is a multilevel index that stays balanced as records are inserted and deleted.

Secondary indices on non-key attributes

A secondary index on Dept has a problem: many students share the same department. Each index entry must point to all the records with that value.

The usual answer is an extra level of indirection. Each index entry points to a bucket of pointers, and the bucket holds a pointer to every record with that value.

A secondary index on Dept, with a bucket of record pointers for each value

The five CSE students are in four different blocks. So a query for all CSE students may read one block for each student. This is why a secondary index is slower than a clustering index for queries that return many records.

Updating an index

Every index must change when records are inserted or deleted.

  • Insertion, dense index: if the search-key value is new, add an entry for it in the right sorted place.
  • Insertion, sparse index: change the index only if the insert creates a new block; the first key of the new block gets an entry.
  • Deletion, dense index: if the deleted record was the last one with its search-key value, remove that entry.
  • Deletion, sparse index: if the deleted key has an index entry, replace it with the next key in the file, or remove the entry if the block is now empty.

Try it yourself

Choose a dense, sparse or multilevel index and search for a roll number. Watch which index entries and blocks are read. Then try a roll number that is not in the file.

Things to try
  • Search for 120 with the dense index and then with the sparse index. Which one finds out sooner that 120 is missing?
  • Search for 141 with each index. Count the index entries and the records checked.

In real life

A dictionary

A printed dictionary shows the first word of each page at the top. That is a sparse index: you find the right page from the top words, then read down the page.

College admissions

The admission file is sorted by application number (the primary index). The office also searches by name and by district, so it keeps secondary indices on those fields.

Key points

  • An ordered index keeps search keys in sorted order with pointers to the records.
  • A primary (clustering) index has a search key that sets the file order; a file has only one.
  • A secondary (non-clustering) index is on any other search key; it must be dense.
  • A dense index has an entry for every search-key value; a sparse index has one for only some values, usually one per block.
  • To search a sparse index, take the largest entry less than or equal to the key, then scan that block.
  • A multilevel index builds a sparse outer index on the inner index, so a search reads very few blocks.
  • A secondary index on a non-key attribute points to a bucket of record pointers for each value.
