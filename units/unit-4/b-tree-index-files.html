What a B tree is

In a B+ tree (topic 4.6), every key is stored in a leaf, and some keys are stored again in the internal nodes as guides. A B tree removes this repetition.

Definition

A B tree is a balanced multiway search tree used as an index, in which each search-key value appears only once. Every key, in a leaf or in an internal node, has a pointer to its record.

Like a B+ tree, a B tree has many children for each node, so it stays short, and a search reads only a few nodes from disk.

Structure of a B tree

A node of a B tree of order n has up to n child pointers (P) and up to n − 1 keys (K). An internal node also has a record pointer (B) for each key.

Layout of an internal node: each key Ki has a record pointer Bi
P1B1K1P2B2K2…Pn
  • The keys in a node are in sorted order.
  • Child pointer Pi leads to the keys between Ki−1 and Ki.
  • A leaf node has keys and record pointers but no child pointers. The leaves are not linked.
  • All leaves are on the same level, so the tree is balanced.

Note

“A B tree of order 3” means each node has at most 3 children, so it holds at most 2 keys. This is the meaning used in the class notes and on this page.

Searching

  1. Start at the root.
  2. Compare the search key with the keys in the node. If it is equal to one of them, the search is successful: follow that key's record pointer.
  3. Otherwise, follow the child pointer between the two keys that the search key falls between.
  4. If you reach a leaf and the key is not there, the search is unsuccessful.

Because a key can be found in an internal node, a search can stop before reaching a leaf. In a B+ tree, every search goes all the way to a leaf.

Example: search the tree in the worked example below

Search 40: at the root [20], 40 > 20, so go right. At [40], 40 is found. The search stops on level 2.

Search 15: at [20], 15 < 20, so go left. At [12], 15 > 12, so go right. At the leaf [15], 15 is found.

Insertion

A new key always goes into a leaf. If the leaf becomes too full, it splits, and the middle key moves up.

  1. Search for the key. If it is already in the tree, stop (keys are unique).
  2. Put the key into the leaf where the search ended, in sorted order.
  3. If the leaf now has more than n − 1 keys, split it into two nodes. The middle key moves up into the parent, together with its record pointer. It does not stay in the leaf.
  4. If the parent is now too full, split it the same way.
  5. If the root splits, the middle key becomes a new root. The tree grows one level taller.
Common mistake

In a B+ tree, a leaf split copies the middle key up, so it stays in the leaf too. In a B tree, every split moves the middle key up, because each key is stored only once.

Deletion

Deletion is harder in a B tree than in a B+ tree, because the key may be in an internal node.

  1. Key in a leaf: remove it from the leaf.
  2. Key in an internal node: replace it with its in-order successor (the smallest key in the subtree to its right, always in a leaf). Then remove the successor from that leaf.
  3. If the leaf still has at least ⌈n / 2⌉ − 1 keys, stop.
  4. Borrow: if a sibling has a key to spare, the separating key comes down from the parent into the node. The sibling's nearest key goes up to take its place.
  5. Merge: if no sibling can spare a key, join the node, the separating key from the parent and a sibling into one node.
  6. If the parent now has too few keys, repeat steps 4 and 5 for the parent. If the root loses its last key, its only child becomes the new root, and the tree gets one level shorter.

The examples start from the worked example tree with one more key, 35.

Delete 50 (borrow). The leaf [50] becomes empty. Its left sibling [30 | 35] has a key to spare. So 40 comes down from the parent into the empty leaf, and 35 goes up to take its place.

Delete 20 (internal key, then merges). 20 is in the root. Its in-order successor is 30, so 30 replaces 20, and 30 is removed from its leaf. That leaf is now empty, and its sibling [40] has no key to spare. So the leaf merges with [40], and 35 comes down: [35 | 40]. Now their parent is empty, and its sibling [12] cannot lend either, so they merge with 30 from the root: [12 | 30]. The root is empty, so [12 | 30] becomes the new root.

When a B+ tree is preferred

  • Range queries: “all students with marks from 60 to 80” finds 60 once and reads along the leaves.
  • Sorted output: ORDER BY on the indexed attribute reads the leaves from left to right.
  • Large tables: the higher fan-out keeps the tree shorter, so a search reads fewer blocks.

Because of these merits, almost every database system, MySQL included, uses B+ trees, not B trees, for its indices. The small space saving of a B tree is not worth the extra complexity.

Merits and demerits (advantages and disadvantages)

Merits (advantages)

  • Each key is stored once, so a B tree can use slightly fewer nodes than a B+ tree for the same keys.
  • A search can end early when the key is in an internal node.
  • The tree stays balanced, so every search reads at most one node on each level.

Demerits (disadvantages)

  • Only a few keys are found early; most keys are in the leaves anyway.
  • Internal nodes hold record pointers, so they hold fewer keys and the tree is taller.
  • Range queries and sorted reads are slow, because the leaves are not linked.
  • Insertion and deletion are more complex to program.

In real life

Why your bank uses B+ trees

A bank statement lists your payments from one date to another. This is a range query, so bank databases index payment dates with B+ trees, whose linked leaves make range queries fast.

File systems

Some file systems and key-value stores use B tree variants to find files and keys. The same idea, a short balanced tree with many keys in each node, appears in many systems.

Key points

  • A B tree is a balanced tree index in which each key appears only once.
  • Every key, in any node, has a pointer to its record. The leaves are not linked.
  • A node of order n has at most n − 1 keys; every node except the root has at least ⌈n / 2⌉ − 1 keys.
  • A search can stop at an internal node when it finds the key there.
  • Insertion splits a full node and moves the middle key up; a root split makes the tree taller.
  • To delete an internal key, replace it with its in-order successor; an underflow borrows from a sibling or merges.
  • B+ trees are preferred in practice: linked leaves give fast range queries, and a higher fan-out keeps the tree short.
