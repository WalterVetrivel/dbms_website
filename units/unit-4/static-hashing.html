Static Hashing

Hashing finds a record by computing where it is, instead of searching for it. In static hashing, the number of buckets is fixed when the file is created.

The idea of hashing

A college hostel has 10 rooms for parcels, numbered 0 to 9. The rule is simple: a parcel goes to the room numbered by the last digit of the student's roll number. To collect a parcel, a student goes straight to one room. No list and no search are needed.

Hashing works the same way.

Definitions

A bucket is a unit of storage that holds one or more records. Usually a bucket is one disk block.

A hash function h maps every search-key value K to a bucket address h(K).

In static hashing, the set of bucket addresses is fixed: the number of buckets B does not change as the file grows or shrinks.

A common hash function for numbers is h(K) = K mod B. With B = 10, h(34789) = 34789 mod 10 = 9, so the record for RollNo 34789 always goes into bucket 9.

Collision
Two different keys hash to the same bucket, for example 25 and 55 with h(K) = K mod 10.
Synonyms
Keys that hash to the same bucket. 25 and 55 are synonyms.
Probe
One calculation of an address and one check of that bucket.

Insert, search and delete

  • Insert: compute h(K) and put the record in that bucket, if there is space.
  • Search: compute h(K), read that bucket and look through its records for K. Records of other keys may be in the same bucket, so each one is checked.
  • Delete: search for the record as above, then remove it from the bucket.
Example: h(K) = K mod 5, two records per bucket

Insert 10, 22, 15 and 37. h(10) = 0, h(22) = 2, h(15) = 0 and h(37) = 2. So bucket 0 holds 10 and 15, and bucket 2 holds 22 and 37. To find 15, compute h(15) = 0 and read only bucket 0.

For a search on the hash key, the DBMS reads about one block, however large the file is. This is the main merit of hashing.

A good hash function

The worst hash function sends every key to the same bucket. Then a search reads the whole file. A good hash function spreads the keys well. It is:

  • Uniform: each bucket gets about the same number of possible search-key values.
  • Random: each bucket gets about the same number of the actual records, whatever pattern the data has.

For example, a hash function on names that uses only the first letter is poor: many names start with S, and very few start with X. For strings, a hash function usually combines the codes of all the characters and then takes the result mod B.

Bucket overflow

Definition

Bucket overflow happens when a new record hashes to a bucket that is already full.

There are two causes:

  1. Too few buckets. The number of buckets B should be more than nr / fr. Here nr is the number of records and fr is the number of records that fit in a bucket. Designers usually add about 20% more buckets than this (a “fudge factor”).
  2. Skew. Some buckets get many more records than others, because many records have the same search-key value, or because the hash function spreads the keys unevenly.

Overflow can be made rare, but not impossible. So every hash file needs a way to handle it.

Overflow chaining (closed hashing)

When a bucket is full, the new record goes into an overflow bucket. All the overflow buckets of one bucket are linked in a list called an overflow chain.

A search for 25 computes h(25) = 0, reads bucket 0, and then follows the chain to the overflow bucket. The records of one bucket are found by following its chain, so the set of buckets stays fixed. Silberschatz calls this form closed hashing.

Open hashing (linear probing)

In open hashing, there are no overflow chains. When a bucket is full, the record goes into another bucket that has space. With linear probing, the DBMS tries the next bucket, then the one after it, and so on, going back to bucket 0 after the last bucket.

Example from the class notes: insert 105 with h(K) = K mod 10

Each bucket holds one record. Buckets 5, 6 and 7 already hold 25, 55 and 36. h(105) = 5, but bucket 5 is full. The next bucket, 6, is full, and so is bucket 7. Bucket 8 is empty, so 105 goes into bucket 8.

A search for 105 must follow the same path: 5, 6, 7, 8. A search for a missing key stops at the first bucket that has free space.

  • Merits (advantages): simple and fast when the table is mostly empty; no extra overflow blocks.
  • Demerits (disadvantages): full buckets form clusters, so searches get longer. When every bucket is full, no record can be added. Deletion is hard, because removing a record can break the probe path of other keys.

Because deletion is hard, database systems use overflow chaining. Open hashing is used for in-memory tables, for example in compilers.

Note on terms

Some books swap these two names: they call chaining “open hashing” and probing “closed hashing”. In the exam, name the method too (overflow chaining or linear probing), so the meaning is clear.

Hash files and hash indices

  • In a hash file organization (topic 4.2), the buckets hold the records themselves.
  • In a hash index, the buckets hold index entries: search keys with pointers to the records, which are stored in some other file. A hash index is always a secondary index.

Why hashing is poor for range queries

Suppose a query asks for all students with RollNo from 120 to 130. With h(K) = K mod 10, these keys are spread over every one of the 10 buckets. The hash value of 120 tells nothing about where 121 is. So the DBMS has to read all the buckets.

A good hash function spreads keys randomly on purpose. That is why it is fast for one exact key, and also why it cannot keep keys in order. For range queries, use an ordered index such as a B+ tree (topic 4.6).

Merits and demerits (advantages and disadvantages)

Merits (advantages)

  • A search on the hash key needs about one disk access.
  • Simple to build: no index tree to keep balanced.
  • Inserts and deletes are fast while there is no overflow.

Demerits (disadvantages)

  • The number of buckets is fixed. If the database grows, buckets overflow and searches get slower. If it starts with many spare buckets, space is wasted. If it shrinks, space is wasted too.
  • Changing the number of buckets means choosing a new hash function and moving every record, which takes a long time.
  • Range queries and sorted output are slow.

Dynamic hashing (topic 4.9) removes the first two problems by letting the number of buckets change.

Try it yourself

Choose the number of buckets, the bucket size and the way to handle a full bucket. Insert keys and search for them. Each step shows the hash calculation.

Things to try
  • Load the open hashing example and search for 105, then for 65. Count the probes.
  • With 5 buckets, insert 5, 10, 15, 20, 25 and 30. This is skew: every key hashes to bucket 0.
  • Repeat the same keys with 7 buckets. Why does a prime number of buckets often spread keys better?

In real life

Locker room at an exam hall

Bags go into lockers by the last two digits of the hall ticket number. Finding your bag takes one step. But if many students share the same last two digits, that locker overflows, just like a bucket.

Login sessions

A website checks your login token on every page you open. It always looks for one exact token, so it keeps sessions in a hash table, which finds the token in one step.

Key points

  • A hash function h maps each search-key value to a bucket; a bucket is usually one disk block.
  • In static hashing, the number of buckets is fixed, for example h(K) = K mod B.
  • A search on the hash key reads about one block.
  • A good hash function is uniform and random.
  • Bucket overflow is caused by too few buckets or by skew.
  • Overflow chaining (closed hashing) links overflow buckets to a full bucket; databases use this method.
  • Open hashing with linear probing puts the record in the next bucket with space; it causes clustering and makes deletion hard.
  • Static hashing cannot grow or shrink well, and it is poor for range queries.
