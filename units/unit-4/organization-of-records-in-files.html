Organization of Records in Files

Inside a file, each record needs a place in a block. Fixed-length records are simple to place. Variable-length records need a smarter layout called the slotted page.

Fixed-length records

Look at this record type for employees. Every field has a fixed size, so every record has the same size.

Record type 
type employee = record
  EmpNo   char(4);
  Ename   char(10);
  Salary  numeric(5);
  Phone   char(10);
end

Each record takes 4 + 10 + 5 + 10 = 29 bytes. A short name such as “Arun” is padded with spaces to fill its 10 bytes.

Definition

A file has fixed-length records when every record in it has the same size. If each record takes n bytes, record i starts at byte n × (i − 1).

So the DBMS can find record 5 at once: it starts at byte 29 × 4 = 116. This makes access fast and simple. But there are two problems.

  1. Records can cross block boundaries. If the block size is not a multiple of 29, part of a record is in one block and the rest is in the next. Reading that record needs two block reads. The fix is to store only as many whole records as fit in a block and leave the few bytes at the end empty.
  2. Deletion leaves a hole. When a record is deleted, its space must be filled or remembered.

Handling deleted records

There are three ways to deal with the hole left by a deleted record.

  • Move every following record up by one place. This needs many disk writes, so it is a poor choice.
  • Move the last record of the file into the hole. Only one record moves.
  • Keep a free list and do not move any record. This is the usual method.
Definition

A free list is a linked list of the deleted records. A file header at the start of the file holds the address of the first deleted record. Each deleted record holds the address of the next deleted record.

On an insert, the DBMS puts the new record in the place the header points to, and the header moves on to the next free record. If the free list is empty, the new record goes at the end of the file.

Example: delete records 1, 3 and 5

After the three deletes, the free list is: header → record 5 → record 3 → record 1 → end. The newest deleted record is at the front. The next insert uses record 5.

Variable-length records

Real tables use VARCHAR fields, so records have different sizes. Variable-length records arise in three ways:

  • Fields whose length can change, such as VARCHAR.
  • Fields that repeat, such as arrays or multisets.
  • Records of more than one type stored in the same file (as in multitable clustering, topic 4.2).
Definition

A file has variable-length records when records in it can have different sizes.

How one variable-length record is stored

The record has two parts:

  1. An initial part of fixed size. Fixed-length fields (such as Salary) are stored here directly. Each variable-length field is stored here as an (offset, length) pair: where its data starts in the record, and how many bytes it takes.
  2. The data of the variable-length fields, one after the other.

A null bitmap sits between the two parts. It has one bit for each field; a 1 means that the field is null.

The slotted-page structure

Variable-length records must be placed inside a block. The common way is the slotted-page structure.

Definition

In the slotted-page structure, each block starts with a block header that holds:

  1. the number of record entries in the block,
  2. the end of free space in the block, and
  3. an array of entries, one per record, giving the location and size of the record.

The records are stored together at the end of the block. The free space is in one piece, between the header and the records.

  • Insert: the new record takes space at the end of the free space, and a new entry is added to the header.
  • Delete: the record's space is freed and its entry is marked as deleted. The records before it are moved so that the free space stays in one piece, and their entries are updated.

Other parts of the database point to the header entry of a record, not to the record itself. So a record can move inside its block without breaking any pointer. Moving records inside one block is cheap, because the whole block is already in memory.

Exam tip

Draw the block as a long box: header on the left (entries and end of free space), free space in the middle, and records packed on the right. Draw an arrow from each header entry to its record.

Try it yourself

Choose a layout. In the fixed-length file, delete records and watch the free list grow; then insert and see which place is reused. In the slotted page, insert and delete records and watch the header entries change.

Things to try
  • In the fixed-length file, delete records 1, 3 and 5, then insert two records.
  • In the slotted page, delete the middle record. Which records move, and which header entries change?
  • Keep inserting until the block is full. Why does the header also need space?

Data dictionary storage

To run any query, the DBMS must know the tables, their columns and their indices. This “data about data” is called metadata.

Definition

The data dictionary (also called the system catalog) is where the DBMS stores metadata about the database.

The data dictionary stores:

  • the names of the relations, and the names, types and lengths of their attributes,
  • views, integrity constraints and indices,
  • users, their roles and their access rights (authorization),
  • statistics, such as the number of tuples in each relation (used by the query optimizer, topic 4.11),
  • physical details, such as how each relation is stored and where.

Most systems store the data dictionary as relations too, so the DBMS can use its own code to read it.

Column-oriented storage

So far, each record is stored with all its fields together. This is row-oriented storage.

Definition

In column-oriented storage (columnar storage), the values of each attribute are stored together, in a separate file or area for each column.

  • Merits (advantages): a query such as “average marks of all students” reads only the Marks column, so it reads far fewer blocks. Values in one column are similar, so they compress well.
  • Demerits (disadvantages): reading or inserting one whole record touches every column, so it is slower.

Column-oriented storage is used for data analytics, business intelligence and data warehouses. Row-oriented storage suits transaction processing, where whole records are read and written.

In real life

Online shopping addresses

One customer lives at “12, Gandhi Road”, and another at a long address with a flat number, street, area and landmark. Storing addresses as variable-length records means short addresses do not waste space.

Sales reports

An online shop asks, “What were the total sales in each state last Diwali?” This reads only the state, date and amount columns of millions of orders. So analytics systems keep such data in column-oriented storage.

Key points

  • Fixed-length records all have the same size n; record i starts at byte n × (i − 1).
  • Deleted fixed-length records are linked in a free list that starts at the file header.
  • Variable-length records store an (offset, length) pair for each variable field, a null bitmap and then the field data.
  • The slotted page has a header with the number of entries, the end of free space and the location and size of each record.
  • In a slotted page, records are packed at the end of the block and may move; pointers point to header entries.
  • The data dictionary (system catalog) stores metadata: schemas, constraints, users, indices and statistics.
  • Column-oriented storage keeps each attribute together; it suits analytics, while row storage suits transactions.
