The parts of a relation

In the relational model, a table is called a relation. The figure names every part of the Student relation.

Each term in detail

Definitions
  • Relation (table): a collection of data items arranged in rows and columns. A relation cannot have two identical rows.
  • Tuple (row, record): a single entry in the table. It holds a set of related data. (2, Bharath, 83, 94430 67890) is one tuple.
  • Attribute (column): one part of every record. Student has four attributes: RollNo, Name, Marks and Phone.
  • Domain: for each attribute, the set of permitted values. The domain of Marks is the whole numbers from 0 to 100.

Relation schema and relation instance

  • A relation schema describes the structure of a relation: its name, its attributes and their types. It is written as Student(RollNo, Name, Marks, Phone).
  • A relation instance is the set of tuples in the relation at one moment. It changes as rows are added, deleted or updated.

The rows of Student with marks above 85 form a smaller set of tuples. That set is also an instance of the same schema.

Atomic domains

A domain is atomic if its values are treated as single units that cannot be divided. Marks (88) is atomic. A Phone attribute that holds two numbers, such as “98400 12345, 94430 11111”, is not atomic, because it can be split into parts. The relational model expects atomic values. This rule is the basis of First Normal Form in Unit II.

NULL values

NULL is a special value that means unknown or does not apply. It is not zero and not a blank space.

Salary table with a NULL
EmpIDNameSalary
E1Divya45000
E2EzhilNULL

Ezhil has just joined and the salary is not fixed yet, so it is unknown. A salary of 0 would mean something different: “works for free”.

Degree and cardinality

  • Degree = the number of attributes (columns). Student has degree 4.
  • Cardinality = the number of tuples (rows). Student has cardinality 3.

The degree is fixed by the schema. The cardinality changes as rows are inserted and deleted.

Worked example: the Staff table

Find the number of columns, the number of tuples, the attributes, the degree and the cardinality of this relation.

Staff

S102JananiFAssistant Professor600002019-07-15
S103KannanMLab Assistant250002021-01-04
Solution
  1. Number of columns = 6.
  2. Number of tuples = 3.
  3. Attributes: StaffID, Name, Sex, Designation, Salary and DOJ (date of joining).
  4. Degree = number of columns = 6.
  5. Cardinality = number of rows = 3.

Properties of a relation

  1. Each relation has a unique name in the database.
  2. Each attribute has a unique name within the relation.
  3. Each cell holds a single, atomic value.
  4. All values in a column come from the same domain.
  5. There are no duplicate tuples: a relation is a set.
  6. The order of tuples does not matter.
  7. The order of attributes does not matter, as long as each value stays with its attribute.

In real life

Exam results sheet

The result sheet on the notice board is a relation. Its column headings are the schema, each student's line is a tuple, and a student who was absent has a NULL mark, not zero.

Train chart

The reservation chart has columns for coach, berth, name and age. Its degree stays the same every day, but its cardinality depends on how many people booked.

Key points

  • Relation = table, tuple = row, attribute = column.
  • A domain is the set of permitted values of an attribute; atomic values cannot be divided.
  • The relation schema is the structure; the relation instance is the set of tuples at one moment.
  • Degree = number of attributes; cardinality = number of tuples.
  • NULL means unknown or not applicable; it is not zero or blank.
  • A relation has no duplicate tuples, and the order of tuples does not matter.
Common mistake

Students often swap degree and cardinality. For the degree, count the column headings. For the cardinality, count the rows.
