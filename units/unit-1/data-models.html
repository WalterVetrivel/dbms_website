What is a data model?

Before building a house, an architect draws a plan with standard symbols for walls, doors and windows. A database designer also needs a standard way to draw the design of a database. That standard way is a data model.

Definition

A data model is a collection of conceptual tools for describing data, relationships among data, the semantics (meaning) of data and consistency constraints.

A data model is the base under a database. It gives a way to describe the design at each of the three levels (see Views of Data).

The textbook puts data models into four main groups. Two older models are also asked in exams.

Relational model

The relational model uses tables to hold both the data and the links between data. A table is also called a relation. Each table has several columns, and each column has a unique name. Each row is one record.

Example

The Student table and the Result table are linked by the common column SeatNo. Student Ram lives in Chennai, and the Result table shows that his marks are 78.

Most databases today use the relational model. Units I and II of this course are mostly about it. Read more in Relational Model.

Merits (advantages)

  • Structural independence: one table can change without changing the others.
  • Conceptual simplicity: the designer thinks about tables, not about disks.
  • Query capability: a simple language, SQL, can ask almost any question.
  • Easy design, maintenance and use.

Demerits (disadvantages)

  • It needs fast machines and large disks.
  • It can be slower than the older models for some fixed tasks.
  • A poor table design leads to a poor database.

Entity-relationship (E-R) model

The E-R model describes the real world as a collection of entities and the relationships among them. An entity is a thing or object in the real world that is different from other objects, such as one employee or one department.

The E-R model is used a lot in database design. The diagram is drawn first. Then it is turned into tables. Unit II covers it in full.

Merits (advantages)

  • Simple: easy to draw once the entities and relationships are known.
  • Easy to read, even for people who do not write code.
  • Effective communication tool between designers and users.
  • Easy conversion into tables of the relational model.

Demerits (disadvantages)

  • Some details, such as the order of steps, can be lost.
  • It can show only a few kinds of relationship.
  • It cannot show how data is changed.
  • There is no single standard set of symbols.

Object-based data model

Languages such as C++, Java and C# are object-oriented. This led to the object-based data model. It extends the relational model with object features: encapsulation, methods (functions) and object identity, plus inheritance.

Object type (sketch) 
type Person   (name, phone)
type Student  under Person (roll_no, cgpa)   -- inherits name and phone
method Student.percentage() returns cgpa * 9.5

Merits (advantages)

  • Rich modeling of real-world objects.
  • Reusability through inheritance and polymorphism.
  • Handles schema change well, because data and code are kept together.
  • Faster for complex objects.

Demerits (disadvantages)

  • There is no single model that all agree on, and its theory is weaker than that of the relational model.
  • It is less used in industry, so it needs skilled programmers.
  • Its many features make the design hard.

Semi-structured data model

In the semi-structured model, data items of the same type may have different sets of attributes. Each item carries its own tags, so there is no fixed schema. XML is widely used for this model, and JSON is now just as common.

XML 
<students>
  <student><roll>101</roll><name>Ram</name><city>Chennai</city></student>
  <student><roll>102</roll><name>Divya</name><hostel>B-112</hostel></student>
</students>

The first student has a city; the second has a hostel room instead. Both are still students.

  • Merits: no fixed schema, so it is flexible and easy to move between systems.
  • Demerit: queries are less efficient than in the relational model.

Hierarchical model

The hierarchical model arranges records in a tree. Each record has one parent, and a parent can have many children. It is like folders on a computer. It was used in the 1960s, for example in IBM's IMS.

  • Merits: simple, and fast for one-to-many data that is always read from the top down.
  • Demerits: it cannot show many-to-many relationships directly. A student in two clubs must be copied under both, which causes redundancy. To reach a child, you must go through its parent.

Network model

The network model arranges records in a graph. A record can have many parents, and records are linked by pointers. This fixes the main limit of the hierarchical model. The CODASYL group defined it in 1971.

  • Merits: it shows many-to-many links directly, and following pointers is fast.
  • Demerits: it is hard to design and change. Programs must follow the pointers step by step. So when the structure changes, the programs must change too.

In real life

Bank core system

Accounts, customers and transactions are tables in a relational database, because every row has the same columns and SQL reports are needed daily.

Online shopping catalog

A phone has a screen size and a battery; a shirt has a size and a fabric. The catalog uses semi-structured JSON, so each product can have its own attributes.

File explorer

The folders on your laptop form a tree, the same shape as the hierarchical model.

Key points

  • A data model is a collection of conceptual tools for describing data, relationships, semantics and constraints.
  • Relational model: data and relationships as tables (relations).
  • E-R model: entities and relationships, drawn as a diagram for design.
  • Object-based model: the relational model plus objects, methods and inheritance.
  • Semi-structured model: items of the same type can have different attributes; XML and JSON.
  • Hierarchical model: a tree, one parent per record; cannot show many-to-many directly.
  • Network model: a graph, many parents per record, linked by pointers.
