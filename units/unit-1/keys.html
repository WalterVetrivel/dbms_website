Keys

A key is how a database tells one row from another. This page builds every kind of key on one Student table, then links two tables with a foreign key. Use the key finder to test your own choices.

Why we need keys

Two students in your college can have the same name. If the office says “Change Priya's marks”, which Priya do they mean? The database needs a value, or a set of values, that is different for every row. That is a key.

Super key

Definition

A super key is a set of one or more attributes that, taken together, identify each tuple in the relation uniquely.

  • {RegNo} is a super key. No two students share a register number.
  • {RegNo, Name} is also a super key. Adding Name to RegNo does not stop it from being unique.
  • {RollNo, Dept} is a super key. Roll number 1 appears twice, but only once in each department.
  • {Name} is not a super key. Rows 1 and 3 are both “Priya”.
  • {Dept, Name} is not a super key. Rows 2 and 5 are both “CSE, Arun”.

Any set that contains a super key is also a super key. So a relation usually has many super keys, and the set of all attributes is always one.

Candidate key

Definition

A candidate key is a minimal super key: a super key from which no attribute can be removed without losing uniqueness.

Student has three candidate keys:

  1. {RegNo}
  2. {Email}
  3. {RollNo, Dept}: remove either attribute and it is no longer unique.

{RegNo, Name} is a super key but not a candidate key, because Name can be removed and RegNo alone is still unique.

Note

Every candidate key is a super key, but not every super key is a candidate key.

Primary key and alternate key

Definitions
  • Primary key: the candidate key chosen by the database designer as the main way to identify tuples in the relation.
  • Alternate key: a candidate key that was not chosen as the primary key.

The designer chooses RegNo as the primary key of Student. So {Email} and {RollNo, Dept} are alternate keys.

Rules for a primary key

  1. A relation has only one primary key.
  2. A primary key may have one attribute or several.
  3. Its value must be unique for every tuple.
  4. Its value can never be NULL (the entity integrity rule, see Constraints, topic 1.8).

How to choose a good primary key

  • Pick a value that never changes. A student may change their email, but not their register number.
  • Pick a short key. It is copied into every table that refers to it.
  • Prefer one attribute to several when you can.
SQL 
CREATE TABLE student (
  reg_no   CHAR(10)    PRIMARY KEY,         -- primary key
  roll_no  INT         NOT NULL,
  dept     VARCHAR(5)  NOT NULL,
  name     VARCHAR(30) NOT NULL,
  email    VARCHAR(40) NOT NULL UNIQUE,     -- alternate key
  UNIQUE (roll_no, dept)                    -- alternate key (composite)
);

In SQL, the primary key is declared with PRIMARY KEY, and each alternate key with UNIQUE.

Composite key

Definition

A composite key is a key made of two or more attributes. No single one of them is unique on its own, but together they are.

{RollNo, Dept} is a composite key. Another common example is a Marks table, where one student has marks in many courses:

Foreign key

Definition

A foreign key is an attribute, or a set of attributes, in one relation that refers to the primary key of another relation.

The table that holds the foreign key is the child (referencing) table. The table it refers to is the parent (referenced) table.

In the Marks table above, RegNo is a foreign key that refers to Student, and CourseID is a foreign key that refers to Course. Every CourseID in Marks must already exist in Course. You cannot enter marks for a course “CS999” that does not exist.

SQL 
CREATE TABLE course (
  course_id CHAR(5) PRIMARY KEY,
  title     VARCHAR(40)
);

CREATE TABLE marks (
  reg_no    CHAR(10),
  course_id CHAR(5),
  marks     INT,
  PRIMARY KEY (reg_no, course_id),
  FOREIGN KEY (reg_no)    REFERENCES student (reg_no),
  FOREIGN KEY (course_id) REFERENCES course (course_id)
);

Notice that RegNo is part of the primary key of Marks and a foreign key. A foreign key can repeat and, unless declared NOT NULL, can be NULL.

How the keys fit together

  • Candidate keys = the minimal super keys.
  • Primary key = the one candidate key the designer chooses.
  • Alternate keys = candidate keys − primary key.
Common mistake

Some notes write “candidate key = super key − primary key”. That is not right. Removing the primary key from the super keys leaves many non-minimal sets. The correct line is alternate keys = candidate keys − primary key. Also, a primary key such as (RollNo, Name) is not allowed if RollNo alone is unique, because a primary key must be a minimal key.

Things to try
  • Tick RollNo and Name. Which two rows clash?
  • Tick RollNo, Dept and Name. Why is this a super key but not a candidate key?

Keys come from the rules of the real world, not from one instance of the table. A set can look unique in a small table and still fail when a new student joins. If only rows 1, 2 and 4 existed, {Name} would look unique. But two students can have the same name, so Name is never a key. A key must stay unique for every row the college could ever add.

In real life

Aadhaar and PAN

A bank can identify a customer by Aadhaar number, PAN or account number. All three are candidate keys. The bank picks the account number as its primary key.

Train ticket

The PNR identifies one booking. Within it, a passenger is identified by (PNR, passenger number): a composite key.

Online order

An order row stores the customer ID, a foreign key that refers to the Customer table. The site cannot accept an order for a customer who does not exist.

Key points

  • Super key: one or more attributes that identify each tuple uniquely.
  • Candidate key: a minimal super key.
  • Primary key: the candidate key chosen by the designer; unique and never NULL; only one per relation.
  • Alternate key: a candidate key that is not the primary key.
  • Composite key: a key with two or more attributes.
  • Foreign key: attributes in a child table that refer to the primary key of a parent table.
  • Every candidate key is a super key; not every super key is a candidate key.
