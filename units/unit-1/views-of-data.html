Views of Data

Data abstraction

When you book a train ticket, you see trains, seats and fares. You do not see the files, blocks or indexes inside the railway's computers. The system hides those details from you.

Definition

Data abstraction means showing users only the data they need and hiding the details of how the data is stored and maintained.

A main purpose of a database system is to give users an abstract view of the data. Many users are not computer experts, so the system hides the complex parts at several levels. This is called the view of data.

Physical level

This is the lowest level. It describes how the records are stored, for example, as blocks of bytes in a file on disk. Most database systems hide these details from programmers.

Logical level

This level describes the whole database using a small number of simple structures, such as tables. The programmer works at this level. The database administrator also uses it to decide what information to keep. Using a simple structure at the logical level may need complex structures at the physical level, but the user does not need to know that.

View level

This is the highest level. Many users need only part of the database. A view gives each user just that part, which makes the system simpler to use. The system can give many views of the same database. A view also adds security, because a user cannot see data outside their view.

Example from the notes

A record type employee has four fields: emp_id, emp_name, dept_no and salary.

  • Physical level: each employee record is a block of storage locations in a row.
  • Logical level: the record type and its four fields with their data types are defined here.
  • View level: a clerk may see the employee's name and id, but not the salary.

Instances and schemas

In a program, you declare a variable once (int marks;), and its value changes many times. The declaration is like a schema. The value at one moment is like an instance.

Definitions
  • Schema: the overall design of the database. It changes rarely.
  • Instance: the collection of information stored in the database at a particular moment. It changes every time data is inserted, deleted or updated.

Types of schema

There is one schema for each level of abstraction:

  • Physical schema: the database design at the physical level.
  • Logical schema: the database design at the logical level. It is the most important one, because programs are written using it.
  • Subschema: a schema at the view level. A database can have several subschemas, one for each view.

Data independence

Each level is connected to the level below it by a mapping. When one level changes, the DBMS changes the mapping, so the level above it does not have to change. This is called data independence.

Definition

Data independence is the ability to change the schema at one level without having to change the schema at the next higher level.

Exam tip

“Physical changes do not reach the logical level; logical changes do not reach the views.” Write this line, then give one example change for each.

Try it: the three levels

Pick a level to see the same student data at that level. Then apply a change and watch which level changes, which mapping is updated and which levels stay the same.

Things to try
  • Apply “Move the data to an SSD”. Which two levels stay unchanged?
  • Apply “Split student into student and hostel_allotment”, then open the view level. Does the warden still see the room?

In real life

UPI app

You see your balance and your last few payments. That is your view. The bank's logical schema has accounts, customers and transactions. The physical level is spread over many servers you never see.

College portal upgrade

The college moves its database to a new server with faster disks. Students log in the next day and see the same pages. That is physical data independence.

Key points

  • Data abstraction hides how data is stored and shows users only what they need.
  • Physical level: how data is stored. Logical level: what data is stored and how it is related. View level: part of the database for one user group.
  • There is one physical schema and one logical schema, but there can be many views (subschemas).
  • Schema: the overall design, which rarely changes. Instance: the data at one moment, which changes often.
  • Physical data independence: change storage without changing the logical schema.
  • Logical data independence: change the logical schema without changing views or programs.
  • Logical data independence is harder to achieve than physical data independence.
Common mistake

Do not say the view level shows “the whole database in a simple way”. That is the logical level. The view level shows only part of the database.
