Introduction to Relational Databases

A relational database keeps all its data in tables. This page shows how tables hold data, how a third table links two others, and which software products are relational databases.

What is a relational database?

Look at the attendance register in your class. It has one row for each student and one column for each day. A relational database stores all its data in tables like this.

Definition

A relational database is a collection of tables, each with a unique name. Each table is made of rows and columns, and tables are linked to each other by common values.

The idea came from E. F. Codd at IBM in 1970. He called a table a relation, which is why these databases are called relational. A program that manages a relational database is a relational database management system (RDBMS).

Tables, rows and columns

The Student table below has three column headers: RollNo, Name and Phone. Each row holds the details of one student.

Student
RollNoNamePhone
001Anitha98400 12345
002Bharath94430 67890
003Charan90030 24680
  • A column holds one kind of value for every row. All values in the Phone column are phone numbers.
  • A row holds all the values for one item. The second row tells us that student 002 is Bharath, and gives his phone number.
  • The order of rows does not matter. The table means the same thing if the rows are shuffled.

Linking tables

Which student joined which course? We could add the course name to the Student table, but then the course details would be copied again and again. Instead, a third table links the two using their common values.

Admission
RollNoCourseID
001102
002101
003102

To find Anitha's course, read her RollNo (001) in Student, find 001 in Admission (course 102), then find 102 in Course: Computer Science. No pointers are needed. The tables are linked only by matching values.

Note

The column that identifies each row (RollNo in Student) is a primary key. A column that refers to another table's key (RollNo and CourseID in Admission) is a foreign key. See Keys.

Why relational databases are popular

  • Simple: everything is a table, which anyone can read.
  • Flexible queries: SQL can combine any tables that share values, without new programs.
  • Data independence: the way tables are stored on disk can change without changing the queries.
  • Strong theory: relational algebra gives a precise meaning to every query (see Relational Algebra).
  • Integrity: keys and constraints keep the data correct.

In real life

College admission

Counselling software keeps Students, Colleges and Allotments as three tables, exactly like Student, Course and Admission above.

Mobile phone contacts

Your phone stores contacts in an SQLite table: one row per contact, with columns for name, number and email.

Key points

  • A relational database is a collection of tables, each with a unique name.
  • A table has rows (one per item) and columns (one per property).
  • The order of rows does not matter.
  • Tables are linked by common values, not by pointers.
  • E. F. Codd proposed the relational model in 1970.
  • MySQL, Oracle, SQL Server, PostgreSQL, Db2 and SQLite are relational database products; all use SQL.
