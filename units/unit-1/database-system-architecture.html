The overall structure

A database system is divided into parts, and each part has one job. The two main parts are the query processor and the storage manager. At the top are the users and the tools they use. At the bottom is the disk storage.

Database users and the DBA

Types of database users
UserWho they areHow they use the system
Naive usersBank clerks, ticket counter staff, people shopping onlineThrough ready-made application interfaces, such as forms
Application programmersSoftware developersWrite application programs that contain SQL
Sophisticated usersAnalysts and engineersWrite their own queries in query tools
Database administrator (DBA)The person in central control of the data and programsUses administration tools

Duties of the DBA

  • Schema definition: creates the database schema by running DDL statements.
  • Storage structure and access method: decides how data is stored and which indexes to build.
  • Schema and physical changes: changes the design as needs change.
  • Granting authorization: decides which user may access which data.
  • Routine maintenance: takes backups, watches free disk space and speeds up slow queries.

Query processor

The query processor understands the user's statements and works out how to run them. It has three parts.

  1. DDL interpreter: reads DDL statements and records the definitions in the data dictionary.
  2. DML compiler (and organizer): translates DML statements into an evaluation plan of low-level instructions that the query evaluation engine understands. A query can be run in many ways that give the same result. The DML compiler also does query optimization: it picks the plan with the lowest cost.
  3. Query evaluation engine: runs the low-level instructions made by the DML compiler.
Note

An evaluation plan is like a route on a map app. Many routes reach the same place. The optimizer picks the fastest one, using facts about the data, such as how many rows each table has. See Query Processing Overview in Unit IV for the full story.

Storage manager

The storage manager sits between the data on disk and the programs and queries sent to the system. Its job is storing, retrieving and updating data. It has four parts.

  1. Authorization and integrity manager: checks that the user has the right to access the data, and tests the integrity constraints.
  2. Transaction manager: keeps the database consistent even if the system fails, and makes sure that transactions running at the same time do not conflict.
  3. File manager: gives out space on disk and looks after the structures that hold the data on disk.
  4. Buffer manager: fetches data from disk into main memory and decides what to keep in memory. It lets the database handle data much larger than main memory, so it is a critical part.

Disk storage

The storage manager keeps these data structures on disk:

  • Data files: store the database itself.
  • Data dictionary: stores metadata (data about data), such as the schema of each table, its constraints and the users' rights.
  • Indices: give fast access to data items, like the index at the back of a book.
  • Statistical data: facts such as the number of rows in each table. The optimizer uses them to choose a plan.

Two-tier and three-tier architecture

The database usually runs on a server, and users work on their own machines. There are two common ways to connect them.

Two-tier and three-tier compared
PointTwo-tierThree-tier
Where the business logic runsOn the clientOn the application server
Client talks toThe database, using SQL (for example, through JDBC)The application server only
SecurityLower, because every client reaches the databaseHigher, because only the server reaches the database
SuitsSmall groups, such as one officeLarge web applications with many users
ExampleA billing program in a shop that connects to a database on the shop's serverAn online shopping website

In real life

IRCTC booking

Your phone app (client) talks to IRCTC's servers (application server), which talk to the database. This is three-tier. Passengers are naive users.

College lab

In the lab, you type SQL in MySQL Workbench. You are a sophisticated user, and Workbench is a query tool.

Key points

  • The two main parts are the query processor and the storage manager.
  • Query processor: DDL interpreter, DML compiler (with query optimization) and query evaluation engine.
  • Storage manager: authorization and integrity manager, transaction manager, file manager and buffer manager.
  • Disk storage: data files, data dictionary (metadata), indices and statistical data.
  • Users: naive users, application programmers, sophisticated users and the DBA.
  • The DBA defines the schema, plans storage, grants access and does routine maintenance.
  • Two-tier: the client talks to the database. Three-tier: the client talks to an application server, which talks to the database.
Common mistake

The DDL interpreter writes to the data dictionary, not to the data files. A CREATE TABLE stores the table's definition, not its rows.
