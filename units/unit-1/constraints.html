Constraints

Constraints are rules that the database checks on every change, so wrong data never gets in. This page explains each kind of constraint, shows how to write it in SQL, and shows what the DBMS does when a rule is broken.

What is an integrity constraint?

Marks must be between 0 and 100. Every student must have a register number. You cannot enter marks for a course that does not exist. These are rules about the data. If we write them in the database, the DBMS checks them on every insert, update and delete.

Definition

An integrity constraint is a rule that the data in a database must satisfy. It keeps the data correct and consistent. Database integrity means the data is accurate.

If a change breaks a constraint, the DBMS rejects the change with an error. The data stays correct.

Domain constraint

A domain is the set of values allowed for an attribute. The domain of a date is all valid dates. The domain of day-of-week is Monday to Sunday. A domain constraint says that every value of the attribute must be in its domain.

The simplest domain constraint is the data type. A column of type INT cannot hold “abc”. A CHECK clause narrows the domain further:

MySQL 
CREATE TABLE marks (
  reg_no    CHAR(10),
  course_id CHAR(5),
  marks     INT CHECK (marks BETWEEN 0 AND 100)
);

Standard SQL also lets you name a domain once and reuse it. This works in PostgreSQL, but not in MySQL:

Standard SQL (PostgreSQL) 
CREATE DOMAIN id_value INT
  CONSTRAINT id_test CHECK (VALUE > 100);

CREATE TABLE student (
  stu_id   id_value PRIMARY KEY,
  stu_name CHAR(30),
  stu_age  INT
);

Key constraint

A key constraint says that a certain minimal set of attributes identifies each tuple. It has two parts:

  1. No two different tuples may have the same values in all the attributes of the key.
  2. No smaller part of the key is enough to identify a tuple.

In SQL, the primary key is declared with PRIMARY KEY. Other candidate keys are declared with UNIQUE. A table can have only one primary key, but many UNIQUE constraints.

MySQL 
CREATE TABLE student (
  roll_no INT,
  name    CHAR(20),
  age     INT,
  UNIQUE (name, age),
  CONSTRAINT student_key PRIMARY KEY (roll_no)
);

Here roll_no is the primary key, and the pair (name, age) is also a key. Read more in Keys.

NOT NULL, UNIQUE, CHECK and DEFAULT

Column constraints
ConstraintMeaningExample
NOT NULLThe column must always have a value. By default, a column may hold NULL.name VARCHAR(20) NOT NULL
UNIQUENo two rows may have the same value. NULL is allowed, and many rows may be NULL.email VARCHAR(40) UNIQUE
CHECKEvery value must make the condition true (or unknown, for NULL).CHECK (price > 0)
DEFAULTThe value used when an INSERT gives none. Not a check, but often listed with them.city VARCHAR(20) DEFAULT 'Salem'
MySQL 
CREATE TABLE employee (
  emp_id      INT           NOT NULL,
  name        VARCHAR(20)   NOT NULL,
  designation VARCHAR(20)   NOT NULL,
  salary      DECIMAL(12,2) CHECK (salary > 0),
  city        VARCHAR(20)   DEFAULT 'Salem',
  PRIMARY KEY (emp_id)
);

-- add a constraint to a table that already exists
ALTER TABLE employee ADD CONSTRAINT uq_name UNIQUE (name);
Note

MySQL checks CHECK constraints from version 8.0.16 onwards. Older versions read them but ignored them.

Entity integrity rule

Definition

The entity integrity rule states that no attribute of a primary key can be NULL.

Why: the primary key is how we find a row. To read, change or delete a row, we must know its key. If the key were NULL (unknown), the row could not be identified, and two such rows could not be told apart.

MySQL 
INSERT INTO student (roll_no, name, age) VALUES (NULL, 'Kavin', 19);
-- ERROR 1048 (23000): Column 'roll_no' cannot be null

Referential integrity rule

Definition

The referential integrity rule states that every value of a foreign key must match an existing primary key value in the referenced (parent) table, or be NULL.

Take two tables: Customer (parent) and Orders (child). CustID in Orders is a foreign key that refers to CustID in Customer.

The rule stops three kinds of wrong change:

  1. Insert into the child: an order for customer C9 is rejected, because C9 is not in Customer.
  2. Delete from the parent: deleting customer C1 would leave orders 501 and 503 pointing to nobody.
  3. Update the parent key: changing C1 to C7 in Customer would also leave those orders pointing to nobody.

For the second and third cases, the designer chooses what the DBMS should do:

Referential actions
ActionWhat happens when the parent row is deleted (or its key changed)
RESTRICT / NO ACTIONThe change is rejected while child rows exist. This is the default.
CASCADEThe child rows are deleted too (or their foreign key is changed to the new value).
SET NULLThe foreign key in the child rows is set to NULL.
MySQL 
CREATE TABLE customer (
  cust_id CHAR(3) PRIMARY KEY,
  name    VARCHAR(30)
);

CREATE TABLE orders (
  order_id INT PRIMARY KEY,
  cust_id  CHAR(3),
  amount   DECIMAL(10,2),
  FOREIGN KEY (cust_id) REFERENCES customer (cust_id)
    ON DELETE CASCADE
    ON UPDATE CASCADE
);

Merits of referential integrity

  • No row in one table points to a missing row in another table.
  • Linked tables always agree with each other.
  • A parent row that is still in use cannot be deleted by mistake.
  • A child row cannot be added unless its parent exists.
Exam tip

For “entity integrity and referential integrity”, give each rule in one line, say why it matters, and show one rejected change for each. A foreign key is the tool; referential integrity is the rule the tool enforces.

In real life

College admission form

The form will not submit without a name (NOT NULL), rejects a cut-off mark above 200 (CHECK), and refuses an email already used (UNIQUE).

Online shopping

You cannot place an order for a product ID that does not exist. If the shop removes a product, old orders keep it, so the shop uses RESTRICT, not CASCADE.

Key points

  • An integrity constraint is a rule the data must satisfy; the DBMS rejects changes that break it.
  • Domain constraint: values must come from the attribute's domain (data type, CHECK).
  • Key constraint: no two tuples share a key value (PRIMARY KEY, UNIQUE).
  • NOT NULL forces a value; UNIQUE forbids repeats; CHECK tests a condition; DEFAULT fills a missing value.
  • Entity integrity: a primary key can never be NULL.
  • Referential integrity: a foreign key must match an existing primary key, or be NULL.
  • ON DELETE and ON UPDATE choose RESTRICT, CASCADE or SET NULL for the child rows.
Common mistake

Referential integrity does not always delete the child rows. That happens only with ON DELETE CASCADE. By default, the DBMS refuses to delete a parent row that still has children.
