Purpose of Database System

Before database systems, data was kept in many files, with a separate program for each task. This page shows what went wrong with that approach, and how a database management system (DBMS) solves each problem.

What is a DBMS?

Think of your college office. It keeps the details of every student: name, department, marks, fees paid and hostel room. This is a large amount of related data. The office also needs programs to add a new student, change marks and print a mark sheet.

Definitions
  • Database: a collection of related data, stored so that it can be used by many people and programs.
  • Database management system (DBMS): a collection of interrelated data and a set of programs to access that data.

The main goal of a DBMS is to store and retrieve information in a way that is both convenient and efficient. To manage data, a DBMS does two jobs:

  1. It defines the structure for storing the information.
  2. It gives a way to manipulate the information (add, change, delete and look up data).

It must also keep the stored information safe, even when the system crashes or someone tries to get in without permission.

Common DBMS products are MySQL, Oracle, Microsoft SQL Server, PostgreSQL and IBM Db2.

The file-processing system

Early systems stored data in ordinary operating system files. Each time the organization needed a new task, a programmer wrote a new application program for it. One program adds a student, another updates marks, another prints hall tickets.

Definition

A file-processing system stores permanent records in many files and needs a different application program to add, change or extract records in each file.

Over time, the college has more and more files and more and more programs. Different programmers write them at different times, in different formats. For example, the office keeps students.txt, while the hostel keeps its own hostel.csv with the student's name and address again.

Example

The same student, Priya, appears in two files. She changes her phone number at the office, but no one tells the hostel.

Disadvantages of the file-processing system

The file-processing system has eight main problems. Learn them in this order. They are the most asked part of this topic.

  1. Data redundancy: the same data is stored in many places. Priya's name and phone are in both the office file and the hostel file. This wastes storage.
  2. Data inconsistency: copies of the same data no longer match. Priya's phone was changed in one file but not in the other. Redundancy leads to inconsistency.
  3. Difficulty in accessing data: to answer a new question, such as “list all students from Salem with more than 80% marks”, someone must write a new program. There is no easy way to ask.
  4. Data isolation: data is spread over many files in different formats. It is hard to write a new program that brings it together.
  5. Integrity problems: data values must follow rules, such as “marks must be between 0 and 100”. These rules are buried inside program code. When a rule changes, every program must be changed.
  6. Atomicity problems: an operation must happen completely or not at all. If the power fails in the middle of a fee transfer, the money may leave one account without reaching the other. Files cannot easily undo this.
  7. Concurrent-access anomalies: when two users change the same data at the same time, one change can overwrite the other. For example, two clerks book the last hostel room at the same moment.
  8. Security problems: not every user should see all the data. A hostel warden should not see salary details. Programs are added one by one, so it is hard to enforce such rules.
Memory aid

Group the eight problems into three sets. Copies: redundancy and inconsistency. Getting data out: difficulty in access and isolation. Protecting data: integrity, atomicity, concurrent access and security.

A database system solves each of these problems. The table compares the two, point by point.

Characteristics of database systems

  • It models one part of the real world, such as a college or a bank.
  • It keeps information in a planned, orderly way.
  • It shows the data to different users in different views. The office sees marks; the hostel sees rooms.
  • It makes it easy and fast to add, delete and change data.
  • It keeps data for a specific purpose.
  • It stores the links between records, for example, which student takes which course.

Merits and demerits (advantages and disadvantages)

Merits (advantages)

  1. Controls data redundancy: data is stored once, so there is little duplication.
  2. Easy to get data: users get the data they want, in the form they want.
  3. Data is organized: data is kept in separate tables that can be joined when needed.
  4. Simple query language: SQL lets users ask new questions without writing a new program.
  5. Integrity is maintained: constraints such as “marks between 0 and 100” are checked on every change.
  6. Atomicity is maintained: a transaction either completes fully or leaves no trace.
  7. Concurrent access: many users can work at the same time without spoiling each other's work.
  8. Security: each user can see only the part of the database they are allowed to see.

Demerits (disadvantages)

  1. Complex design: designing a database is difficult and takes time.
  2. Hardware and software cost: a DBMS needs powerful machines and costly licenses.
  3. Damage spreads: if one central part of the database is damaged, the whole database can be affected.
  4. Conversion cost: moving from files to a database needs new tools and a lot of work.
  5. Training: people must be trained to design and maintain the database.
Exam tip

For a 16-mark answer, start with the definition and list the uses. Then explain the eight file-system problems, with one small example each. End with the comparison table. If the question also asks for views of data, go on to Views of Data (topic 1.2).

In real life

Railway reservation

Thousands of people book Tatkal tickets at 10 a.m. The database lets them all search at once, but sells each berth to only one person. A file system could not do this safely.

Aadhaar-linked services

A bank, a gas agency and a mobile company each check your details. They ask one central system instead of keeping their own copies, which avoids redundancy and inconsistency.

EB bill

The electricity board stores each meter reading once. The bill, the payment receipt and the monthly report all read the same data, so they always agree.

Key points

  • A DBMS is a collection of interrelated data and a set of programs to access that data.
  • Its goal is to store and retrieve information conveniently and efficiently, and keep it safe.
  • A file-processing system keeps data in separate files with a separate program for each task.
  • The eight file-system problems: redundancy, inconsistency, difficulty in access, isolation, integrity, atomicity, concurrent access and security.
  • Redundancy (duplicate copies) leads to inconsistency (copies that disagree).
  • A DBMS controls redundancy, enforces constraints, supports transactions and limits access.
  • Demerits of a DBMS: complex design, cost, damage that spreads, conversion cost and training.
Common mistake

A DBMS does not remove redundancy completely. It controls it. Some copies, such as a foreign key or a backup, are kept on purpose.
