Relational Algebra

Relational algebra is a small set of operations that take relations as input and give a relation as output. SQL is built on it. This page explains every operation with small tables, and the playground lets you run each one.

What is relational algebra?

In school algebra, operators such as + and × take numbers and give a number. In relational algebra, operators take relations (tables) and give a relation. So the output of one operation can be the input of the next.

Definition

Relational algebra is a procedural query language. It consists of a set of operations that take one or two relations as input and produce a new relation as their result.

  • Procedural means the query says the steps, in order, to compute the answer. (SQL is declarative: it says what you want, and the DBMS decides the steps.)
  • A sequence of operations forms a relational algebra expression. Its result is also a relation.
  • The query processor turns every SQL query into a relational algebra expression before running it.

Select (σ)

Select picks the tuples (rows) that satisfy a condition, called the predicate. It keeps all the attributes.

Syntax 
σ predicate (relation)

Query: find the students older than 18.

Relational algebra 
σ age > 18 (Student)
Result
sidsnameagecity
1Anitha19Salem
2Bharath21Chennai
4Divya20Erode

The predicate can use =, ≠, <, ≤, > and ≥, joined by ∧ (and), ∨ (or) and ¬ (not). For example, σ age > 18 ∧ city = 'Salem' (Student) gives only Anitha.

Project (π)

Project picks the attributes (columns) you list and drops the rest. Because a relation is a set, any duplicate tuples are removed.

Syntax 
π A1, A2, ..., An (relation)

Query: list the cities of the students.

Relational algebra 
π city (Student)
Result: Salem appears once, not twice

Combining σ and π: the names of students from Salem are π sname (σ city = 'Salem' (Student)) = {Anitha, Charan}. The inner operation runs first.

Union, intersection and set difference

These work like the set operations in mathematics. The two relations must be union compatible:

  1. They have the same number of attributes.
  2. The domains of matching attributes are the same.

Union and intersection give the same result in either order. Set difference does not: F − P ≠ P − F. Intersection is not fundamental, because r ∩ s = r − (r − s).

With different relations, project first to make them compatible: π sname (Student) ∪ π bname (Book) lists every student name and every book name in one column.

Cartesian product (×)

The Cartesian product r × s pairs every tuple of r with every tuple of s. If r has n1 tuples and s has n2, the result has n1 × n2 tuples. Student × Reserve has 4 × 3 = 12 tuples.

Most of those pairs are meaningless, because they join a student to another student's reservation. So a product is nearly always followed by a select.

Query: find the names of students who reserved the book with isbn 005.

Relational algebra 
π sname (σ Student.sid = Reserve.sid ∧ Reserve.isbn = '005' (Student × Reserve))

Result: Anitha. When both relations have an attribute with the same name (sid), we write the relation name in front: Student.sid and Reserve.sid.

Rename (ρ)

The results of relational algebra expressions have no name. Rename gives a name to a relation (and, if needed, to its attributes).

Syntax 
ρ x (E)                 -- the result of E is named x
ρ x(A1, A2, ..., An) (E)  -- also renames the attributes

Example: ρ Student_names (π sid, sname (Student)) creates a relation called Student_names with the attributes sid and sname.

Rename is needed when a relation is joined with itself. To find students older than Anitha, we need two copies of Student with different names:

Relational algebra 
π S.sname (σ S.age > A.age ∧ A.sname = 'Anitha' (ρ S (Student) × ρ A (Student)))

Result: Bharath and Divya.

Joins: theta join, equijoin and natural join

A join combines related tuples from two relations into single tuples. It is a Cartesian product followed by a selection, written as one operation.

Theta join

The theta join uses any condition θ, built with =, ≠, <, ≤, > or ≥:

Definition 
r ⋈θ s = σθ (r × s)

Equijoin

An equijoin is a theta join whose condition uses only =. Student ⋈ Student.sid = Reserve.sid Reserve is an equijoin. The result keeps both sid columns.

Natural join

The natural join r ⋈ s needs no condition. It matches tuples that have equal values in all the attributes with the same name, and keeps each common attribute only once.

Query: list the reserved books with their names.

Relational algebra 
Reserve ⋈ Book
Result of Reserve ⋈ Book (isbn appears once)
sidisbnbname

Book 009 (Python) is reserved by no one, so it does not appear. Those three joins are all inner joins: unmatched tuples are dropped.

Query: find the names of students who reserved the book “DBMS”: π sname (σ bname = 'DBMS' (Student ⋈ Reserve ⋈ Book)) = {Anitha}.

Division (÷)

Division answers questions with the words “for all” or “every”. If r has attributes (x, y) and s has attribute (y), then r ÷ s gives the x values that appear in r with every y value in s.

Query: find the customers who have an account in all branches.

Account ÷ Branch = {Asha}. Babu has no account in Erode, and Chitra has none in Salem.

Division can be written with fundamental operations: r ÷ s = π x (r) − π x ((π x (r) × s) − r). The inner part finds the (customer, branch) pairs that are missing; subtracting their customers leaves those with nothing missing.

Assignment (←)

Assignment stores the result of an expression in a temporary relation variable, so a long query can be written in steps:

Relational algebra 
temp1 ← σ city = 'Salem' (Student)
temp2 ← temp1 ⋈ Reserve
result ← π sname (temp2)

The result is {Anitha}: the only student from Salem with a reservation.

In real life

Shopping filters

On a shopping site, “price below ₹500” is a select, showing only name and price is a project, and showing each product with its seller is a join.

Scholarship list

“Students who passed every subject” is a division: students ÷ subjects, using the pass records.

Key points

  • Relational algebra is a procedural query language; each operation takes relations and gives a relation.
  • Fundamental operations: select σ, project π, union ∪, set difference −, Cartesian product × and rename ρ.
  • σ picks rows by a predicate; π picks columns and removes duplicates.
  • Union, intersection and difference need union-compatible relations; r − s ≠ s − r.
  • Theta join = σθ(r × s); an equijoin uses only =; a natural join matches common attributes and keeps them once.
  • Outer joins keep unmatched tuples and fill the gaps with NULL (left ⟕, right ⟖, full ⟗).
  • Division (÷) answers “for all” queries; assignment (←) stores a partial result.
Common mistake

Do not mix up σ and π. σ selects rows; π projects columns. Note that the SQL keyword SELECT does the job of π, not σ. The WHERE clause does the job of σ.
