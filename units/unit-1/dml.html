DML

DML commands work on the rows inside the tables: they add, change, remove and read data. This page runs each command on one small table and shows the table before and after.

What is DML?

Definition

DML (Data Manipulation Language) is the part of SQL used to insert, change, delete and retrieve the data stored in tables.

The four DML commands
CommandWhat it does
INSERTAdds new rows.
UPDATEChanges values in existing rows.
DELETERemoves rows.
SELECTReads rows (a query).

The textbook names two kinds of DML:

  • Procedural DML: the user says what data is needed and how to get it, step by step. Relational algebra is procedural.
  • Declarative (non-procedural) DML: the user says only what data is needed. SQL is declarative.

The part of DML that reads data is called the query language.

The sample table

Every example on this page uses this small person table, a shorter form of the person_details table from the DDL page.

MySQL 
CREATE TABLE person (
  aadhaar_no INT PRIMARY KEY,
  first_name VARCHAR(20) NOT NULL,
  city       VARCHAR(20),
  age        INT
);

The table starts empty. We fill it in the next section.

INSERT

Syntax 
INSERT INTO table_name (col1, col2, ...)
VALUES (value1, value2, ...);

One row, all columns

If you give a value for every column in table order, the column list can be left out.

MySQL 
INSERT INTO person VALUES (111, 'Anitha', 'Salem', 20);

One row, some columns

Columns you leave out get their default value, or NULL if there is no default.

MySQL 
INSERT INTO person (aadhaar_no, first_name, city) VALUES (222, 'Bala', 'Erode');

Many rows at once

MySQL 
INSERT INTO person (aadhaar_no, first_name, city, age) VALUES
  (333, 'Charan', 'Salem',   21),
  (444, 'Divya',  'Chennai', 19),
  (555, 'Ezhil',  'Erode',   22);

Rows that break a rule

The DBMS checks every constraint before it adds a row. Both of these are rejected and the table does not change:

MySQL 
INSERT INTO person VALUES (111, 'Farhan', 'Salem', 23);   -- ERROR: duplicate primary key 111
INSERT INTO person (aadhaar_no, city) VALUES (666, 'Salem'); -- ERROR: first_name cannot be NULL

Copy rows from a query

INSERT ... SELECT adds the result of a query to another table with matching columns.

MySQL 
CREATE TABLE salem_person (aadhaar_no INT, first_name VARCHAR(20));
INSERT INTO salem_person
  SELECT aadhaar_no, first_name FROM person WHERE city = 'Salem';   -- adds 2 rows

UPDATE

Syntax 
UPDATE table_name
SET col1 = value1, col2 = value2, ...
WHERE condition;

UPDATE changes only the rows that match WHERE. Every other row stays the same.

MySQL 
UPDATE person SET city = 'Chennai' WHERE aadhaar_no = 333;
UPDATE person SET age = 20 WHERE aadhaar_no = 222;
UPDATE person SET age = age + 1 WHERE city = 'Erode';

The last statement uses the old value of a column to work out the new one. It adds one year to both people from Erode.

Watch out

An UPDATE without WHERE changes every row. UPDATE person SET city = 'Salem'; moves everyone to Salem. The notes also drop the equals sign (SET city 'Chennai'); SQL needs SET city = 'Chennai'.

DELETE

Syntax 
DELETE FROM table_name WHERE condition;
MySQL 
DELETE FROM person WHERE aadhaar_no = 444;

DELETE FROM person; with no WHERE removes every row but keeps the empty table. For a big table, TRUNCATE does the same job faster; see DROP, TRUNCATE and DELETE.

If another table has a foreign key that points to a row, the DBMS refuses to delete that row unless the key says ON DELETE CASCADE or ON DELETE SET NULL (see Constraints).

SELECT

SELECT reads rows and never changes the table. Its full structure is on the Basic Structure of SQL Queries page. Here are the common forms on the person table:

MySQL 
SELECT * FROM person;                                     -- all rows, all columns
SELECT first_name, city FROM person WHERE age > 20;       -- Bala, Charan, Ezhil
SELECT DISTINCT city FROM person;                         -- Salem, Erode, Chennai
SELECT first_name FROM person ORDER BY age DESC, first_name;  -- Ezhil, Bala, Charan, Anitha

Bala and Charan are both 21, so the second sort column, first_name, puts Bala first.

Undoing DML with ROLLBACK

Unlike DDL, DML changes can be undone until they are committed. In MySQL, start a transaction first, because each statement is committed on its own by default.

MySQL 
START TRANSACTION;
DELETE FROM person;              -- oops, no WHERE
SELECT COUNT(*) FROM person;     -- 0
ROLLBACK;
SELECT COUNT(*) FROM person;     -- 4: every row is back

COMMIT makes the changes permanent. Transactions are covered in Unit III: SQL DCL and TCL Commands.

Worked example: DDL and DML together

This script builds a student table and uses all six commands a long answer asks for: CREATE, ALTER, INSERT, UPDATE, DELETE and SELECT.

MySQL 
-- DDL: define the structure
CREATE TABLE student (
  roll_no INT PRIMARY KEY,
  name    VARCHAR(30) NOT NULL,
  dept    CHAR(4)
);
ALTER TABLE student ADD marks INT CHECK (marks BETWEEN 0 AND 100);

-- DML: work on the data
INSERT INTO student VALUES
  (1, 'Anitha', 'CSE', 88),
  (2, 'Bala',   'ECE', 72),
  (3, 'Charan', 'CSE', 65),
  (4, 'Divya',  'MECH', 91);
UPDATE student SET marks = 70 WHERE roll_no = 3;
DELETE FROM student WHERE dept = 'MECH';
SELECT name, marks FROM student WHERE dept = 'CSE' ORDER BY marks DESC;
Result of the final SELECT
namemarks
Anitha88
Charan70

Step by step: CREATE makes an empty table with three columns, and ALTER adds a fourth. INSERT adds four rows. UPDATE raises Charan's marks to 70. DELETE removes Divya, the only MECH student. SELECT lists the CSE students, highest marks first.

In real life

Online sign-up

Creating an account on a website runs an INSERT. Changing your phone number later runs an UPDATE with WHERE user_id = your id.

Shopping cart

Adding an item is an INSERT, changing the quantity is an UPDATE, removing it is a DELETE, and showing the cart is a SELECT.

Key points

  • DML works on rows: INSERT, UPDATE, DELETE and SELECT.
  • INSERT can add one row, many rows, or the result of a SELECT.
  • UPDATE ... SET ... WHERE changes chosen rows; without WHERE it changes every row.
  • DELETE FROM ... WHERE removes chosen rows; without WHERE it empties the table.
  • Every INSERT, UPDATE and DELETE must satisfy the table's constraints.
  • DML can be undone with ROLLBACK before COMMIT; DDL cannot.
