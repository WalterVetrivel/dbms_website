DDL

DDL commands build and change the structure of a database: the tables, their columns and their rules. This page walks through each command on one example table, then compares DDL with DML.

What is DDL?

Definition

DDL (Data Definition Language) is the part of SQL used to define, change and remove the schema: databases, tables, columns, constraints, views and indexes.

DDL works on the structure, not on the rows. The DDL interpreter (see Database System Architecture) stores each definition in the data dictionary, so the DBMS always knows what tables exist and what rules they follow.

The five DDL commands
CommandWhat it does
CREATEMakes a new database, table, view or index.
ALTERChanges an existing table: add, drop or change a column or a constraint.
DROPRemoves a table (structure and data) for good.
TRUNCATERemoves all rows but keeps the empty table.
RENAMEGives a table a new name.

CREATE

Create a database

Syntax 
CREATE DATABASE database_name;
USE database_name;

USE makes it the current database, so the tables you create next go inside it.

Create a table

Syntax 
CREATE TABLE table_name (
  column1 datatype [column constraints],
  column2 datatype [column constraints],
  ...
  [table constraints]
);

Each column needs a name and a data type (see Overview of SQL for the types). The example below is the person_details table from the notes, with a primary key added.

MySQL 
CREATE TABLE person_details (
  aadhaar_no  INT,
  first_name  VARCHAR(20),
  middle_name VARCHAR(20),
  last_name   VARCHAR(20),
  address     VARCHAR(30),
  city        VARCHAR(20),
  PRIMARY KEY (aadhaar_no)
);
DESCRIBE person_details;

DESCRIBE (or DESC) shows the structure. The new table has six columns and no rows.

Watch out

The notes write the column list inside curly braces { }. SQL needs round brackets ( ), and each column is separated by a comma. With braces the statement fails.

A table can also be made from a query. It copies the columns and the rows, but not the keys:

MySQL 
CREATE TABLE salem_people AS
  SELECT aadhaar_no, first_name FROM person_details WHERE city = 'Salem';

Defining constraints

Constraints are rules the data must follow. The meaning of each one is on the Constraints page. Here we look at how to write them.

A constraint can be written in two places:

  • Column level: right after the column, for a rule on that one column.
  • Table level: after all the columns, for a rule on one or more columns. A composite key must be written here.

The CONSTRAINT name part is optional. A name makes error messages clearer and lets you drop the rule later.

MySQL 
CREATE TABLE department (
  dept_id   INT PRIMARY KEY,                       -- column level
  dept_name VARCHAR(20) NOT NULL UNIQUE            -- column level
);

CREATE TABLE employee (
  emp_id      INT NOT NULL,
  name        VARCHAR(20) NOT NULL,
  designation VARCHAR(20),
  salary      DECIMAL(10, 2) CHECK (salary > 0),   -- column level
  dept_id     INT,
  CONSTRAINT pk_employee PRIMARY KEY (emp_id),     -- table level
  CONSTRAINT fk_emp_dept FOREIGN KEY (dept_id)
    REFERENCES department (dept_id)                -- table level
);

A composite primary key names two columns at table level:

MySQL 
CREATE TABLE enrolment (
  roll_no   INT,
  course_id VARCHAR(10),
  grade     CHAR(2),
  CONSTRAINT pk_enrolment PRIMARY KEY (roll_no, course_id)
);
Watch out

The notes give Price DECIMAL(10, 2) NOT NULL CHECK(cost > 0). There is no cost column, so this fails. The check must name a real column: CHECK (price > 0).

ALTER

ALTER TABLE changes a table that already exists. The rows already in it are kept.

Common ALTER TABLE forms in MySQL
TaskForm
Add a columnADD column datatype
Remove a columnDROP COLUMN column
Change a column's type or ruleMODIFY column new_datatype
Rename a columnRENAME COLUMN old TO new
Add a constraintADD CONSTRAINT name ...
Remove a constraintDROP CONSTRAINT name

Add and drop a column

MySQL 
ALTER TABLE person_details ADD email VARCHAR(30);
ALTER TABLE person_details DROP COLUMN address;

The table now has email at the end, and address is gone with all its values. Existing rows get NULL in the new column.

Modify and rename a column

MySQL 
ALTER TABLE person_details MODIFY city VARCHAR(30) NOT NULL;
ALTER TABLE person_details RENAME COLUMN email TO email_id;

MODIFY makes the column wider and adds NOT NULL. It fails if a row already has NULL in that column.

Add and drop a constraint

MySQL 
ALTER TABLE employee ADD CONSTRAINT uq_designation UNIQUE (designation);
ALTER TABLE employee ADD CONSTRAINT chk_name CHECK (name <> '');
ALTER TABLE employee DROP CONSTRAINT chk_name;
Other databases

MODIFY is MySQL and Oracle syntax. Standard SQL, PostgreSQL and SQL Server use ALTER COLUMN instead.

DROP

DROP TABLE removes the table, its rows, its constraints and its indexes. The name is gone from the data dictionary.

MySQL 
DROP TABLE salem_people;
DROP TABLE IF EXISTS old_marks;   -- no error if the table is not there

A parent table cannot be dropped while a foreign key in another table still points to it. Drop the child table first, or remove its foreign key.

MySQL 
DROP TABLE department;   -- ERROR: employee.dept_id still references it

The same command works for other objects: DROP DATABASE, DROP VIEW and DROP INDEX.

TRUNCATE

TRUNCATE TABLE removes every row but keeps the table, its columns and its constraints. It is much faster than deleting the rows one at a time, because the DBMS simply empties the table's storage.

MySQL 
TRUNCATE TABLE enrolment;
SELECT COUNT(*) FROM enrolment;   -- 0, but the table still exists

RENAME

RENAME TABLE gives a table a new name. The rows and constraints stay the same.

MySQL 
RENAME TABLE person_details TO person;
ALTER TABLE person RENAME TO person_details;   -- the same thing with ALTER

Auto-commit

In MySQL and Oracle, every DDL statement first commits any open transaction and then commits itself. A ROLLBACK after DROP TABLE does not bring the table back. DML commands are covered on the DML page.

In real life

App updates

When a shopping app adds a “wish list” feature, its developers run a migration script: a CREATE TABLE for the new list and an ALTER TABLE to add a column.

New semester

A college portal may TRUNCATE a temporary “attendance this week” table every Monday. The table stays, only the old rows go.

Key points

  • DDL defines the schema: CREATE, ALTER, DROP, TRUNCATE and RENAME.
  • CREATE TABLE lists each column with a data type, then any table-level constraints.
  • Constraints can be written at column level or table level; composite keys go at table level.
  • ALTER TABLE can ADD, DROP COLUMN, MODIFY or RENAME COLUMN, and add or drop constraints.
  • DROP removes the table; TRUNCATE empties it; DELETE (DML) removes chosen rows.
  • DDL is auto-committed in MySQL, so it cannot be rolled back.
