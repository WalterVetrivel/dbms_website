Basic Structure of SQL Queries

Almost every SQL query has the shape SELECT … FROM … WHERE. This page explains each clause, joins two tables in one query, filters and sorts the result, and shows the order in which the DBMS actually runs the clauses.

Learning outcomes

After this page you can
  • Write a SELECT-FROM-WHERE query and say what each clause does.
  • Relate a query to the relational algebra operations π, σ and ×.
  • Query two tables together using a join condition.
  • Filter with AND, OR, NOT, IN, BETWEEN and LIKE, and sort with ORDER BY.

The SELECT-FROM-WHERE structure

Syntax 
SELECT [DISTINCT] A1, A2, ..., An     -- target list: the columns you want
FROM   r1, r2, ..., rm               -- relation list: the tables to read
WHERE  P;                            -- qualification: the condition rows must meet
The three clauses
ClauseWhat it doesRelational algebra
SELECTLists the attributes wanted in the resultProject π
FROMLists the relations to read. Several relations mean their Cartesian productCartesian product ×
WHEREA predicate on the attributes, built with comparisons, AND, OR and NOTSelect σ

So a basic query is the same as this relational algebra expression:

Relational algebra 
π A1, A2, ..., An (σ P (r1 × r2 × ... × rm))
Common mistake

The SQL keyword SELECT matches the project (π) operation, not the select (σ) operation. The WHERE clause matches σ.

The sample table

MySQL 
CREATE TABLE student (
  roll  INT PRIMARY KEY,
  name  VARCHAR(20),
  dept  VARCHAR(5),
  city  VARCHAR(20),
  marks INT
);
INSERT INTO student VALUES
  (1, 'Anitha', 'CSE', 'Salem', 88),   (2, 'Bharath', 'IT', 'Chennai', 72),
  (3, 'Charan', 'CSE', 'Salem', 65),   (4, 'Divya', 'ECE', 'Erode', 91),
  (5, 'Ezhil', 'IT', 'Salem', 55),     (6, 'Farhan', 'CSE', 'Erode', 79),
  (7, 'Gowri', 'ECE', 'Salem', 84),    (8, 'Hari', 'IT', 'Erode', 47);

SELECT and FROM

All columns: the star * means every attribute.

SQL 
SELECT * FROM student;

Some columns: list them, separated by commas.

SQL 
SELECT name, marks FROM student;

DISTINCT and ALL

Unlike relational algebra, SQL keeps duplicate rows by default. Add DISTINCT to remove them. (ALL, the default, keeps them.)

SQL 
SELECT city FROM student;           -- 8 rows, Salem four times
SELECT DISTINCT city FROM student;  -- 3 rows: Salem, Chennai, Erode

Expressions and aliases

The SELECT list can compute values. AS gives the result column a new name (an alias).

SQL 
SELECT name, marks + 5 AS revised_marks FROM student;

WHERE: choosing rows

WHERE keeps only the rows that make the condition true. Conditions use the comparison operators =, <> (not equal), <, <=, > and >=.

SQL 
SELECT name FROM student WHERE marks > 80;

Result: Anitha, Divya and Gowri.

Logical operators: AND, OR and NOT

Logical operators
OperatorA row is kept ifExampleResult
ANDAll the conditions are truedept = 'CSE' AND city = 'Salem'Anitha, Charan
ORAt least one condition is truecity = 'Chennai' OR marks > 90Bharath, Divya
NOTThe condition is falseNOT city = 'Salem'Bharath, Divya, Farhan, Hari
SQL 
SELECT roll, name, city
FROM student
WHERE dept = 'CSE' AND city = 'Salem';

IN, BETWEEN and LIKE

  • IN tests a list of values. It is a short form of several ORs: WHERE roll IN (1, 3) gives Anitha and Charan.
  • BETWEEN tests a range, ends included: WHERE marks BETWEEN 70 AND 85 gives Bharath, Farhan and Gowri.
  • LIKE matches a text pattern. % means any number of characters and _ means exactly one: WHERE name LIKE 'D%' gives Divya.
SQL 
SELECT name, marks FROM student WHERE marks BETWEEN 70 AND 85;

Queries on more than one table

Often the answer needs data from two tables. Add a department table with each head of department (HOD):

MySQL 
CREATE TABLE department (
  dept      VARCHAR(5) PRIMARY KEY,
  dept_name VARCHAR(40),
  hod       VARCHAR(20)
);
INSERT INTO department VALUES
  ('CSE', 'Computer Science and Engineering', 'Dr. Raghu'),
  ('IT',  'Information Technology',           'Dr. Janani'),
  ('ECE', 'Electronics and Communication',    'Dr. Kannan');

Query: list each student from Salem with the name of their HOD.

SQL 
SELECT student.name, department.hod
FROM student, department
WHERE student.dept = department.dept
  AND student.city = 'Salem';
Result
namehod
AnithaDr. Raghu
CharanDr. Raghu
EzhilDr. Janani
GowriDr. Kannan
  • FROM student, department forms the Cartesian product: 8 × 3 = 24 row pairs.
  • student.dept = department.dept is the join condition. It keeps only the pairs that belong together. Without it, every student would be paired with every HOD.
  • Both tables have a dept column, so we write student.dept and department.dept to say which one we mean.

Tuple variables (table aliases)

Short names make long queries easier to read. The same query, written with aliases and the JOIN ... ON form:

SQL 
SELECT s.name, d.hod
FROM student AS s
INNER JOIN department AS d ON s.dept = d.dept
WHERE s.city = 'Salem';

Both forms give the same result. LEFT, RIGHT and FULL joins keep unmatched rows, just like the outer joins of Relational Algebra. Unit II covers them under Joins.

ORDER BY: sorting the result

The rows of a result come in no fixed order unless you ask for one. ORDER BY sorts them. ASC (ascending, smallest first) is the default; DESC sorts largest first.

SQL 
SELECT name, dept, marks
FROM student
ORDER BY dept ASC, marks DESC;

Rows are sorted by dept first. Within the same dept, the higher marks come first: CSE gives Anitha 88, Farhan 79, Charan 65.

The order in which clauses run

We write SELECT first, but the DBMS runs it near the end. The logical order is:

  1. FROM: get the rows of the tables (and join them).
  2. WHERE: remove rows that fail the condition.
  3. GROUP BY: put the remaining rows into groups.
  4. HAVING: remove groups that fail the group condition.
  5. SELECT: compute the output columns (then DISTINCT removes repeats).
  6. ORDER BY: sort the final rows.

This explains a common error: an alias made in SELECT cannot be used in WHERE, because WHERE runs before SELECT. It can be used in ORDER BY, which runs after. GROUP BY and HAVING are covered in Unit II.

Things to try
  • In “WHERE and ORDER BY”, how many rows are left after WHERE? Which clause decides that Gowri comes before Charan?
  • In “GROUP BY and HAVING”, which rows does WHERE remove, and which whole group does HAVING remove?

In real life

Rank list

A college rank list is SELECT name, marks FROM student WHERE dept = 'CSE' ORDER BY marks DESC.

Food delivery filters

“Vegetarian, rating above 4, sorted by delivery time” is a WHERE with AND, followed by ORDER BY.

Key points

  • Basic form: SELECT columns FROM tables WHERE condition.
  • SELECT ≈ π, FROM ≈ ×, WHERE ≈ σ.
  • SQL keeps duplicates unless you write DISTINCT.
  • With several tables in FROM, a join condition in WHERE (or JOIN ... ON) pairs the right rows.
  • AND needs all conditions true, OR needs one, NOT reverses a condition; IN, BETWEEN and LIKE are short forms.
  • ORDER BY sorts the result; ASC is the default, DESC is largest first.
  • Clauses run in the order FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY.
