SQL Set Operations

A set operation combines the results of two SELECT queries into one result. SQL has four: UNION, UNION ALL, INTERSECT and EXCEPT. This page shows what each one returns, how each treats duplicate rows, and how to write them in MySQL.

Rules for set operations

Definition

A set operation combines the rows returned by two SELECT statements into one result. The general form is:

Syntax 
SELECT column_list FROM table1
{UNION | UNION ALL | INTERSECT | EXCEPT}
SELECT column_list FROM table2;

The two queries must be union compatible:

  1. They return the same number of columns.
  2. Matching columns have compatible data types (for example, both numbers or both text).
  3. Columns are matched by position, not by name. The result takes its column names from the first query.

These are the SQL versions of the relational algebra operations ∪, ∩ and − (see Relational Algebra).

Common mistake

MySQL checks the number of columns, but it converts types silently. SELECT NAME FROM First UNION SELECT ID FROM Second runs without an error and mixes names with numbers in one column. Make sure matching columns mean the same thing.

UNION

UNION returns every row that is in the first result, the second result, or both. It removes duplicates, so each row appears once.

SQL 
SELECT * FROM First
UNION
SELECT * FROM Second
ORDER BY ID;
Output 
+------+---------+
| ID   | NAME    |
+------+---------+
|    1 | Jack    |
|    2 | Harry   |
|    3 | Jackson |
|    4 | Stephan |
|    5 | David   |
+------+---------+

Jackson is in both tables but appears once. UNION is the same as UNION DISTINCT.

UNION ALL

UNION ALL returns all the rows of both results and keeps duplicates.

SQL 
SELECT * FROM First
UNION ALL
SELECT * FROM Second
ORDER BY ID;
Output 
+------+---------+
| ID   | NAME    |
+------+---------+
|    1 | Jack    |
|    2 | Harry   |
|    3 | Jackson |
|    3 | Jackson |
|    4 | Stephan |
|    5 | David   |
+------+---------+
  • The number of rows is always the sum: 3 + 3 = 6.
  • UNION ALL is faster than UNION, because it does not have to look for duplicates.
  • Use it when duplicates cannot occur, or when you want to count them.

INTERSECT

INTERSECT returns only the rows that appear in both results, without duplicates.

SQL 
SELECT * FROM First
INTERSECT
SELECT * FROM Second;
Output 
+------+---------+
| ID   | NAME    |
+------+---------+
|    3 | Jackson |
+------+---------+

MySQL supports INTERSECT from version 8.0.31. In older versions, write it with IN or EXISTS:

SQL 
SELECT * FROM First f
WHERE EXISTS (SELECT * FROM Second s WHERE s.ID = f.ID AND s.NAME = f.NAME);

EXCEPT (MINUS)

EXCEPT returns the rows of the first result that are not in the second, without duplicates. Order matters: A EXCEPT B is not the same as B EXCEPT A.

SQL 
SELECT * FROM First
EXCEPT
SELECT * FROM Second
ORDER BY ID;
Output 
+------+-------+
| ID   | NAME  |
+------+-------+
|    1 | Jack  |
|    2 | Harry |
+------+-------+

MySQL supports EXCEPT from version 8.0.31. In older versions, use NOT EXISTS:

SQL 
SELECT * FROM First f
WHERE NOT EXISTS (SELECT * FROM Second s WHERE s.ID = f.ID AND s.NAME = f.NAME)
ORDER BY ID;
Common mistake

Some notes use the keyword MINUS. MINUS is Oracle's name for this operation. The SQL standard, MySQL, PostgreSQL and SQL Server all call it EXCEPT. In MySQL, SELECT ... MINUS SELECT ... is a syntax error.

Sorting and combining operations

  • ORDER BY goes once, at the very end. It sorts the whole combined result. Use the column names of the first query.
  • Without ORDER BY, the order of the rows is not guaranteed by any of the four operations.
  • You can chain operations: q1 UNION q2 EXCEPT q3. INTERSECT binds more tightly than UNION and EXCEPT, just as × binds more tightly than + in arithmetic. Use brackets to make the order clear.
  • MySQL also has INTERSECT ALL and EXCEPT ALL, which keep duplicates, as UNION ALL does.
Common mistake

Some notes say INTERSECT and MINUS “arrange the data in ascending order by default”. That is not promised. Some systems happen to sort while removing duplicates, but the order can change between versions or plans. Always add ORDER BY when order matters.

In real life

Mailing list

A college sends one circular to everyone: students UNION staff gives one list of email addresses with no repeats.

Bank offers

Customers with a savings account INTERSECT customers with a loan gives the people who have both, for a combined offer.

Exam hall tickets

Registered students EXCEPT students with fee dues gives the list of students who get a hall ticket.

Key points

  • Set operations combine two SELECT results with the same number of columns and compatible types.
  • UNION: rows in either result, duplicates removed. UNION ALL keeps duplicates.
  • INTERSECT: rows in both results. EXCEPT: rows in the first but not the second.
  • MySQL uses EXCEPT, not MINUS. INTERSECT and EXCEPT need MySQL 8.0.31 or later.
  • Put one ORDER BY at the end. Without it, the order is not guaranteed.
