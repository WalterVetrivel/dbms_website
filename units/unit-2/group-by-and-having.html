GROUP BY and HAVING

Aggregate functions summarize a whole table. GROUP BY lets them summarize each part of it, such as the total cost per company or the average mark per department. HAVING then keeps only the groups you want. This page shows both, and the difference between HAVING and WHERE.

GROUP BY

Definition

GROUP BY puts rows that have the same value in the given columns into one group. Each aggregate function in SELECT is then applied to each group separately, and the query returns one row per group.

Syntax 
SELECT column, aggregate_function(column)
FROM table
[WHERE condition]
GROUP BY column
[HAVING group_condition]
[ORDER BY column];

We use the PRODUCT_MAST table from Aggregate Functions: ten products of three companies.

SQL 
SELECT COMPANY, COUNT(*)
FROM PRODUCT_MAST
GROUP BY COMPANY
ORDER BY COMPANY;
Output 
+---------+----------+
| COMPANY | COUNT(*) |
+---------+----------+
| Com1    |        5 |
| Com2    |        3 |
| Com3    |        2 |
+---------+----------+

The ten rows form three groups, so the result has three rows.

GROUP BY with WHERE

WHERE removes rows before they are grouped:

SQL 
SELECT COMPANY, SUM(COST)
FROM PRODUCT_MAST
WHERE QTY > 3
GROUP BY COMPANY
ORDER BY COMPANY;
Output 
+---------+-----------+
| COMPANY | SUM(COST) |
+---------+-----------+
| Com1    |       150 |
| Com3    |       170 |
+---------+-----------+

Only Item4 (Com3, 50), Item7 (Com1, 150) and Item10 (Com3, 120) have QTY > 3. Com2 has no such row, so it has no group at all.

Common mistake

Some notes write this query without COMPANY in the SELECT list, and show the result as Com1 150 and Com2 170. Two things are wrong. Without COMPANY in SELECT, the output has no company column at all. And the second group is Com3 (50 + 120 = 170), not Com2.

Rules for GROUP BY

  1. Every column in SELECT must either be in GROUP BY or be inside an aggregate function. SELECT COMPANY, PRODUCT, SUM(COST) ... GROUP BY COMPANY is an error in MySQL 8.4: a group has five products, so which one should it show?
  2. A column in GROUP BY does not have to appear in SELECT, but the result is hard to read without it.
  3. All NULL values in a grouping column form one group.
  4. GROUP BY does not promise any order. Add ORDER BY to sort the groups.
GROUP BY without aggregates

SELECT COMPANY FROM PRODUCT_MAST GROUP BY COMPANY; returns each company once. It does the same job as SELECT DISTINCT COMPANY.

HAVING

Definition

HAVING filters groups after GROUP BY has formed them. Its condition can use aggregate functions.

SQL 
SELECT COMPANY, COUNT(*)
FROM PRODUCT_MAST
GROUP BY COMPANY
HAVING COUNT(*) > 2
ORDER BY COMPANY;
Output 
+---------+----------+
| COMPANY | COUNT(*) |
+---------+----------+
| Com1    |        5 |
| Com2    |        3 |
+---------+----------+

Com3 has only 2 products, so its group is removed.

SQL 
SELECT COMPANY, SUM(COST)
FROM PRODUCT_MAST
GROUP BY COMPANY
HAVING SUM(COST) >= 170
ORDER BY COMPANY;
Output 
+---------+-----------+
| COMPANY | SUM(COST) |
+---------+-----------+
| Com1    |       335 |
| Com3    |       170 |
+---------+-----------+

The totals are Com1 335, Com2 165 and Com3 170. Com2 is below 170, so it is removed.

WHERE and HAVING compared

WHERE compared with HAVING
PointWHEREHAVING
FiltersIndividual rowsGroups
RunsBefore GROUP BYAfter GROUP BY
Aggregate functionsNot allowedAllowed
Needs GROUP BYNoUsually used with it (without it, the whole table is one group)
ExampleWHERE RATE >= 20HAVING SUM(COST) > 150

A condition on a plain column, such as COMPANY = 'Com1', works in either place. Put it in WHERE: fewer rows are grouped, so the query is faster.

The order SQL runs the clauses

We write SELECT first, but the database runs it almost last:

  1. FROM: take the rows of the table.
  2. WHERE: keep only the rows that pass the condition.
  3. GROUP BY: put the remaining rows into groups.
  4. HAVING: keep only the groups that pass the condition.
  5. SELECT: compute the output columns and aggregates.
  6. ORDER BY: sort the result.

This order explains the rules. WHERE runs before groups exist, so it cannot use SUM. ORDER BY runs after SELECT, so it can use a column alias such as total. (MySQL also lets HAVING use an alias, but the SQL standard does not.)

A full example

For products with a rate of at least 20, show each company's number of items and total cost. Keep only companies whose total is over 150, largest first.

SQL 
SELECT COMPANY, COUNT(*) AS items, SUM(COST) AS total
FROM PRODUCT_MAST
WHERE RATE >= 20
GROUP BY COMPANY
HAVING SUM(COST) > 150
ORDER BY total DESC;
Output 
+---------+-------+-------+
| COMPANY | items | total |
+---------+-------+-------+
| Com1    |     3 |   285 |
| Com2    |     3 |   165 |
+---------+-------+-------+
  1. WHERE keeps the 7 products with RATE ≥ 20.
  2. GROUP BY makes three groups: Com1 (Item3, Item6, Item7), Com2 (Item2, Item5, Item9) and Com3 (Item10).
  3. The totals are 285, 165 and 120. HAVING removes Com3.
  4. ORDER BY sorts by total, largest first.

Grouping by several columns

With two columns in GROUP BY, rows go into the same group only when both values match.

SQL 
SELECT COMPANY, RATE, COUNT(*) AS items, SUM(COST) AS total
FROM PRODUCT_MAST
GROUP BY COMPANY, RATE
ORDER BY COMPANY, RATE;
Output 
+---------+------+-------+-------+
| COMPANY | RATE | items | total |
+---------+------+-------+-------+
| Com1    |   10 |     2 |    50 |
| Com1    |   25 |     1 |    75 |
| Com1    |   30 |     2 |   210 |
| Com2    |   20 |     1 |    40 |
| Com2    |   25 |     2 |   125 |
| Com3    |   10 |     1 |    50 |
| Com3    |   30 |     1 |   120 |
+---------+------+-------+-------+

Com1 now splits into three groups, one for each of its rates.

In real life

Placement report

GROUP BY dept counts the students placed in each department. HAVING COUNT(*) >= 50 lists the departments that met the target.

Sales dashboard

A shop groups sales by month to see monthly revenue, and uses HAVING to flag months with revenue below a goal.

Attendance

GROUP BY roll number with HAVING AVG(present) < 0.75 lists students who are short of attendance.

Key points

  • GROUP BY forms groups of rows with equal values; aggregates then give one result per group.
  • Each SELECT column must be in GROUP BY or inside an aggregate.
  • HAVING filters groups and can use aggregates; WHERE filters rows and cannot.
  • Order of execution: FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY.
  • Put plain-column conditions in WHERE, so fewer rows are grouped.
  • GROUP BY does not sort; use ORDER BY.
