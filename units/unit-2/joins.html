Joins

Normalization splits data into many tables. A join puts it back together for a query, by matching rows from two tables. This page covers every join type, shows exactly which rows each one returns, and points out the NULL traps that catch most beginners.

Learning outcomes

After this page you can
  • Write inner, natural, left, right, cross and self joins and predict their results.
  • Explain which rows an outer join keeps and why NULL values appear.
  • Write a full outer join in MySQL using UNION.
  • Use outer joins to count and to find rows with no match.

Why we need joins

Definition

A join combines rows from two tables into one result, using a join condition that says which rows belong together. Usually the condition matches a foreign key with the primary key it refers to.

After normalization, a student's name is in one table and the department name is in another. To list students with their department names, we must join the two tables on dept_id.

In relational algebra, a join is a Cartesian product followed by a selection (see Relational Algebra). SQL gives it its own syntax.

The sample tables

SQL 
CREATE TABLE department (
  dept_id   INT PRIMARY KEY,
  dept_name VARCHAR(20)
);
CREATE TABLE student (
  roll    INT PRIMARY KEY,
  name    VARCHAR(20),
  dept_id INT,
  FOREIGN KEY (dept_id) REFERENCES department (dept_id)
);
INSERT INTO department VALUES (10, 'CSE'), (20, 'IT'), (30, 'ECE');

Inner join

An inner join returns only the pairs of rows that satisfy the join condition. Rows with no partner are left out.

SQL 
SELECT s.name, d.dept_name
FROM student s
INNER JOIN department d ON s.dept_id = d.dept_id
ORDER BY s.roll;
Output 
+---------+-----------+
| name    | dept_name |
+---------+-----------+
| Anitha  | CSE       |
| Bharath | IT        |
| Charan  | CSE       |
+---------+-----------+
  • Divya is missing: her dept_id is NULL, and NULL = 10 is never true.
  • ECE is missing: no student has dept_id 30.
  • The word INNER is optional. JOIN on its own means inner join.
  • The letters s and d are aliases: short names for the tables.
  • A join whose condition uses = is an equi join. A condition can also use <, > or other operators (a theta join).

The older comma style gives the same result: SELECT s.name, d.dept_name FROM student s, department d WHERE s.dept_id = d.dept_id;. The JOIN ... ON style is clearer, because it keeps the join condition apart from the filters.

Natural join and USING

A natural join joins on every column with the same name in both tables, and shows each such column once.

SQL 
SELECT * FROM student NATURAL JOIN department ORDER BY roll;
Output 
+---------+------+---------+-----------+
| dept_id | roll | name    | dept_name |
+---------+------+---------+-----------+
|      10 |    1 | Anitha  | CSE       |
|      20 |    2 | Bharath | IT        |
|      10 |    3 | Charan  | CSE       |
+---------+------+---------+-----------+

JOIN department USING (dept_id) does the same, but names the column to match. It is safer, because NATURAL JOIN silently matches any other columns that happen to share a name, such as two columns both called name.

Left outer join

A left outer join returns every row of the left table. Where a row has no partner in the right table, the right-side columns are filled with NULL.

SQL 
SELECT s.name, d.dept_name
FROM student s
LEFT JOIN department d ON s.dept_id = d.dept_id
ORDER BY s.roll;
Output 
+---------+-----------+
| name    | dept_name |
+---------+-----------+
| Anitha  | CSE       |
| Bharath | IT        |
| Charan  | CSE       |
| Divya   | NULL      |
+---------+-----------+

Divya is kept, with NULL for the department. The word OUTER is optional: LEFT JOIN and LEFT OUTER JOIN mean the same.

Right outer join

A right outer join keeps every row of the right table, with NULL in the left-side columns where there is no match.

SQL 
SELECT s.name, d.dept_name
FROM student s
RIGHT JOIN department d ON s.dept_id = d.dept_id
ORDER BY d.dept_id, s.roll;
Output 
+---------+-----------+
| name    | dept_name |
+---------+-----------+
| Anitha  | CSE       |
| Charan  | CSE       |
| Bharath | IT        |
| NULL    | ECE       |
+---------+-----------+

ECE is kept, with NULL for the student. A RIGHT JOIN B gives the same rows as B LEFT JOIN A, so many people only ever write LEFT JOIN.

Full outer join

A full outer join keeps every row of both tables: matched pairs, left rows with no partner, and right rows with no partner.

Standard SQL writes it as FULL OUTER JOIN. MySQL does not support FULL OUTER JOIN, so we combine a left join and a right join with UNION:

SQL 
SELECT s.roll, s.name, d.dept_name
FROM student s
LEFT JOIN department d ON s.dept_id = d.dept_id
UNION
SELECT s.roll, s.name, d.dept_name
FROM student s
RIGHT JOIN department d ON s.dept_id = d.dept_id;
Output 
+------+---------+-----------+
| roll | name    | dept_name |
+------+---------+-----------+
|    1 | Anitha  | CSE       |
|    2 | Bharath | IT        |
|    3 | Charan  | CSE       |
|    4 | Divya   | NULL      |
| NULL | NULL    | ECE       |
+------+---------+-----------+
  • Both halves return the three matched rows. UNION removes the copies, so they appear once.
  • Include a key (here roll) in the SELECT list. Otherwise two different students with the same name and department would look like copies, and UNION would merge them.
  • To avoid that risk completely, use UNION ALL and keep only the unmatched rows in the second half: add WHERE s.roll IS NULL to the right join.

Cross join

A cross join pairs every row of the first table with every row of the second. It is the Cartesian product, and it has no join condition.

SQL 
SELECT s.name, d.dept_name
FROM student s
CROSS JOIN department d
WHERE s.roll = 1
ORDER BY d.dept_id;
Output 
+--------+-----------+
| name   | dept_name |
+--------+-----------+
| Anitha | CSE       |
| Anitha | IT        |
| Anitha | ECE       |
+--------+-----------+

Without the WHERE, the result has 4 × 3 = 12 rows. Forgetting the join condition in the comma style gives a cross join by accident, which is a common bug.

Self join

A self join joins a table with itself. Give the table two different aliases, so each copy can be named.

SQL 
CREATE TABLE employee (
  emp_id     INT PRIMARY KEY,
  name       VARCHAR(20),
  manager_id INT
);
INSERT INTO employee VALUES (1, 'Ravi', NULL), (2, 'Meena', 1), (3, 'Kumar', 1), (4, 'Asha', 2);

SELECT e.name AS employee, m.name AS manager
FROM employee e
LEFT JOIN employee m ON e.manager_id = m.emp_id
ORDER BY e.emp_id;
Output 
+----------+---------+
| employee | manager |
+----------+---------+
| Ravi     | NULL    |
| Meena    | Ravi    |
| Kumar    | Ravi    |
| Asha     | Meena   |
+----------+---------+

e is the employee and m is the manager. A LEFT JOIN keeps Ravi, who has no manager. An inner join would drop him.

ON and WHERE in outer joins

For an inner join, a condition gives the same result in ON or in WHERE. For an outer join, it does not:

SQL 
-- Condition in ON: every student is kept; only CSE departments are matched.
SELECT s.name, d.dept_name
FROM student s
LEFT JOIN department d ON s.dept_id = d.dept_id AND d.dept_name = 'CSE'
ORDER BY s.roll;

-- Condition in WHERE: rows with NULL dept_name are then removed.
SELECT s.name, d.dept_name
FROM student s
LEFT JOIN department d ON s.dept_id = d.dept_id
WHERE d.dept_name = 'CSE'
ORDER BY s.roll;
Output 
+---------+-----------+
| name    | dept_name |
+---------+-----------+
| Anitha  | CSE       |
| Bharath | NULL      |
| Charan  | CSE       |
| Divya   | NULL      |
+---------+-----------+
+--------+-----------+
| name   | dept_name |
+--------+-----------+
| Anitha | CSE       |
| Charan | CSE       |
+--------+-----------+

The WHERE version runs after the join and throws away the NULL rows, so the left join behaves like an inner join. Put conditions on the right table in ON when you want to keep every left row.

Two useful patterns

Count, including zero

SQL 
SELECT d.dept_name, COUNT(s.roll) AS students
FROM department d
LEFT JOIN student s ON s.dept_id = d.dept_id
GROUP BY d.dept_id, d.dept_name
ORDER BY d.dept_id;
Output 
+-----------+----------+
| dept_name | students |
+-----------+----------+
| CSE       |        2 |
| IT        |        1 |
| ECE       |        0 |
+-----------+----------+

Use COUNT(s.roll), not COUNT(*). The ECE row has NULL in s.roll, so COUNT(s.roll) gives 0, while COUNT(*) would count the row and give 1.

Find rows with no match

SQL 
SELECT d.dept_name
FROM department d
LEFT JOIN student s ON s.dept_id = d.dept_id
WHERE s.roll IS NULL;      -- ECE

The left join keeps every department, and the WHERE keeps only those that found no student. This is called an anti-join.

In real life

Order history

An online shop joins orders with products and customers to show “who bought what”: an inner join on product ID and customer ID.

Inactive customers

A left join from customers to orders, keeping rows where the order is NULL, finds customers who never ordered: a target list for offers.

Org charts

An HR system builds its reporting chart with a self join of employees on manager ID.

Key points

  • An inner join keeps only matching pairs. NULL never matches anything.
  • Left and right outer joins also keep unmatched rows of one side, padded with NULL.
  • MySQL has no FULL OUTER JOIN; write LEFT JOIN UNION RIGHT JOIN.
  • A cross join returns every pair: rows(A) × rows(B).
  • A self join uses one table twice, with two aliases.
  • In an outer join, a condition on the optional side belongs in ON, not WHERE.
