Multivalued Dependencies and Fourth Normal Form

Some tables repeat data even though they are in BCNF. This happens when one attribute has two independent lists of values, such as a student's courses and a student's skills. A multivalued dependency describes this, and fourth normal form removes it.

Learning outcomes

After this page you can
  • Define a multivalued dependency and recognize one in a table.
  • Tell trivial MVDs from non-trivial ones, and relate MVDs to FDs.
  • Define 4NF and decompose a relation into 4NF without loss.
  • Compare 4NF with BCNF.

The problem BCNF misses

A college records the courses each student takes and the languages (skills) each student speaks. The two lists have nothing to do with each other.

Student(sid, course, skill)
sidcourseskill
1CEnglish
1CGerman
1JavaEnglish
1JavaGerman
2CTamil
  • Student 1 takes 2 courses and speaks 2 languages, so the table needs 2 × 2 = 4 rows. Each course is stored twice, and each language is stored twice.
  • No FD holds here. sid does not determine course, and sid does not determine skill. The only key is {sid, course, skill}, so the table is in BCNF.
  • Yet it has anomalies. If student 1 learns French, we must add two rows, one for each course. Adding only one would wrongly suggest French is linked to one course.

The cause is not an FD. It is a multivalued dependency.

Multivalued dependency

Definition

Let X and Y be sets of attributes of R, and let Z = R − X − Y be the rest. The multivalued dependency X →→ Y (“X multi-determines Y”) holds if each X value has a set of Y values that does not depend on Z.

Formally: take any two rows t1 and t2 that agree on X. Then there must also be a row t3 with the same X value, the Y value of t1 and the Z value of t2.

In Student, sid →→ course holds. Rows (1, C, English) and (1, Java, German) agree on sid. So the rows (1, C, German) and (1, Java, English) must also be there, and they are. Every course of a student appears with every skill of that student.

For a relation R(A, B, C), an MVD A →→ B needs three things:

  1. One A value has several B values.
  2. The relation has at least three attributes.
  3. B and C are independent of each other, for a fixed A.
Common mistake

Some notes say an MVD exists whenever “for one value of A there are many values of B”. That is not enough. In Enrollment(sid, course, teacher), one student has many courses, but the teacher depends on the course. So sid →→ course does not hold there. The B values must be independent of the rest.

The symbol is a double arrow, →→. A single arrow means an FD.

Rules for MVDs

  • Complementation: if X →→ Y holds, then X →→ R − X − Y holds too. In Student, sid →→ course gives sid →→ skill. MVDs come in pairs.
  • Trivial MVD: X →→ Y is trivial if Y ⊆ X, or if X ∪ Y = R. A trivial MVD holds in every relation, so it says nothing.
  • Every FD is an MVD: if X → Y, then X →→ Y. Each X value has a set of exactly one Y value.
  • Lossless split: R splits into (X ∪ Y) and (X ∪ Z) without loss if and only if X →→ Y holds. This is the exact test for a two-way split.

The last rule shows that an MVD is the condition for a lossless split into two. A join dependency, in the next topic, extends this to three or more parts.

Fourth normal form (4NF)

Definition

A relation R is in fourth normal form if, for every non-trivial MVD X →→ Y that holds on R, X is a superkey of R.

  • This is the BCNF rule with MVDs in place of FDs.
  • Every FD is an MVD, so a 4NF relation is always in BCNF.
  • Student is not in 4NF: sid →→ course is non-trivial, and sid is not a superkey.
Common mistake

Some notes say a table is in 4NF if it is in BCNF and “has no multivalued dependency”. Every relation has trivial MVDs, and an MVD whose left side is a superkey is harmless. The correct rule is: no non-trivial MVD whose left side is not a superkey.

Decomposing into 4NF

  1. Find a non-trivial MVD X →→ Y where X is not a superkey.
  2. Split R into R1 = X ∪ Y and R2 = R − (Y − X).
  3. The split is lossless, by the rule above.
  4. Repeat on R1 and R2 until every table is in 4NF.

For Student, sid →→ course gives:

Each course and each skill of a student is now stored once. Joining the two tables on sid gives back all 5 original rows, and adding French for student 1 needs one row.

A second example

Course(course, teacher, book): any teacher of a course may use any of the course's books.

Course(course, teacher, book)
courseteacherbook
DBMSRaviKorth
DBMSRaviNavathe
DBMSMeenaKorth
DBMSMeenaNavathe
OSRaviGalvin
  • course →→ teacher and course →→ book hold. The teachers and books of a course are independent lists.
  • The key is all three attributes, so the table is in BCNF but not in 4NF.
  • 4NF tables: Course_Teacher(course, teacher) and Course_Book(course, book).

If the rule changes, so that each teacher uses only some books, the MVD no longer holds. Then the three-column table is needed, and it is already in 4NF.

The 4NF tables in SQL

SQL 
CREATE TABLE Student_Course (
  sid    INT,
  course VARCHAR(20),
  PRIMARY KEY (sid, course)
);

CREATE TABLE Student_Skill (
  sid   INT,
  skill VARCHAR(20),
  PRIMARY KEY (sid, skill)
);

INSERT INTO Student_Course VALUES (1, 'C'), (1, 'Java'), (2, 'C');
INSERT INTO Student_Skill VALUES (1, 'English'), (1, 'German'), (2, 'Tamil');

-- Student 1 learns French: one new row, not one per course.
INSERT INTO Student_Skill VALUES (1, 'French');

SELECT c.sid, c.course, s.skill
FROM Student_Course c
JOIN Student_Skill s ON s.sid = c.sid
ORDER BY c.sid, c.course, s.skill;
Output 
+-----+--------+---------+
| sid | course | skill   |
+-----+--------+---------+
|   1 | C      | English |
|   1 | C      | French  |
|   1 | C      | German  |
|   1 | Java   | English |
|   1 | Java   | French  |
|   1 | Java   | German  |
|   2 | C      | Tamil   |
+-----+--------+---------+

One insert added French to both of student 1's courses in the joined view. In the old table we would have needed two inserts, and forgetting one would break the data.

In real life

Restaurant menus

A restaurant has several branches and a list of dishes it delivers. If every branch delivers every dish, store Restaurant_Branch and Restaurant_Dish separately, not every branch-dish pair.

Employee profiles

An employee's phone numbers and certificates are independent lists. Keeping them in one table forces every phone to be paired with every certificate.

Product options

A shirt comes in several colors and several sizes, and every color comes in every size. Storing colors and sizes separately is the 4NF design.

Key points

  • X →→ Y: each X value has a set of Y values, independent of the other attributes.
  • MVDs come in pairs: X →→ Y gives X →→ R − X − Y.
  • Every FD is an MVD. An MVD is trivial if Y ⊆ X or X ∪ Y = R.
  • R splits losslessly into (X ∪ Y) and (X ∪ Z) exactly when X →→ Y holds.
  • 4NF: for every non-trivial MVD X →→ Y, X is a superkey. 4NF implies BCNF.
  • A BCNF table can still repeat data when it stores two independent lists; 4NF splits them.
