Aggregate Functions

An aggregate function takes many rows and returns one value, such as a total, an average or a count. SQL has five standard ones: COUNT, SUM, AVG, MIN and MAX. This page shows each one on a sample table, and the rules about NULL and duplicates that catch many students out.

Learning outcomes

After this page you can
  • Use COUNT, SUM, AVG, MIN and MAX in a query and predict the result.
  • Explain how each aggregate treats NULL values and how DISTINCT changes it.
  • Combine aggregates with WHERE, and know where aggregates may not be used.
  • Tell COUNT(*) from COUNT(column).

What an aggregate function is

Definition

An aggregate function takes the values of a column from many rows and returns one value that summarizes them.

The five standard aggregate functions
FunctionReturnsWorks on
COUNTThe number of rows or valuesAny type
SUMThe totalNumbers only
AVGThe average (mean)Numbers only
MINThe smallest valueNumbers, text and dates
MAXThe largest valueNumbers, text and dates

Each function can take ALL (the default) or DISTINCT before its argument: SUM(DISTINCT RATE) adds each different rate once.

Without GROUP BY, an aggregate summarizes all the selected rows and the query returns one row. With GROUP BY, it returns one value per group (see GROUP BY and HAVING).

Some notes print Item6's company as “Cpm1”. It is a typo for Com1. The notes' own answers (Com1 has 5 items) only work with Com1.

COUNT

COUNT has three forms:

  • COUNT(*) counts rows, including rows with NULL values and duplicate rows.
  • COUNT(column) counts the non-NULL values in a column.
  • COUNT(DISTINCT column) counts the different non-NULL values.
SQL 
SELECT COUNT(*) FROM PRODUCT_MAST;                   -- 10
SELECT COUNT(*) FROM PRODUCT_MAST WHERE RATE >= 20;  -- 7
SELECT COUNT(DISTINCT COMPANY) FROM PRODUCT_MAST;    -- 3

With WHERE, the filter runs first. COUNT then counts the 7 rows with a rate of 20 or more.

Common mistake

Some notes write the WHERE example as SELECT COUNT(*) FROM PRODUCT_MAST; WHERE RATE>=20;. The semicolon after PRODUCT_MAST ends the query too early, so MySQL returns 10 and then reports an error for the stray WHERE. The semicolon goes only at the end.

SUM

SUM adds up the values of a numeric column. NULL values are skipped.

SQL 
SELECT SUM(COST) FROM PRODUCT_MAST;               -- 670
SELECT SUM(COST) FROM PRODUCT_MAST WHERE QTY > 3; -- 320
SELECT SUM(DISTINCT RATE), SUM(RATE) FROM PRODUCT_MAST;
Output 
+--------------------+-----------+
| SUM(DISTINCT RATE) | SUM(RATE) |
+--------------------+-----------+
|                 85 |       215 |
+--------------------+-----------+
  • With QTY > 3, only Item4 (50), Item7 (150) and Item10 (120) remain: 50 + 150 + 120 = 320.
  • The different rates are 10, 25, 30 and 20, so SUM(DISTINCT RATE) = 85. SUM(RATE) adds all ten rates: 215.

AVG

AVG returns the average of the non-NULL values: their sum divided by their count.

SQL 
SELECT AVG(COST) FROM PRODUCT_MAST;
Output 
+-----------+
| AVG(COST) |
+-----------+
|   67.0000 |
+-----------+

670 ÷ 10 = 67. MySQL returns AVG of whole numbers as a decimal with four places. Use ROUND(AVG(COST), 2) to show two.

MIN and MAX

MIN and MAX return the smallest and largest value. They work on numbers, text and dates.

SQL 
SELECT MAX(RATE), MIN(RATE) FROM PRODUCT_MAST;
SELECT MIN(PRODUCT), MAX(PRODUCT) FROM PRODUCT_MAST;
Output 
+-----------+-----------+
| MAX(RATE) | MIN(RATE) |
+-----------+-----------+
|        30 |        10 |
+-----------+-----------+
+--------------+--------------+
| MIN(PRODUCT) | MAX(PRODUCT) |
+--------------+--------------+
| Item1        | Item9        |
+--------------+--------------+
Why is MAX(PRODUCT) Item9, not Item10?

Text is compared character by character, like words in a dictionary. “Item1” and “Item9” differ at the fifth character, and 9 comes after 1. So Item10 sorts between Item1 and Item2.

Several aggregates in one query

SQL 
SELECT COUNT(*) AS items, SUM(COST) AS total, AVG(RATE) AS avg_rate,
       MIN(COST) AS cheapest, MAX(COST) AS dearest
FROM PRODUCT_MAST;
Output 
+-------+-------+----------+----------+---------+
| items | total | avg_rate | cheapest | dearest |
+-------+-------+----------+----------+---------+
|    10 |   670 |  21.5000 |       20 |     150 |
+-------+-------+----------+----------+---------+

Aggregates and NULL

Add a product whose cost is not known yet:

SQL 
INSERT INTO PRODUCT_MAST VALUES ('Item11', 'Com3', 1, 40, NULL);

SELECT COUNT(*), COUNT(COST), SUM(COST), AVG(COST) FROM PRODUCT_MAST;
Output 
+----------+-------------+-----------+-----------+
| COUNT(*) | COUNT(COST) | SUM(COST) | AVG(COST) |
+----------+-------------+-----------+-----------+
|       11 |          10 |       670 |   67.0000 |
+----------+-------------+-----------+-----------+
  • COUNT(*) counts the new row: 11. COUNT(COST) skips the NULL: 10.
  • SUM and AVG skip the NULL. AVG is 670 ÷ 10 = 67, not 670 ÷ 11.
  • If no row is selected, or every value is NULL, SUM, AVG, MIN and MAX return NULL. COUNT returns 0.
Getting 0 instead of NULL

SELECT COALESCE(SUM(COST), 0) FROM PRODUCT_MAST WHERE QTY > 10; returns 0 when no row matches.

Rules for using aggregates

  1. Not in WHERE. WHERE runs before rows are grouped, so WHERE SUM(COST) > 100 is an error. Use HAVING to filter on an aggregate.
  2. No plain columns beside an aggregate without GROUP BY. SELECT COMPANY, SUM(COST) FROM PRODUCT_MAST asks for one total but ten companies. MySQL 8.4 rejects it, because its default mode includes ONLY_FULL_GROUP_BY. Add GROUP BY COMPANY.
  3. No aggregate inside an aggregate in one query level: MAX(AVG(COST)) is an error. Use a subquery instead.
  4. An aggregate can be used in SELECT, HAVING and ORDER BY.

In real life

Mark sheets

A class report shows the number of students (COUNT), the class average (AVG) and the highest and lowest marks (MAX, MIN) for each subject.

Shop billing

The bill total is SUM(price × quantity) over the items in the cart. The number of items is COUNT(*).

Weather data

A day's record keeps MIN and MAX temperature. A broken sensor leaves NULL, and AVG simply skips it.

Key points

  • COUNT, SUM, AVG, MIN and MAX each return one value from many rows.
  • COUNT(*) counts rows; COUNT(column) counts non-NULL values; COUNT(DISTINCT column) counts different values.
  • SUM and AVG work on numbers only. MIN and MAX also work on text and dates.
  • All aggregates except COUNT(*) skip NULL. With no rows, COUNT gives 0 and the others give NULL.
  • WHERE runs before aggregation, so aggregates cannot go in WHERE. Use HAVING.
  • A plain column beside an aggregate needs GROUP BY.
