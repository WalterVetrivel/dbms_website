Views

A view is a saved query that you can use like a table. It stores no data of its own. Views hide complex joins, show each user only what they need, and keep old queries working when tables change. This page shows how to create, use, change and drop views in MySQL.

Learning outcomes

After this page you can
  • Define a view and explain how it differs from a base table.
  • Create views on one table and on a join, and query them.
  • Predict when an INSERT, UPDATE or DELETE through a view works, and use WITH CHECK OPTION.
  • Change and remove views with CREATE OR REPLACE, ALTER VIEW and DROP VIEW.

What is a view

Definition

A view is a virtual table defined by a SELECT query. It has rows and columns like a table, but it stores only the query. Each time you use the view, the database runs the query on the base tables (the real tables) and shows the current data.

  • A view can show some columns, some rows, or both, of one or more tables.
  • You query a view exactly like a table: SELECT ... FROM view_name.
  • When the base tables change, the view shows the change at once. There is no copy to keep up to date.
  • Dropping a view does not touch the base tables or their data.

Views give logical data independence at the view level of the three-schema architecture (see Views of Data). Users and programs read the view, so the tables underneath can change without breaking them.

Creating a view

Syntax 
CREATE VIEW view_name [(column_list)] AS
SELECT ...
[WITH CHECK OPTION];

This view shows the name and address of the students with STU_ID below 4:

SQL 
CREATE VIEW DetailsView AS
SELECT NAME, ADDRESS
FROM Student_Detail
WHERE STU_ID < 4;

SELECT * FROM DetailsView;
Output 
+---------+-----------+
| NAME    | ADDRESS   |
+---------+-----------+
| Stephan | Delhi     |
| Kathrin | Noida     |
| David   | Ghaziabad |
+---------+-----------+

The view name can be used anywhere a table name can be used in a SELECT. You can add WHERE, ORDER BY and joins on top of it.

Common mistake

Some notes create this view FROM Student_Details, with an extra s. The table is Student_Detail, so that query fails with “table doesn't exist”. Names must match exactly.

A view on two tables

A view can join tables (see Joins). Users then read one simple “table” instead of writing the join each time.

SQL 
CREATE VIEW MarksView AS
SELECT d.NAME, d.ADDRESS, m.MARKS
FROM Student_Detail d
JOIN Student_Marks m ON d.STU_ID = m.STU_ID;

SELECT * FROM MarksView;
Output 
+---------+-----------+-------+
| NAME    | ADDRESS   | MARKS |
+---------+-----------+-------+
| Stephan | Delhi     |    97 |
| Kathrin | Noida     |    86 |
| David   | Ghaziabad |    74 |
| Alina   | Gurugram  |    90 |
+---------+-----------+-------+

John has marks but no row in Student_Detail, so the inner join leaves him out. Now a short query gives a useful answer:

SQL 
SELECT NAME, MARKS FROM MarksView
WHERE MARKS > 85
ORDER BY MARKS DESC;
Output 
+---------+-------+
| NAME    | MARKS |
+---------+-------+
| Stephan |    97 |
| Alina   |    90 |
| Kathrin |    86 |
+---------+-------+
Common mistake

Some notes write this view with FROM Student_Detail, Student_Mark but Student_Marks.NAME in the WHERE clause. The table is Student_Marks in both places. The notes also join on NAME. Joining on the key STU_ID is safer, because two students can share a name.

Changing data through a view

A simple view on one table is updatable. An UPDATE, INSERT or DELETE on the view changes the base table.

SQL 
UPDATE DetailsView SET ADDRESS = 'Chennai' WHERE NAME = 'David';

SELECT * FROM Student_Detail WHERE STU_ID = 3;
Output 
+--------+-------+---------+
| STU_ID | NAME  | ADDRESS |
+--------+-------+---------+
|      3 | David | Chennai |
+--------+-------+---------+

The view has no data of its own, so the change goes to Student_Detail.

An INSERT through a view fails if the base table has a NOT NULL column that is missing from the view and has no default. For example, a view with only ADDRESS cannot insert a row, because NAME is NOT NULL. MySQL gives error 1423: “Field of view ... underlying table doesn't have a default value”.

WITH CHECK OPTION

Without a check, you could insert a row through a view that the view itself would not show. The row would “vanish” as soon as it was added. WITH CHECK OPTION stops this. Every row inserted or updated through the view must satisfy the view's WHERE clause.

SQL 
CREATE VIEW TopScorers AS
SELECT STU_ID, NAME, MARKS
FROM Student_Marks
WHERE MARKS >= 90
WITH CHECK OPTION;

INSERT INTO TopScorers VALUES (6, 'Ravi', 95);   -- works: 95 >= 90
INSERT INTO TopScorers VALUES (7, 'Meena', 60);  -- rejected: 60 < 90

The first INSERT adds Ravi to Student_Marks, with AGE NULL because the view has no AGE column. The second INSERT fails with error 1369, “CHECK OPTION failed”, and nothing is added.

Which views are updatable

A view is updatable only if each of its rows maps to exactly one row of a base table. In MySQL, a view is not updatable if its SELECT uses any of these:

  • Aggregate functions such as SUM, COUNT or AVG
  • DISTINCT, GROUP BY or HAVING
  • UNION or UNION ALL
  • A subquery in the SELECT list (in most cases)
  • Only literal values, with no base table column

This summary view is read-only, because one row stands for a whole group:

SQL 
CREATE VIEW AgeStats AS
SELECT AGE, COUNT(*) AS students, AVG(MARKS) AS avg_marks
FROM Student_Marks
GROUP BY AGE;

SELECT * FROM AgeStats;
Output 
+------+----------+-----------+
| AGE  | students | avg_marks |
+------+----------+-----------+
|   18 |        2 |   85.0000 |
|   19 |        1 |   97.0000 |
|   20 |        1 |   90.0000 |
|   21 |        1 |   86.0000 |
+------+----------+-----------+

UPDATE AgeStats SET students = 5 WHERE AGE = 18; fails with error 1288, “The target table AgeStats of the UPDATE is not updatable”. There is no single base row to change.

A join view such as MarksView can be updated, but one statement may change only one base table. Setting MARKS and ADDRESS in the same UPDATE fails with error 1393.

Common mistake

Some notes list these as the “disadvantages of views”. Some of them are about Oracle or SQL Server, not MySQL:

  • “WITH READ ONLY” and the pseudocolumn “rownum” are Oracle features. MySQL has neither.
  • “Rules and defaults” are an old SQL Server feature.

Two points do hold in MySQL. A view cannot take parameters. A view cannot use a temporary table (error 1352).

Changing and dropping views

To change a view, give its new query with CREATE OR REPLACE VIEW or ALTER VIEW. Both keep the view's name, so queries that use it still work.

SQL 
CREATE OR REPLACE VIEW DetailsView AS
SELECT STU_ID, NAME, ADDRESS
FROM Student_Detail
WHERE STU_ID < 4;

ALTER VIEW DetailsView AS
SELECT NAME, ADDRESS
FROM Student_Detail;

CREATE OR REPLACE also works when the view does not exist yet. ALTER VIEW needs the view to exist.

To remove a view, use DROP VIEW. The base tables and their data stay as they are.

SQL 
DROP VIEW MarksView;
DROP VIEW IF EXISTS MarksView;   -- no error if it is already gone

SHOW FULL TABLES; lists tables and views, with the type BASE TABLE or VIEW.

SELECT * in a view is fixed when the view is made

MySQL expands SELECT * into a column list when you create the view. If you add a column to the table later, the view does not show it until you replace the view. If you drop the base table, any use of the view fails with error 1356.

Why use views

Benefits of views
BenefitHow a view helps
SecurityGive a user access to the view but not the table. They see only the allowed rows and columns.
Simpler queriesA long join or calculation is written once. Users query the view like a single table.
Logical data independenceIf tables are split or renamed, the view can be rewritten so old queries still work.
ConsistencyEveryone uses the same definition, for example of “active customer”.
RenamingA view can give columns clearer names without changing the table.
IntegrityWITH CHECK OPTION makes sure rows added through the view meet its condition.
Little storageOnly the query is stored, not the rows.

Here a clerk may read DetailsView but not the table under it:

SQL 
GRANT SELECT ON school.DetailsView TO 'clerk'@'localhost';

The clerk can run SELECT * FROM DetailsView. SELECT * FROM Student_Detail fails with error 1142, “SELECT command denied”.

The costs are small but real. A view over a view over a view can be slow and hard to debug, and many views cannot be updated.

Kinds of views

Common names for kinds of views
NameMeaning
Simple viewBuilt on one table, with no aggregates, GROUP BY or DISTINCT. Usually updatable. DetailsView is one.
Complex viewUses aggregates, GROUP BY, DISTINCT or set operations. Read-only. AgeStats is one.
Join viewHas more than one table in its FROM clause. MarksView is one.
Inline viewOracle's name for a subquery in the FROM clause. MySQL calls it a derived table (see Sub Queries). It is not saved.
Materialized viewA view whose result is stored and refreshed. Oracle and PostgreSQL have them; MySQL does not.

In real life

Payroll privacy

An HR database gives managers a view of their team with names and roles, but no salary or bank columns.

Reporting

A sales dashboard reads a view that joins orders, customers and products. The report tool never sees the joins.

Safe upgrades

When a table is split in two, a view with the old name and columns keeps old programs running.

Key points

  • A view is a stored SELECT query that acts as a virtual table. It holds no data of its own.
  • A view always shows the current data of its base tables.
  • A simple one-table view is updatable. Changes go to the base table.
  • Views with aggregates, DISTINCT, GROUP BY, HAVING or UNION are read-only.
  • WITH CHECK OPTION rejects rows that would not appear in the view.
  • Use CREATE OR REPLACE VIEW or ALTER VIEW to change a view, and DROP VIEW to remove it. Dropping a view never deletes table data.
  • Views help with security, simpler queries and logical data independence.
