The four properties

To keep data correct, the database system makes every transaction follow four properties. Their first letters spell ACID.

Definitions
  • Atomicity: either all operations of the transaction are reflected in the database, or none are.
  • Consistency: a transaction run alone, with no other transaction running at the same time, keeps the database consistent.
  • Isolation: each transaction is unaware of other transactions running at the same time. To Ti, it looks as if Tj ran fully before it or fully after it.
  • Durability: after a transaction completes successfully, its changes stay in the database, even if the system fails.
Memory aid

A = all or nothing. C = correct before and after. I = in its own world. D = does not disappear.

The running example

Ti transfers ₹50 from account A to account B. Before Ti runs, A = ₹1000 and B = ₹2000.

Ti: read(A);
    A := A − 50;
    write(A);
    read(B);
    B := B + 50;
    write(B).

We now look at what each ACID property means for Ti.

Atomicity

Suppose the system fails after write(A) but before write(B). The database now holds A = ₹950 and B = ₹2000. The sum A + B has dropped from ₹3000 to ₹2950, so ₹50 has been destroyed. This is an inconsistent state.

Values on disk when the system fails after write(A)
MomentABA + B
Before Ti100020003000
After write(A), then failure95020002950
After recovery undoes Ti100020003000

Atomicity says this half-done state must never be seen. How it is ensured: before a data item changes, the system writes its old value to a file called the log. If the transaction does not finish, the system uses the log to put the old values back. It then looks as if the transaction never ran.

Responsible: the recovery system of the DBMS.

Consistency

For Ti, the consistency requirement is that the sum A + B is unchanged by the transaction. Without it, money could be created or destroyed.

Consistency also covers the rules written into the schema, such as primary keys, foreign keys and CHECK constraints (for example, a balance may not go below zero). The DBMS tests these integrity constraints automatically.

Responsible: the application programmer who writes the transaction, helped by the integrity constraints that the DBMS checks.

Note

While Ti is running, the database may be inconsistent for a short time (after write(A) and before write(B)). That is allowed. What matters is that it is consistent again when Ti ends. Atomicity and isolation make sure no one sees the in-between state.

Isolation

Suppose a second transaction Tj runs at the same time and computes A + B, for example to print the bank's total. If Tj reads A and B in the middle of Ti (after write(A), before write(B)), it sees A = 950 and B = 2000, and prints ₹2950. That total is wrong.

Tj reads in the middle of Ti
Ti (transfer)Tj (print total)
read(A); A := A − 50; write(A)
read(A) gives 950; read(B) gives 2000; display(A + B) shows 2950
read(B); B := B + 50; write(B)

Worse, if Tj then updates A or B using these wrong values, the database can stay inconsistent even after both transactions finish.

The simple fix is to run transactions serially, one after the other. But that is slow. Isolation allows transactions to run at the same time, as long as the result is the same as running them one after another in some order.

Responsible: the concurrency-control system of the DBMS, for example by using locks (see Locking Protocols).

Durability

The user is told that the transfer succeeded. Now the new balances A = ₹950 and B = ₹2050 must never be lost. This holds even if the system crashes a moment later.

Durability is guaranteed if either of these is true:

  1. The changes made by the transaction are written to disk before the transaction completes; or
  2. Enough information about the changes is written to disk (in the log) to rebuild them when the system restarts after a failure.

Responsible: the recovery system of the DBMS. See Transaction Recovery.

In real life

ATM withdrawal

If the ATM debits your account but the cash is not dispensed, atomicity requires that the debit be undone. Banks reverse such failed withdrawals automatically.

College fee portal

After the portal says “fee paid”, the receipt must still be there tomorrow, even if the server restarted overnight. That is durability.

Online sale

Two buyers click “buy” on the last phone at the same moment. Isolation makes sure only one order gets it, as if the orders came one after the other.

Key points

  • ACID stands for atomicity, consistency, isolation and durability.
  • Atomicity: all operations happen or none do; old values in the log allow undo.
  • Consistency: a transaction run alone keeps the database consistent (A + B unchanged).
  • Isolation: concurrent transactions do not see each other's unfinished work.
  • Durability: committed changes survive system failures.
  • The recovery system ensures atomicity and durability.
  • The concurrency-control system ensures isolation; the programmer and integrity constraints ensure consistency.
