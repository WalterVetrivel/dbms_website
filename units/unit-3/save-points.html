Save Points

ROLLBACK undoes a whole transaction. Sometimes you want to undo only the last few steps and keep the rest. A savepoint marks a point inside a transaction that you can roll back to.

  • Work out which changes ROLLBACK TO undoes, and which savepoints remain afterward.
  • Explain how COMMIT and ROLLBACK affect savepoints.
  • Use savepoints to handle an error partway through a long transaction.

What is a savepoint?

Definition

A savepoint is a named point in a transaction to which you can roll the transaction back, without rolling back the entire transaction.

Think of it as a bookmark. Changes made before the bookmark are kept; changes made after it can be undone. The transaction stays open after a partial rollback, so you can carry on and later commit or roll back as usual.

Savepoints belong to the transaction control language (TCL), along with COMMIT and ROLLBACK. See SQL DCL and TCL Commands.

Commands

Savepoint commands
CommandWhat it does
SAVEPOINT savepoint_name;Creates a savepoint with this name at the current point in the transaction. It changes no data.
ROLLBACK TO savepoint_name;Undoes every change made after the savepoint. Changes made before it are kept, and the transaction remains open.
RELEASE SAVEPOINT savepoint_name;Removes the savepoint. No data is changed, but you can no longer roll back to it.

In MySQL, the full form is ROLLBACK [WORK] TO [SAVEPOINT] savepoint_name, so ROLLBACK TO SAVEPOINT SP2 and ROLLBACK TO SP2 mean the same.

Example: the CUSTOMERS table

You plan to delete three records from the CUSTOMERS table. You create a savepoint before each delete, so that you can roll back to any savepoint at any time and return the right data to its original state.

CUSTOMERS, before the transaction
IDNAMEAGEADDRESSSALARY
1Suresh23Chennai5400
2Mano22Cochin6500
3Subhiksha23New York4500
4Malar24Bangalore4300
5Sarath22Trichy7500
6Krishna32Coimbatore6600
7Ranchana21Hyderabad5500
SQL 
SQL> SAVEPOINT SP1;
Savepoint created.
SQL> DELETE FROM CUSTOMERS WHERE ID = 1;
1 row deleted.
SQL> SAVEPOINT SP2;
Savepoint created.
SQL> DELETE FROM CUSTOMERS WHERE ID = 2;
1 row deleted.
SQL> SAVEPOINT SP3;
Savepoint created.
SQL> DELETE FROM CUSTOMERS WHERE ID = 3;
1 row deleted.

Now you change your mind and roll back to SP2. SP2 was created after the first deletion, so the last two deletions are undone:

SQL 
SQL> ROLLBACK TO SP2;
Rollback complete.
SQL> SELECT * FROM CUSTOMERS;
CUSTOMERS after ROLLBACK TO SP2 (6 rows selected)
IDNAMEAGEADDRESSSALARY
2Mano22Cochin6500
3Subhiksha23New York4500
4Malar24Bangalore4300
5Sarath22Trichy7500
6Krishna32Coimbatore6600
7Ranchana21Hyderabad5500

Only the first deletion remains. It is still not permanent: a COMMIT now would make it permanent, and a ROLLBACK would bring row 1 back too.

Rules to remember

  • Later savepoints are removed. After ROLLBACK TO SP2, SP3 no longer exists, because it was created after SP2. SP1 and SP2 remain, so you can still roll back to either.
  • The transaction stays open. ROLLBACK TO does not end the transaction. Only COMMIT or ROLLBACK (without TO) ends it.
  • Same name, new place. If you create a savepoint with a name that already exists, the old one is replaced by the new one.
  • COMMIT and ROLLBACK remove all savepoints. After a COMMIT, the changes are permanent and ROLLBACK TO SP1 gives an error such as “SAVEPOINT SP1 does not exist”.
  • RELEASE keeps the data. RELEASE SAVEPOINT only forgets the bookmark. The changes made after it are not undone.
  • Only inside a transaction. With autocommit on, each statement commits at once, so a savepoint is useless. Start a transaction first (START TRANSACTION), or turn autocommit off.
Exam tip

To find what ROLLBACK TO S undoes, draw the statements in order and put a line where S was created. Everything below the line is undone; everything above it is kept but still uncommitted. Cross out any savepoint below the line.

Why use savepoints?

  • Handle an error without losing all the work. In a long transaction, if one step fails, roll back only that step and try another way, instead of starting again.
  • Try something out. Make a change, check the result with a SELECT, and roll back to the savepoint if it looks wrong.
  • Structure big programs. A stored procedure can set a savepoint at the start of each part, so that an error handler can undo just that part.

The idea is the same as the partial rollback used in deadlock recovery: undo only as much as needed. The undo itself uses the log records described in Transaction Recovery.

SQL 
START TRANSACTION;
INSERT INTO orders VALUES (101, 'Ravi', CURRENT_DATE);
SAVEPOINT before_items;
INSERT INTO order_items VALUES (101, 'P7', 2);
-- the stock check for P7 fails
ROLLBACK TO before_items;
INSERT INTO order_items VALUES (101, 'P9', 2);   -- a substitute item
COMMIT;

Here the order header is kept, the failed item is undone, and the substitute item is committed with the order.

Savepoints in different databases

Savepoint syntax by database
DatabaseCreateRoll back toRelease
MySQL (InnoDB)SAVEPOINT sROLLBACK TO [SAVEPOINT] sRELEASE SAVEPOINT s
OracleSAVEPOINT sROLLBACK TO [SAVEPOINT] sNot supported
PostgreSQLSAVEPOINT sROLLBACK TO [SAVEPOINT] sRELEASE [SAVEPOINT] s
SQL ServerSAVE TRANSACTION sROLLBACK TRANSACTION sNot supported
Note

In MySQL InnoDB, rolling back to a savepoint undoes the data changes, but row locks taken after the savepoint are usually kept until the transaction ends. Under the SQL standard, RELEASE SAVEPOINT also removes any savepoints created after the one released.

In real life

Group railway booking

A booking for four passengers adds each passenger in turn. If the berth for the fourth cannot be allotted, the system can roll back to the savepoint before that passenger and put them on the waiting list, while keeping the first three confirmed.

Spreadsheet undo

Pressing undo a few times takes back your last few edits but keeps earlier ones, and nothing is final until you save. ROLLBACK TO is the same idea, with COMMIT as the save.

Key points

  • A savepoint is a named point inside a transaction that you can roll back to.
  • SAVEPOINT s creates it; ROLLBACK TO s undoes changes after it; RELEASE SAVEPOINT s removes it.
  • ROLLBACK TO keeps changes made before the savepoint and keeps the transaction open.
  • Savepoints created after s are removed by ROLLBACK TO s; s itself remains.
  • COMMIT and ROLLBACK end the transaction and remove all savepoints.
  • Savepoints need a transaction: use START TRANSACTION or turn autocommit off.
