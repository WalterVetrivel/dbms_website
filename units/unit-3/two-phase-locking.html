Two Phase Locking

Two phase locking is the rule most databases use to keep concurrent schedules serializable. It is simple: once a transaction releases any lock, it may not ask for a new one. This page explains the rule, its variants and its costs.

The two phase rule

Definition

The two phase locking protocol requires that each transaction issue its lock and unlock requests in two phases:

  1. Growing phase: the transaction may obtain locks, but may not release any lock.
  2. Shrinking phase: the transaction may release locks, but may not obtain any new lock.

A transaction starts in the growing phase and gets locks as it needs them. As soon as it releases its first lock, it enters the shrinking phase and can never ask for another lock.

The point in the schedule where a transaction obtains its final lock (the end of its growing phase) is called its lock point.

Which transactions are two phase?

Accounts A and B; T1 moves ₹50 from B to A, and T2 displays A + B. These are the transactions from Locking Protocols, and their two phase versions T3 and T4.

T1: lock-X(B); read(B);
    B := B − 50; write(B);
    unlock(B);
    lock-X(A); read(A);
    A := A + 50; write(A);
    unlock(A).

Not two phase: it locks A after unlocking B.

T3: lock-X(B); read(B);
    B := B − 50; write(B);
    lock-X(A); read(A);
    A := A + 50; write(A);
    unlock(B);
    unlock(A).

Two phase: all locks come before the first unlock. Its lock point is lock-X(A).

T2: lock-S(A); read(A);
    unlock(A);
    lock-S(B); read(B);
    unlock(B);
    display(A + B).

Not two phase: it locks B after unlocking A.

T4: lock-S(A); read(A);
    lock-S(B); read(B);
    display(A + B);
    unlock(A);
    unlock(B).

Two phase. Its lock point is lock-S(B).

Exam tip

To check a transaction, scan its instructions from top to bottom. If any lock appears after any unlock, it is not two phase. The unlocks need not come at the very end.

Why 2PL ensures serializability

Merit (advantage): if every transaction follows two phase locking, every legal schedule is conflict serializable.

The reason: order the transactions by their lock points. Suppose an operation of Ti conflicts with a later operation of Tj on item Q. Tj could lock Q only after Ti unlocked it. Ti unlocked Q in its shrinking phase, which is after its lock point. So Ti's lock point comes before Tj's. Every edge of the precedence graph therefore goes from an earlier lock point to a later one, so there can be no cycle.

Note

The serializability order of the transactions is the order of their lock points. 2PL is a sufficient condition, not a necessary one: some conflict serializable schedules cannot be produced by 2PL.

1. It does not prevent deadlock

T3 and T4 are both two phase, yet each waits for the other forever. 2PL guarantees serializability, but not freedom from deadlock. Deadlocks must be handled separately; see Deadlock.

All three are two phase. But T5 released its X lock on A before committing. T6 and then T7 read the uncommitted value. When T5 fails after T7's read, T6 and T7 must both be rolled back. This is a cascading rollback.

Strict and rigorous 2PL

Strict two phase locking

Locking must be two phase, and all exclusive-mode locks taken by a transaction are held until the transaction commits or aborts.

No transaction can read or write data written by an uncommitted transaction, so schedules are strict and cascadeless. Shared locks may still be released early.

Rigorous two phase locking

All locks, shared and exclusive, are held until the transaction commits or aborts.

Transactions can be serialized in the order in which they commit. This is simpler to reason about.

Most database systems use strict or rigorous 2PL. Both still allow deadlocks.

A further form, conservative (static) 2PL, makes a transaction lock every item it will need before it starts. If any lock is not available, it takes none and waits. Conservative 2PL is free from deadlock, but a transaction must know its full read and write set in advance, which is rarely possible.

Lock conversion

Suppose T8 reads many items a1, a2, …, an and at the end writes only a1. Under plain 2PL it must take an X lock on a1 from the start, which blocks other readers for the whole time. Lock conversion lets it start with an S lock and change it later.

  • Upgrade: change a shared lock to an exclusive lock. Allowed only in the growing phase.
  • Downgrade: change an exclusive lock to a shared lock. Allowed only in the shrinking phase.

2PL with lock conversion still ensures conflict serializability, and lets more transactions run at the same time.

Automatic generation of locks

In practice, programmers do not write lock instructions. A widely used scheme makes the DBMS add them from the transaction's reads and writes:

  • When Ti issues read(Q), the system issues lock-S(Q) and then read(Q).
  • When Ti issues write(Q), the system checks whether Ti already holds an S lock on Q. If so, it issues upgrade(Q); otherwise lock-X(Q). Then it issues write(Q).
  • All locks of a transaction are released after it commits or aborts.

This is rigorous two phase locking with lock conversion, and it is how most commercial systems work.

In real life

MySQL InnoDB

InnoDB holds row locks taken by UPDATE, DELETE and SELECT ... FOR UPDATE until the transaction commits or rolls back, which is strict two phase locking.

Hostel room allotment

A warden first reserves every room needed for a group (growing), and frees them only after the allotment list is final (shrinking). Freeing a room and then grabbing another would let a second warden see a half-done list.

Key points

  • 2PL: a growing phase (only lock) followed by a shrinking phase (only unlock).
  • The lock point is where a transaction gets its final lock.
  • 2PL ensures conflict serializability; the serial order is the order of lock points.
  • Basic 2PL allows deadlock and cascading rollback.
  • Strict 2PL holds X locks until commit or abort, so it is cascadeless.
  • Rigorous 2PL holds all locks until commit or abort; transactions serialize in commit order.
  • Upgrade (S to X) only in the growing phase; downgrade (X to S) only in the shrinking phase.
  • Conservative 2PL takes all locks before starting, so it is deadlock-free.
