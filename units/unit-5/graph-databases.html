Graph Databases

Some data is mostly about connections: who knows whom, which station links to which, which account sent money to which. A graph database stores these connections directly. This page explains the property graph model and the Cypher query language of Neo4j.

What is a graph database?

Definition

A graph database is a NoSQL database that stores data as a graph: nodes for entities, edges (relationships) for the links between them, and properties on both. Relationships are stored directly as data, not worked out with joins.

Draw your friends on paper. Each person is a circle, and a line joins two friends. That drawing is a graph. A graph database stores exactly that drawing, so questions like “who are my friends' friends?” are easy to answer.

In a relational database, a link is only implied: two rows share a value, such as a foreign key. A join must find the match each time. In a graph database, the link itself is stored.

The property graph model

  • Node: an entity, such as a person or a city. It is like a row.
  • Label: the kind of node, such as :Person or :City. It is like a table name.
  • Relationship (edge): a named, directed link between two nodes, such as KNOWS or LIVES_IN.
  • Property: a key-value pair on a node or a relationship, such as name: "Arun" or since: 2023.

Like a document store, a graph database has a flexible schema. Two Person nodes can have different properties.

Why links are fast

In a graph database, each node keeps direct pointers to its relationships. This is called index-free adjacency. To go from Arun to his friends, the database follows the pointers. It does not search a table.

Example

A social network has 10 crore users. To find a user's friends of friends with SQL, the database joins a huge friendship table with itself, using an index each time. In a graph database, it follows the links from one node. The work depends on how many friends the user has, not on how many users there are.

The more “hops” a question needs, the bigger the gain. Three or four hops can be slow with joins, but quick in a graph database.

Worked example: Cypher in Neo4j

Neo4j uses the Cypher query language. Its patterns look like drawings: () is a node and -[]-> is a relationship.

Step 1. Create the graph in the picture above.

Cypher (Neo4j) 
CREATE (a:Person {name: 'Arun'}),
       (p:Person {name: 'Priya'}),
       (k:Person {name: 'Kavin'}),
       (s:City {name: 'Salem'}),
       (e:City {name: 'Erode'}),
       (a)-[:KNOWS {since: 2023}]->(p),
       (p)-[:KNOWS]->(k),
       (a)-[:LIVES_IN]->(s),
       (p)-[:LIVES_IN]->(s),
       (k)-[:LIVES_IN]->(e);

Step 2. Find the people Arun knows.

Cypher (Neo4j) 
MATCH (a:Person {name: 'Arun'})-[:KNOWS]->(f:Person)
RETURN f.name;            -- Priya

Step 3. Suggest new friends: people known by Arun's friends, whom Arun does not know yet.

Cypher (Neo4j) 
MATCH (a:Person {name: 'Arun'})-[:KNOWS]->(:Person)-[:KNOWS]->(fof:Person)
WHERE NOT (a)-[:KNOWS]->(fof) AND fof <> a
RETURN fof.name;          -- Kavin

Step 4. Find people who live in the same city as Arun.

Cypher (Neo4j) 
MATCH (a:Person {name: 'Arun'})-[:LIVES_IN]->(c:City)<-[:LIVES_IN]-(other:Person)
RETURN other.name, c.name;   -- Priya, Salem

Worked example: the same query in SQL

In MySQL, people and friendships go in two tables. Friends of friends need the knows table joined to itself.

SQL (MySQL 8.4) 
CREATE TABLE person (id INT PRIMARY KEY, name VARCHAR(50));
CREATE TABLE knows (from_id INT, to_id INT, since INT,
                    PRIMARY KEY (from_id, to_id));

SELECT DISTINCT p3.name
FROM person p1
JOIN knows k1  ON k1.from_id = p1.id
JOIN knows k2  ON k2.from_id = k1.to_id
JOIN person p3 ON p3.id = k2.to_id
WHERE p1.name = 'Arun'
  AND p3.id <> p1.id
  AND NOT EXISTS (SELECT 1 FROM knows k
                  WHERE k.from_id = p1.id AND k.to_id = p3.id);

It works, but each extra hop adds two more joins. The Cypher pattern only gets one more -[:KNOWS]->(). It is also easier to read.

Exam tip

When asked to define a graph database, name the three parts: nodes, edges and properties. Then draw a small graph with three nodes and give one application, such as friend suggestions or fraud detection.

Applications

Social networks

Friend suggestions, “people you may know”, groups and followers are all paths in a graph.

Fraud detection

Banks link accounts, phones and addresses. A ring of new accounts sharing one phone number stands out as a pattern in the graph.

Recommendations

“Students who took DBMS also took Data Mining” comes from following student and course links.

Routes and networks

Bus and train routes, delivery paths and computer networks need shortest paths between nodes.

Graph databases include Neo4j, Amazon Neptune, ArangoDB and JanusGraph.

Merits and demerits (advantages and disadvantages)

Merits (advantages)

  • Fast link queries: following relationships does not need joins.
  • Natural model: the data looks like the whiteboard drawing of the problem.
  • Flexible schema: new kinds of nodes and relationships can be added at any time.
  • Readable queries: Cypher patterns are short and look like the graph.

Demerits (disadvantages)

  • Hard to spread over servers: cutting a graph into pieces breaks many links.
  • Not for bulk totals: adding up values over millions of rows is better done elsewhere.
  • Less common skills: fewer developers know Cypher than SQL.
  • Overkill for simple data: data with few links fits tables better.

Key points

  • A graph database stores nodes (entities), relationships (edges) and properties on both.
  • Labels group nodes, such as :Person; relationships are named and directed, such as KNOWS.
  • Links are stored directly (index-free adjacency), so multi-hop queries are fast.
  • Neo4j uses Cypher: MATCH (a)-[:KNOWS]->(b) RETURN b.
  • Uses: social networks, fraud detection, recommendations and routes.
  • Examples: Neo4j, Amazon Neptune, ArangoDB and JanusGraph.
