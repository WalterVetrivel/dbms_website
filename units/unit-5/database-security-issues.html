Database Security: Security Issues

A database holds marks, salaries, bank balances and health records. Keeping this data safe is called database security. This page explains the issues, the threats and the main ways to control them.

What is database security?

Definition

Database security is the protection of a database against unauthorized access, wrong changes and loss, whether on purpose or by accident. It decides which users may do which actions on which data.

Think of a college exam cell. Only some staff may enter it. Only the controller may change marks. The papers are kept in a locked room and copies are kept safe. A database needs the same kind of rules, locks and copies.

Types of security issues

Database security deals with four kinds of issues.

  1. Legal and ethical issues: who has the right to see some data. Some data is protected by law, such as health records and Aadhaar details. India's Digital Personal Data Protection Act, 2023 sets rules for personal data.
  2. Policy issues: rules set by the government or the organization about what may be shared. For example, a college may publish pass percentages but not each student's marks.
  3. System issues: where security is checked. It can be at the hardware, the operating system or the DBMS level.
  4. Data and user level issues: many organizations sort data and users into security levels, such as public, internal, confidential and top secret. A user may read only data at or below their level.

Threats to databases

A threat can cause three kinds of loss. They are often remembered as CIA: confidentiality, integrity and availability.

The three kinds of loss
Loss ofMeaningExample
IntegrityData is changed, inserted or deleted wrongly, on purpose or by accidentA student changes their own marks; a clerk deletes the wrong row
AvailabilityAuthorized users cannot use the data or the systemA denial-of-service attack; ransomware locks the server
ConfidentialityData is shown to people who should not see itCustomer phone numbers leak and are sold to spammers

Each loss hurts in its own way. Wrong data leads to wrong decisions and fraud. A system that is down stops all work. Leaked data brings loss of trust, shame and court cases.

Common causes are stolen passwords and staff who misuse their access. Others are SQL injection through web forms (topic 5.13), old software with known holes, lost backups and simple mistakes.

Worked example: name the threat

For each event, decide which kind of loss happened.

  1. An attacker floods the online fee payment site so no student can pay. Answer: loss of availability. The data is safe, but no one can use it.
  2. A hacker copies the hostel database with parents' phone numbers. Answer: loss of confidentiality. Nothing changed, but private data was seen.
  3. A program bug sets every student's attendance to 0%. Answer: loss of integrity. The data is now wrong, even though no one meant harm.
Common mistake

Security is not only about hackers. Mistakes by staff and failures of hardware also cause loss. That is why backups and logs are part of security.

Control measures

There are four main control measures in a DBMS.

1. Access control

Only users with an account and a password (or other proof of identity) can log in. Each user then gets only the privileges they need. This is the most common control. Topics 5.11 and 5.12 cover it in detail.

2. Inference control

Used for statistical databases, which answer only totals and averages. Inference control stops users from working out one person's private value from many summary answers.

3. Flow control

Stops information from flowing to users who should not get it, for example from a top secret table into a public report. Hidden paths that leak data are called covert channels.

4. Data encryption

Data is turned into unreadable code with a key. A thief who steals the disk or listens on the network sees only scrambled data. Topic 5.14 covers it.

Two more measures support these four. Auditing keeps a log of who did what and when, so misuse can be found and proved. Backups let the data be restored after an attack or failure.

Worked example: an inference attack

A college lets staff see only averages of salaries, never one person's salary. A user runs these two queries.

SQL (MySQL 8.4) 
SELECT COUNT(*), AVG(salary) FROM staff
WHERE dept = 'CSE' AND gender = 'F' AND designation = 'Professor';
-- 1 row:  COUNT = 1,  AVG = 185000

The answer is an “average”, but the count is 1. So the user has learned the exact salary of the only woman professor in CSE. The rule “averages only” was not enough.

Inference control fixes this in a few ways.

  • Refuse a query when the group is too small, such as fewer than 5 people.
  • Refuse queries whose groups overlap too much with earlier queries.
  • Add a little random noise to the answers.

The DBA and database security

The database administrator (DBA) is the central authority for security. The DBA uses a powerful superuser account (in MySQL, the root account) to do four kinds of actions.

  1. Account creation: make a new account and password for a user or group.
  2. Privilege granting: give accounts the right to do actions, such as reading a table.
  3. Privilege revocation: take those rights back.
  4. Security level assignment: put each account at the right security level.
SQL (MySQL 8.4) 
-- 1. Account creation
CREATE USER 'meena'@'localhost' IDENTIFIED BY 'Str0ng#Pass2026';

-- 2. Privilege granting
GRANT SELECT ON college.marks TO 'meena'@'localhost';

-- 3. Privilege revocation
REVOKE SELECT ON college.marks FROM 'meena'@'localhost';

-- Check what an account may do
SHOW GRANTS FOR 'meena'@'localhost';

The DBA also keeps the audit log, which records each login and each change with the account name and time. If marks are changed wrongly, the log shows who did it.

Merits and demerits (advantages and disadvantages)

Strong security has a cost as well as a benefit.

Merits (advantages)

  • Protects people: private data stays private.
  • Keeps data correct: only allowed users can change it.
  • Meets the law: the organization follows data protection rules and avoids fines.
  • Builds trust: students, customers and partners trust the system.

Demerits (disadvantages)

  • Cost: security tools, audits and trained staff cost money.
  • Slower work: extra checks, encryption and logging add some delay.
  • Less convenience: strict rules can block users who need data quickly.
  • Never finished: new attacks appear, so security needs constant updates.

In real life

Hospital records

Doctors see their own patients' records. The billing staff see only bills, not test reports. Every access is logged, so misuse can be traced.

Census data

Census results are published as totals for areas. Small groups are merged or hidden so that no single family can be identified. This is inference control.

Key points

  • Database security protects data against unauthorized access, wrong changes and loss.
  • The issues are legal and ethical, policy, system, and data and user level issues.
  • Threats cause loss of integrity, availability or confidentiality (CIA).
  • The four control measures are access control, inference control, flow control and encryption.
  • Inference control stops users from working out private values from summary answers.
  • The DBA creates accounts, grants and revokes privileges, assigns security levels and keeps the audit log.
