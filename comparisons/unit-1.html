1.1 Purpose of Database System

File-processing system and database system

In one line: A file-processing system keeps data in separate files owned by separate programs; a database system keeps it once, under one DBMS that controls access to it.

File-processing system and database system
PointFile-processing systemDatabase system
RedundancySame data is stored in many filesData is stored once and shared, so redundancy is controlled
ConsistencyCopies can disagreeOne copy, so all users see the same value
AccessA new program for each new questionA query language such as SQL answers new questions
IntegrityRules are hidden in program codeRules are declared once as constraints and checked by the DBMS
AtomicityHalf-done updates can remainTransactions run fully or not at all
Concurrent accessUsers can overwrite each otherConcurrency control keeps users apart
SecurityHard to limit who sees whatEach user gets only the rights they need
Backup and recoveryDone by hand, if at allBuilt into the DBMS
Data independencePrograms depend on the file formatPrograms do not change when storage changes
Exam tip

This table is also the answer to “advantages of a DBMS”. Each row of the database column is one advantage.

1.4 Database System Architecture

Two-tier and three-tier architecture

In one line: In two-tier, the client talks to the database directly; in three-tier, an application server sits between the client and the database.

Two-tier and three-tier compared
PointTwo-tierThree-tier
LayersClient and database serverClient, application server and database server
Where the business logic runsOn the clientOn the application server
Client talks toThe database, using SQL (for example, through JDBC)The application server only
SecurityLower, because every client reaches the databaseHigher, because only the server reaches the database
ScalabilityLow; each client keeps its own connection to the databaseHigh; the application server shares connections among many users
Changing the logicUpdate the program on every clientUpdate the application server once

1.7 Keys

Super key, candidate key, primary key, alternate key, composite key and foreign key

In one line: Every primary key is a candidate key, every candidate key is a super key and a foreign key points to the primary key of another table.

The keys of Student(RegNo, RollNo, Dept, Name, Email) and Marks(RegNo, CourseID, Marks)
KeyMeaningHow many per tableExampleSQL
Super keyAny set of attributes that identifies each tuple uniquely; it need not be minimalMany{RegNo}, {RegNo, Name}Not declared
Candidate keyA minimal super key: no attribute can be removedOne or more{RegNo}, {Email}, {RollNo, Dept}Not declared as such
Primary keyThe candidate key chosen to identify tuples; never NULLExactly one{RegNo}PRIMARY KEY
Alternate keyA candidate key that was not chosen as the primary keyZero or more{Email}, {RollNo, Dept}UNIQUE (with NOT NULL)
Composite keyA key made of two or more attributesAny key above can be composite{RollNo, Dept}; {RegNo, CourseID} in MarksPRIMARY KEY (a, b)
Foreign keyAttributes that refer to the primary key of another (or the same) table; may be NULLZero or moreRegNo in Marks refers to StudentFOREIGN KEY ... REFERENCES

Syntax side by side

Primary, alternate and composite keys 
CREATE TABLE student (
  reg_no  CHAR(10) PRIMARY KEY,
  roll_no INT NOT NULL,
  dept    VARCHAR(5) NOT NULL,
  name    VARCHAR(30) NOT NULL,
  -- alternate key:
  email   VARCHAR(40) NOT NULL UNIQUE,
  -- composite alternate key:
  UNIQUE (roll_no, dept)
);
Composite primary key and foreign keys 
CREATE TABLE marks (
  reg_no    CHAR(10),
  course_id CHAR(5),
  marks     INT,
  PRIMARY KEY (reg_no, course_id),
  FOREIGN KEY (reg_no)
    REFERENCES student (reg_no),
  FOREIGN KEY (course_id)
    REFERENCES course (course_id)
);

Primary key and foreign key
BasisPrimary keyForeign key

Unique valuesYes, alwaysNo; many child rows can hold the same value
NULLNever allowedAllowed, unless declared NOT NULL
Number per tableExactly one (it may be composite)Zero, one or many
Table it lives inThe parent (referenced) tableThe child (referencing) table
Rule it enforcesEntity integrityReferential integrity
Value comes fromChosen for each new rowMust already exist in the parent's primary key (or be NULL)
Deleting a rowA parent row that is still referenced cannot be deleted, unless ON DELETE CASCADE or SET NULL is givenA child row can be deleted freely
IndexCreated automaticallyMySQL (InnoDB) creates one if none exists
Examplecourse_id in Coursecourse_id in Marks

Number per tableOnly oneMany
Used forThe primary keyAlternate keys, such as an email or a phone number
Can a foreign key refer to it?Yes; this is the usual caseYes, in MySQL, but referring to the primary key is the normal practice
Index in MySQL (InnoDB)The clustered index; rows are stored in its orderA separate secondary index
Syntaxcol INT PRIMARY KEYcol VARCHAR(40) UNIQUE

Entity integrity and referential integrity

In one line: Entity integrity: a primary key is never NULL. Referential integrity: a foreign key matches a primary key value in the parent table, or is NULL.

Entity integrity and referential integrity
BasisEntity integrityReferential integrity
RuleNo attribute of a primary key can be NULLA foreign key value must match a primary key value in the parent table, or be NULL
Tables involvedOne tableTwo tables (or one table that refers to itself)
Declared withPRIMARY KEYFOREIGN KEY ... REFERENCES
Protects againstRows that cannot be identifiedChild rows that point to a parent that does not exist (orphan rows)
Checked onINSERT and UPDATE of the tableINSERT and UPDATE of the child; UPDATE and DELETE of the parent
On a violationThe statement is rejectedThe statement is rejected, or the change is passed on with CASCADE, SET NULL or RESTRICT
ExampleA student row with no register number is rejectedMarks for course CS999 are rejected when Course has no CS999

Syntax side by side

Entity integrity 
CREATE TABLE customer (
  cust_id INT PRIMARY KEY,
  name    VARCHAR(30)
);
INSERT INTO customer
  VALUES (NULL, 'Ravi');
-- Error: cust_id cannot be NULL
Referential integrity 
CREATE TABLE orders (
  order_id INT PRIMARY KEY,
  cust_id  INT,
  FOREIGN KEY (cust_id)
    REFERENCES customer (cust_id)
    ON DELETE SET NULL
);
INSERT INTO orders VALUES (1, 99);
-- Error if there is no
-- customer 99

1.9 Relational Algebra

Selection (σ) and projection (π)

In one line: Selection picks rows that satisfy a condition; projection picks columns and removes duplicate rows.

Selection and projection
BasisSelection (σ)Projection (π)
PicksTuples (rows)Attributes (columns)
NeedsA condition (predicate)A list of attributes
Notationσcondition(r)πA1, A2(r)
Degree of the result (columns)Same as rThe number of attributes listed
Cardinality of the result (rows)Same as r or fewerSame as r or fewer, because duplicates are removed
DuplicatesCannot appear (r has none)Removed, because a relation is a set
Commutative?Yes: σc1(σc2(r)) = σc2(σc1(r))No; the outer list must be part of the inner list
SQL partWHEREThe column list after SELECT (with DISTINCT)
Exampleσage > 18(Student)πcity(Student)

Syntax side by side

Relational algebra

π city (Student)

π sname (σ city = 'Salem' (Student))

1.10 Overview of the SQL Query Language

DDL, DML, DCL and TCL

In one line: DDL defines the structure, DML works on the rows, DCL gives and takes away access rights and TCL ends or undoes transactions.

The main parts of SQL
PartPurposeCommands
DDL: Data Definition LanguageDefine, change and delete the schema (tables, views, indexes)CREATE, ALTER, DROP, TRUNCATE, RENAME
DML: Data Manipulation LanguageInsert, change, delete and retrieve the dataINSERT, UPDATE, DELETE, SELECT
DCL: Data Control LanguageGive and take away access rightsGRANT, REVOKE
TCL: Transaction Control LanguageMark the start and end of transactionsCOMMIT, ROLLBACK, SAVEPOINT

Syntax side by side

DDL 
CREATE TABLE student (
  roll_no INT PRIMARY KEY,
  name    VARCHAR(30)
);
ALTER TABLE student
  ADD city VARCHAR(20);
DML 
INSERT INTO student
  VALUES (1, 'Anitha', 'Salem');
UPDATE student SET city = 'Erode'
  WHERE roll_no = 1;
SELECT * FROM student;
DCL 
GRANT SELECT, INSERT
  ON college.student
  TO 'clerk'@'localhost';
REVOKE INSERT
  ON college.student
  FROM 'clerk'@'localhost';
TCL 
START TRANSACTION;
UPDATE student SET city = 'Salem'
  WHERE roll_no = 1;
SAVEPOINT sp1;
DELETE FROM student;
ROLLBACK TO sp1;
COMMIT;
Exam tip

Memory aid: DDL is the shape, DML is the data, DCL is the door (who may enter) and TCL is the save button.

CHAR and VARCHAR

In one line: CHAR(n) always takes n characters, padded with spaces; VARCHAR(n) takes only as many characters as the value needs, up to n.

CHAR and VARCHAR in MySQL
BasisCHAR(n)VARCHAR(n)
LengthFixed: always n charactersVariable: up to n characters
Storage of 'Ram' in (10)'Ram' plus 7 spaces'Ram' plus 1 length byte
Extra bytesNone1 length byte (2 if the column can be longer than 255 bytes)
Maximum n25565,535 bytes in all for the row
Trailing spacesAdded when stored, removed when readKept as given
SpeedSlightly faster to find and update, because every value has the same sizeSaves space when values vary in length
Best forValues of one length: PIN code, gender code, register numberValues that vary: names, addresses, emails
